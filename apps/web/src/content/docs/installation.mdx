This guide helps you get Vibecanvas running reliably on a new machine.

## 1) Install Node.js

Install Node.js 18 or newer, then verify:

```bash
node --version
npm --version
```

Vibecanvas uses Node package tooling when generated guest widget code installs its package dependencies.

## 2) Install Bun

Follow the Bun install guide, then verify:

```bash
bun --version
```

## 3) Install Vibecanvas globally

Choose the package manager you already use:

```bash
bun add -g vibecanvas
```

```bash
npm i -g vibecanvas
```

```bash
pnpm add -g vibecanvas
```

## 4) Verify the CLI is available

```bash
vibecanvas --version
```

## 5) Launch the local app

```bash
vibecanvas
```

Running `vibecanvas` starts the `serve` command by default.

To choose a port explicitly:

```bash
vibecanvas serve --port 3001
```

The default port is `3000` in development and `7496` in compiled builds.

## 6) Verify core behavior

- App opens with canvas and side panels.
- Chat can start a new conversation.
- Generated widgets can be added to the canvas.
- Live widget state updates through the local backend.

## 7) Keep Vibecanvas updated

```bash
vibecanvas upgrade --check
vibecanvas upgrade
```

To install a specific release:

```bash
vibecanvas --upgrade 0.2.0-beta.3
```

If you need the full command list:

```bash
vibecanvas --help
```

## 8) Back up encrypted secret stores

Vibecanvas stores one independent AEGIS-256 database key per secret store in the main control database's general-purpose `encryption_keys` table. A separate link associates each secret resource with its key. Encrypted secret databases remain separate resource files. A usable restore needs both the main-database backup and the corresponding resource data; losing one linked key makes that secret store unreadable.

In the default local setup, the main database and resource files can live under the same data root, so a complete copy contains both encrypted data and its keys. In a managed deployment, the main database can live on a separate server from the resource files. This design favors simple operation; protect access to the main database accordingly.

The current release does not provide key export or rotation. At-rest encryption prevents casual plaintext inspection of a secret database or WAL copied without the main database, but it is not a substitute for database access control, host security, API authorization, or careful handling of plaintext after an operator or authorized function reveals it.

## 9) Uninstall

To remove the curl-installed binary and local Vibecanvas config/data/state/cache:

```bash
vibecanvas uninstall --dry-run
vibecanvas uninstall --yes
```

A full uninstall removes the local main database and encrypted resource data together with the rest of Vibecanvas's local data.

If one of these fails, ask in Discussions:
