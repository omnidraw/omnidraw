This guide helps you get Vibecanvas running reliably on a new machine.

## 1) Install Node.js

Install Node.js 18 or newer, then verify:

```bash
node --version
npm --version
```

Vibecanvas uses Node package tooling when generated guest widget code installs its package dependencies.

## 2) Install Bun

Follow the Bun install guide, then verify:

```bash
bun --version
```

## 3) Install Vibecanvas globally

Choose the package manager you already use:

```bash
bun add -g vibecanvas
```

```bash
npm i -g vibecanvas
```

```bash
pnpm add -g vibecanvas
```

## 4) Verify the CLI is available

```bash
vibecanvas --version
```

## 5) Launch the local app

```bash
vibecanvas
```

Running `vibecanvas` starts the `serve` command by default.

To choose a port explicitly:

```bash
vibecanvas serve --port 3001
```

The default port is `3000` in development and `7496` in compiled builds.

## 6) Verify core behavior

- App opens with canvas and side panels.
- Chat can start a new conversation.
- Generated widgets can be added to the canvas.
- Live widget state updates through the local backend.

## 7) Keep Vibecanvas updated

```bash
vibecanvas upgrade --check
vibecanvas upgrade
```

To install a specific release:

```bash
vibecanvas --upgrade 0.2.0-beta.3
```

If you need the full command list:

```bash
vibecanvas --help
```

## 8) Back up encrypted secret stores

Vibecanvas stores the secret-store master key at `keys/secret-store-master-key.v1.hex` under its configuration root and encrypted secret databases under its data root. Back up both roots as one unit. Losing, replacing, or restoring only one side makes every encrypted secret store unreadable; Vibecanvas does not recreate a missing key or silently reset an unreadable database.

Keep custom configuration and data roots separate: Vibecanvas refuses to provision or open secret stores when the key would live inside the data root. It also fails closed on hosts where it cannot enforce current-user-only access to the key file; the current Node host therefore does not enable secret stores on Windows until a current-user ACL implementation is available.

The current release does not provide master-key export or rotation. At-rest encryption protects copied database and WAL files, but it is not a substitute for filesystem permissions, host security, API authorization, or careful handling of plaintext after an operator or authorized actor reveals it.

## 9) Uninstall

To remove the curl-installed binary and local Vibecanvas config/data/state/cache:

```bash
vibecanvas uninstall --dry-run
vibecanvas uninstall --yes
```

A full uninstall removes both the configuration key and encrypted secret data. Without a backup of both, that loss is irreversible.

If one of these fails, ask in Discussions:

- https://github.com/vibecanvas/vibecanvas/discussions
