# A42 - add Codex hooks for functional-core checks
[Overview](../BASED.md)

Add Codex hook integration that runs the shared functional-core rules for `fn.*.ts`, `fx.*.ts`, and `tx.*.ts` files.

## Context

Codex supports command hooks through repo-local config such as `.codex/hooks.json` or `.codex/config.toml`. The desired behavior is to reuse the normalized functional-core implementation from `.pi/extensions/functional-core` after S53, not duplicate rule logic.

Relevant files after S53:
- `.pi/extensions/functional-core/`
- `.codex/hooks.json` or `.codex/config.toml`
- `.codex/hooks/`

Codex hook events to consider:
- `SessionStart` for adding rule context to the model.
- `PostToolUse` for checking files after edits or commands.
- Optional later `PreToolUse` for preflight patch validation if reliable patch previewing is implemented.

## Plan

### Phase 1 - consume shared core

Use the normalized functional-core API from S53. Do not copy validator logic into `.codex` scripts.

### Phase 2 - add hook config

Add repo-local Codex hook config and scripts. Prefer git-root-based command paths so hooks work from subdirectories.

### Phase 3 - implement feedback

For violations, return Codex-compatible JSON feedback so Codex sees the rule failures and fixes them.

### Phase 4 - document and verify

Document trust/review steps and test hook scripts with representative stdin payloads.
