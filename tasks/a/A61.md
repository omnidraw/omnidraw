# A61 - ai wizard: approve should scaffold then prompt AI implementation
[Overview](../../BASED.md)

Approve should create scaffold files and then continue the AI flow to generate real actor/widget code.

## Context
Currently approving an actor candidate from `packages/canvas/src/components/AiWizzard/tabs/ActorTab.tsx` calls the approve flow, which writes only boilerplate/stubs through `packages/service-agent/src/tools/tool.approve-actor-candidate.ts` and `packages/service-agent/src/tools/tx.scaffold.ts`.

The result is useful scaffold, but not implemented widget behavior. Example from the observed session: approving the Todo List candidate wrote files like `actor/tx.addTodo.ts` and `widget/main.ts`, but transition files throw `not implemented yet` and the widget only renders state/context JSON.

Related docs:
- `docs/internal/llm.widget-system.md`
- `packages/canvas/src/components/AiWizzard/tabs/ActorTab.tsx`
- `packages/service-agent/src/tools/tool.approve-actor-candidate.ts`
- `packages/service-agent/src/tools/tx.scaffold.ts`

## Plan
Approval should become a two-step user-visible operation:

### 1. Generate scaffold
Keep the current deterministic scaffold generation:
- `vibecanvas.json`
- package files
- actor function registry
- actor function stubs
- starter widget files

### 2. Prompt AI to implement
After scaffold succeeds, automatically prompt/continue the AI session with a focused implementation request, using the latest approved manifest and generated files as context.

The AI should implement:
- actor transition functions
- `actor/types.ts` if needed
- `widget/main.ts`
- `widget/main.css`
- any small local helpers if needed

The flow should make clear that approve is not done after stubs; it should either enqueue/run the implementation prompt or surface a clear "Generate implementation" continuation state.
