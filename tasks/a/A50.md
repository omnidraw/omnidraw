# A50 - ai wizard: chat-driven widget generation flow
[Overview](../../BASED.md)

Design and implement a chat-driven widget wizard that drafts an actor candidate, lets the user inspect/play/edit it, then approves and generates widget files.

## Context
- User flow must stay chat-driven: user prompt -> AI actor candidate -> user verifies in Actor tab/playground -> user reprompts or edits until satisfied -> approve -> scaffold files -> auto-prompt AI to finish implementation -> show result.
- Pre-approval must not write widget files; keep actor candidate in memory/session/draft state.
- Post-approval writes real files and emits widget update events.

## Plan

### 1. Draft model and phases
- Add wizard draft state per widget/session.
- Phase 1: actor candidate only, no filesystem write access.
- Phase 2: approved actor contract, scaffold/files can be edited.
- Store important candidate fields first: `name`, `description`, `actor`, `widget.tool.label`, `widget.tool.icon`, `widget.tool.group`, `widget.tool.priority`, `widget.tool.behavior`.

### 2. Custom tools by phase
- Define phase 1 tools:
  - `vc_set_actor_candidate`: create/replace actor candidate from chat.
  - `vc_patch_actor_candidate`: apply focused edits from chat or UI.
  - `vc_validate_actor_candidate`: validate actor candidate and return errors/warnings.
  - Future optional read-only tools: web/design-doc/asset/library search.
- Define approval tool/API:
  - `vc_approve_actor_candidate`: freeze current candidate, generate `vibecanvas.json`, scaffold folders/files.
- Define phase 2 tools:
  - `vc_list_widget_files`: list generated draft files.
  - `vc_read_widget_file`: read generated draft file.
  - `vc_write_widget_file`: write generated draft file.
  - `vc_grep_widget_files`: search generated draft files.
  - No bash by default.
- Ensure `AgentService` creates Pi sessions with only the tools needed for the current phase.

### 3. Events and frontend refresh
- Emit a draft event when actor candidate changes.
- Emit `widgetupdate` with changed file paths when `vibecanvas.json` or generated files change.
- Frontend parses `vibecanvas.json` when it changes and refreshes Actor/Preview tabs.
- Consider folder watch after approval so non-tool file edits also publish `widgetupdate`.

### 4. Actor tab playground
- Show candidate actor contract before approval.
- Let user edit important fields and state machine details.
- Validate sample input payloads against `inputMsgSchema`.
- Show selected state transition and allowed target states.
- Let user approve only when candidate validates.

### 5. Scaffold and auto implementation prompt
- On approval write deterministic scaffold:
  - `vibecanvas.json`
  - `actor/functions.ts`
  - actor function stubs
  - `actor/types.ts` if needed
  - `widget/main.ts`
  - `widget/main.css`
- Auto-prompt AI to finish implementation without changing approved candidate unless user explicitly asks for contract revision.

### 6. Tests
- Test each custom tool in isolation.
- Test phase 1 session loads candidate tools and does not load fs/bash tools.
- Test phase 2 session loads file edit/read/grep tools and does not load bash.
- Test reconnect loads latest candidate/draft state.
- Test candidate validation catches bad actor state/message/schema shapes.
- Test approval writes scaffold and emits `widgetupdate` including `vibecanvas.json`.
- Test UI patch flow updates candidate revision/event shape.

- Phase 1 must be safe: no file writes, no bash.
- Phase 2 should edit generated widget files with read/write/grep only; avoid bash unless a later task explicitly allows it.
- Approved actor contract is stable by default; changing it should be an explicit contract revision loop.
