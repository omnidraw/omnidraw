# A43 - db: add authz for public DB methods
[Overview](../../BASED.md)

Add authorization rules to the public Turso DB service method surface.

## Context
`DbServiceTurso` exposes an `IPublicMethods` surface for account, canvas, file, and filesystem operations.
Recent Turso raw-query methods intentionally skipped authz for file/filesystem and allow some canvas operations to run unscoped.
We need a follow-up pass to define and enforce authz consistently at this public boundary.

Relevant files:
- `packages/service-db/src/DbServiceTurso/DbServiceTurso.ts`
- `packages/service-db/src/DbServiceTurso/fx.canvas.ts`
- `packages/service-db/src/DbServiceTurso/tx.canvas.ts`
- `packages/service-db/src/DbServiceTurso/fx.file.ts`
- `packages/service-db/src/DbServiceTurso/tx.file.ts`
- `packages/service-db/src/DbServiceTurso/fx.filesystem.ts`
- `packages/service-db/src/DbServiceTurso/tx.filesystem.ts`
- `packages/service-db/src/IDbService.ts`

## Plan

### Define policy
- Decide which `IPublicMethods` operations require an account id.
- Decide whether missing account id means admin/internal call or denied public call.
- Align canvas, file, and filesystem policy with existing membership tables.

### Implement checks
- Add small fx helpers for permission reads.
- Gate tx methods before writes.
- Keep internal/unscoped behavior explicit instead of accidental optional args.

### Validate callers
- Update API/CLI call sites to pass account id where public access is expected.
- Keep local OSS/default-owner bootstrap working.
