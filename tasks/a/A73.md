# A73 - startup: create an empty canvas when none exists
[Overview](../BASED.md)

Ensure a first-time user starts with an existing empty canvas instead of an empty canvas list.

## Context

The frontend currently fetches canvases during startup in [`apps/frontend/src/store.ts`](../../apps/frontend/src/store.ts). Manual canvas creation and navigation are handled in [`apps/frontend/src/feature/sidebar/components/Sidebar.tsx`](../../apps/frontend/src/feature/sidebar/components/Sidebar.tsx).

## Plan

1. Add a startup bootstrap flow that lists canvases and, only when the successful result is empty, creates one empty default canvas through the existing canvas API.
2. Update the frontend canvas store with either the existing list or the newly created canvas while avoiding duplicate creation across repeated initialization or concurrent startup work.
3. Decide and implement the initial navigation behavior so the generated canvas is immediately useful without overriding a valid canvas deep link.
4. Handle list/create failures through the existing error conventions and leave retry behavior safe and idempotent.
5. Add focused tests for existing canvases, zero canvases, failures, repeated startup, and deep-link behavior.
