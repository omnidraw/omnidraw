# A53 - ai wizard: draft Actor runtime API setup
[Overview](../../BASED.md)

Set up the shared draft Actor runtime used by both Actor and Preview tabs. Reuse `packages/service-actor/src/Actor.ts` for draft and published actors; do not introduce a separate DraftActor class.

## Context
- This continues [A50](A50.md) and prepares [A54](A54.md) + [A55](A55.md).
- Actor Tab and Preview Tab should touch the same running draft actor state.
- The draft actor must execute generated backend actor functions through the existing Actor runtime path.
- `Actor` itself has no DB concept; `ActorSupervisor` manages published actors, while `AgentService` can manage draft actors for wizard sessions.
- Draft actors are temporary and scoped by `{ widgetId, sessionId }`.
- Relevant files:
  - `docs/internal/llm.widget-system.md`
  - `packages/service-actor/src/Actor.ts`
  - `packages/service-actor/src/icp-client.ts`
  - `packages/service-agent/src/AgentService.ts`
  - `packages/api-agent/src/contract.ts`
  - `packages/sdk/src/widget.ts`
  - `packages/sdk/src/widget-bridge.ts`
  - `packages/canvas/src/components/AiWizzard/index.tsx`
  - `tasks/a/A50.md`

## Plan

### 1. Actor usage modes
- Keep one `Actor` class.
- Add JSDoc to `Actor` explaining both usage modes:
  - published mode: owned by `ActorSupervisor`, backed by DB rows/connections outside the Actor class
  - draft mode: owned by `AgentService`, backed by wizard draft files and disposed with the wizard session
- Ensure constructor config remains generic: id, manifest, rootDir, optional state/data.
- Avoid adding DB, supervisor, or canvas concepts into `Actor`.

### 2. AgentService draft actor ownership
- Add an internal draft actor map in `AgentService`, keyed by widget id and session id.
- Draft actor root should be the wizard cwd where scaffold/files are generated.
- Draft actor manifest should be loaded from draft `vibecanvas.json`.
- Do not auto-start draft actors from `connectWizzard`; connecting the AI wizard chat and starting the draft runtime are separate actions.
- Starting/reloading a draft actor should close any existing actor for the same wizard session.
- Stopping a draft actor should dispose only that draft runtime, not the AI wizard chat session.
- Closing/resetting a wizard session should dispose the draft actor.

### 3. Draft actor API
- Add typed API endpoints under `agent.wizzard` in a nested draft actor namespace, for example `agent.wizzard.draftActor.*`.
- Draft actor lifecycle must be explicit; `connectWizzard` must not start the actor.
- Minimum endpoints:
  - start/reload draft actor from current draft files
  - stop draft actor for the wizard session
  - inspect whether a draft actor is running/ready, including current snapshot when available
  - send input message `{ name, payload }`
  - reset draft actor to initial state/data
  - read latest draft manifest and widget source map for Preview Tab
- Prefer reusing existing agent event stream for draft actor updates, or add a typed event endpoint if cleaner.
- Events must be enough for both Actor and Preview tabs to stay synced.

### 4. Planned ORPC API shape
- Keep the draft runtime API under the wizard namespace because draft actors are scoped to wizard sessions.
- Proposed endpoints:
  - `agent.wizzard.draftActor.start({ widgetId, sessionId }) -> TAgentDraftActorResult`
    - Explicitly starts or reloads the draft actor from current draft files.
    - Disposes any existing draft actor for the same `{ widgetId, sessionId }` first.
    - Returns `ready: false` with a clear reason when draft files are not ready.
  - `agent.wizzard.draftActor.stop({ widgetId, sessionId }) -> { stopped: boolean }`
    - Disposes the draft actor runtime only; leaves the AI wizard chat session alive.
  - `agent.wizzard.draftActor.inspect({ widgetId, sessionId }) -> TAgentDraftActorInspectResult`
    - Reports whether a draft actor is currently running/ready.
    - Includes `{ state, context }` snapshot when running.
    - Can include latest not-ready/readiness diagnostics when not running.
  - `agent.wizzard.draftActor.send({ widgetId, sessionId, name, payload }) -> { messageId: string } | not-ready`
    - Sends an input message to the shared draft actor for this wizard session.
    - Messages sent from Actor or Preview tabs update both via shared events.
  - `agent.wizzard.draftActor.reset({ widgetId, sessionId }) -> TAgentDraftActorResult`
    - Resets runtime to manifest initial state/data, preferably by recreating the draft actor from current files.
  - `agent.wizzard.previewSource({ widgetId, sessionId }) -> TAgentPreviewSourceResult`
    - Reads latest draft `vibecanvas.json` and widget source map for Preview Tab without starting the actor.
- Planned shared input shape:
  ```ts
  type TAgentWizzardDraftActorScope = {
    widgetId: string;
    sessionId: string;
  };
  ```
- Planned result shapes:
  ```ts
  type TAgentDraftActorSnapshot = {
    state: TActorState;
    context: TActorData;
  };

  type TAgentDraftActorNotReadyReason =
    | 'session-missing'
    | 'manifest-missing'
    | 'manifest-invalid'
    | 'actor-functions-missing'
    | 'actor-not-running';

  type TAgentDraftActorResult =
    | { ready: true; actorId: string; snapshot: TAgentDraftActorSnapshot }
    | { ready: false; reason: TAgentDraftActorNotReadyReason; message: string };

  type TAgentDraftActorInspectResult =
    | { running: true; actorId: string; snapshot: TAgentDraftActorSnapshot }
    | { running: false; reason?: TAgentDraftActorNotReadyReason; message?: string };

  type TAgentDraftActorSendResult =
    | { ready: true; messageId: string; snapshot: TAgentDraftActorSnapshot }
    | { ready: false; reason: TAgentDraftActorNotReadyReason; message: string };

  type TAgentPreviewSourceResult =
    | { ready: true; manifest: TVibecanvasJson; sources: Record<string, string> }
    | { ready: false; reason: TAgentDraftActorNotReadyReason; message: string };
  ```
- Proposed event discriminant on existing `agent.events` stream:
  - chat/session events keep current shape.
  - draft actor events use a clear discriminant such as `{ kind: 'draft-actor', widgetId, sessionId, event }`.
  - snapshot update events should carry `{ state, context }` so Actor and Preview tabs stay synced without independently reconstructing state.

### 5. Shared state/event contract
- Convert `Actor` events to SDK-compatible snapshots:
  - `state.changed` updates snapshot state
  - `data.changed` updates snapshot context
  - `error` can be exposed to tabs as runtime diagnostics
- Keep first pass aligned with current `Actor` transition semantics: functions execute in the child process, and automatic state change occurs when the transition has exactly one allowed target state.
- Both Actor Tab and Preview Tab must subscribe to the same draft actor event source.
- Sending a message from either tab must update both tabs.

### 6. Approval/scaffold relationship
- Draft actor runtime should run after generated draft files exist.
- If no `vibecanvas.json` or actor functions exist yet, API should return a clear not-ready result.
- Do not publish draft actors into the normal actor registry.
- Do not create normal `actor_instances` DB rows for draft preview.

### 7. Tests/checks
- Test that `AgentService` can start a draft actor from a temp wizard cwd.
- Test snapshot returns initial state/data.
- Test sending a valid message returns a message id and emits snapshot updates.
- Test reset returns to manifest initial state/data.
- Test reload disposes old actor and starts from current draft files.
