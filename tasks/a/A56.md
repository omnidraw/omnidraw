# A56 - ai wizard: Tool tab for widget toolbar metadata
[Overview](../../BASED.md)

Add an AI wizard Tool tab that explains and configures widget toolbar metadata.

## Context
The AI wizard currently has Chat, Actor, Preview, and Settings tabs in [`packages/canvas/src/components/AiWizzard/index.tsx`](../../packages/canvas/src/components/AiWizzard/index.tsx). Widget toolbar metadata is stored in `widget.tool` inside `vibecanvas.json`; valid entries are defined by [`packages/service-actor/src/core/vibecanvasjson.zod.ts`](../../packages/service-actor/src/core/vibecanvasjson.zod.ts) and mirrored in [`packages/service-actor/src/core/types.ts`](../../packages/service-actor/src/core/types.ts). Runtime toolbar behavior is handled by [`packages/canvas/src/services/tool/types.ts`](../../packages/canvas/src/services/tool/types.ts), [`packages/canvas/src/services/tool/ToolService.ts`](../../packages/canvas/src/services/tool/ToolService.ts), and widget registration currently flows through [`packages/canvas/src/services/widget/fx.register-tool.ts`](../../packages/canvas/src/services/widget/fx.register-tool.ts).

## Plan
1. Add a new `Tool` tab under `packages/canvas/src/components/AiWizzard/`.
2. Read the latest wizard draft manifest/candidate and show current `widget.tool` values.
3. Help setup how the widget appears in the canvas toolbar: group, name/label, icon, priority/order, and behavior.
4. Show valid manifest entries and note any runtime mismatch.
5. Decide whether the tab is read-only guidance, form editing, or chat-assisted editing before implementation.

## NOTES
Valid manifest entries researched:
- `label` is required and is the toolbar display name.
- `icon` is optional; toolbar accepts a string, sanitizes SVG markup, and falls back to the first two tool id letters if omitted.
- `group` is optional; runtime type notes it is planned for dropdown/grouping.
- `priority` is optional; lower numbers sort earlier and runtime defaults to `10000`.
- `behavior` is required; valid values are `{ type: "mode", mode: "draw-create" | "click-create" | "select" | "hand" }`, `{ type: "action" }`, or `{ type: "modal" }`.
- Actor-backed widget registration currently hard-codes runtime behavior to draw-create in `fx.register-tool.ts` even though manifest validation accepts the full behavior union.
