# A57 - ai wizard: new widget vs edit published widget flow
[Overview](../../BASED.md)

Replace the chat action “New chat” with explicit widget workflows: “New widget” and “Edit existing widget”. Editing a published widget should copy it from the published widget directory into the wizard local widget/draft directory, jump directly to phase 2, bump the version, load the agent with the initial Actor already set up, render Actor/Tool/Preview tabs from the beginning, and publish back over the old widget with runtime reload/replacement.

## Context
- Current chat action menu shows “New chat” and “Copy chat” in `packages/canvas/src/components/AiWizzard/ChatComposer/ChatComposer.tsx`.
- We do not want a generic “New chat” action in the AI wizard UI.
- “New widget” is essentially the current new-chat behavior, but named after the actual workflow.
- “Edit existing widget” should open a selection dialog for already-published widgets.
- Use Kobalte Dialog patterns from `docs/external/llm.kobalte.md`:
  - import from `@kobalte/core/dialog`
  - use `Dialog`, `Dialog.Trigger`, `Dialog.Portal`, `Dialog.Overlay`, `Dialog.Content`, `Dialog.Title`, `Dialog.Description`, close/action controls
  - keep modal focus behavior and style all parts with local classes
- Published widgets are the installed widget folders under config `widgets`, surfaced today through actor definitions and manifests.
- Use `actors.definitions.list` from `packages/api-actors/src/contract.ts` as the published-widget picker API, and extend that list response to include manifest `version`.
- Editing must not mutate the published folder until the user publishes.
- This task builds on the wizard draft/session work in [A50](A50.md), draft Actor setup in [A53](A53.md), Actor tab in [A54](A54.md), and Preview tab in [A55](A55.md).

## Plan

### 1. UI action rename and workflow split
- Replace `onNewChat` naming in AI wizard-facing components with widget workflow actions.
- Chat action menu should show:
  - `New widget`
  - `Edit existing widget`
  - `Copy chat`
- `New widget` should perform the existing blank-session reset behavior:
  - create a fresh session id
  - clear message history
  - clear draft/candidate/preview state
  - start in phase 1
- Avoid exposing “chat” as the primary noun in this workflow.

### 2. Published widget picker dialog
- Add a Kobalte Dialog for `Edit existing widget`.
- Dialog should list published widgets with enough information to choose safely:
  - name
  - slug
  - version
  - description
  - manifest path or short source hint if useful
- Use existing actor definition/manifest APIs for listing: extend `actors.definitions.list` to return version along with the actor definition fields.
- Do not add a separate list-published-widgets API unless later implementation proves actor definitions cannot represent the picker data.
- Show loading, empty, and error states.
- Confirming a widget starts an edit workflow for that published widget.

### 3. Edit workflow backend preparation
- Add a deterministic service/API path to start editing a published widget.
- Keep listing separate from edit preparation: the picker should use `actors.definitions.list`, while this new API performs draft/session setup.
- Input should identify the selected published widget by stable definition name, selected from `actors.definitions.list`.
- Backend should create or reset a wizard session/draft cwd for edit mode.
- `startWidgetEdit` must copy the selected widget from the published widget directory into the wizard local widget/draft directory used by the agent runtime.
- The copied local widget directory becomes the source of truth for the edit session; the published directory remains untouched until explicit publish.
- Exclude unsafe/transient folders when copying, for example `node_modules`, `.git`, and wizard metadata folders.
- Bump `vibecanvas.json.version` in the draft immediately so AI and UI operate on the next version.
- Record edit metadata in the session, for example:
  - source definition name
  - source slug
  - source manifest path
  - previous version
  - next version
  - edit mode marker
- Append/derive the same approval/phase marker used by A50 so `connectWizzard()` enters phase 2 immediately.
- Initialize the edit session as if the initial Actor setup is already complete, because the copied widget already contains `vibecanvas.json`, actor files, widget files, and tool definitions.
- Return latest `vcJson`, phase, source metadata, message history/draft status, and enough draft runtime identifiers for the frontend to render Actor, Tool, and Preview tabs immediately.

### 4. Version bump rules
- Add a small deterministic version bump helper.
- Recommended first-pass behavior:
  - numeric string like `1` -> `2`
  - semver-like `1.2.3` -> `1.2.4`
  - missing version -> `1`
  - unknown format -> append or replace with a safe next value after deciding and documenting the rule
- Ensure the bumped version is written to draft `vibecanvas.json` before draft Actor/Preview starts.
- On publish, the bumped version becomes the published version.

### 5. Phase 2 and draft runtime integration
- Editing an existing widget should skip phase 1 actor-candidate generation.
- Agent loading for edit mode must start in phase 2 with the initial Actor already set up from the copied local widget directory.
- Actor Tab, Tool Tab, and Preview Tab should be available/rendered from the beginning of the edit session.
- Actor Tab, Tool Tab, and Preview Tab should use the copied draft files through A53/A54/A55 draft runtime APIs.
- Chat should be able to continue from edit mode with phase 2 tools only.
- Prompt/session context should mention that the user is editing an existing published widget and include source/version metadata.

### 6. Publish edited widget back over the old widget
- Publishing an edited widget should use the normal existing publish API/path.
- Do not add a separate publish-edited-widget API unless the normal publish path cannot carry the required edit metadata.
- In edit mode, normal publish should overwrite/replace the original published widget directory with the draft/local widget directory, same as the existing publish behavior overwrites the target directory.
- Validate draft files before replacement.
- Keep publish explicit; selecting edit must not mutate published files.
- After successful publish, trigger frontend reload/refresh of available tools so the UI sees the updated widget/tool definitions.
- Backend must reload loaded actor definitions after successful publish.
- Backend should also update/restart/reset existing actor instances for the edited definition so they use the new version. If this actor-instance reload/replacement is too complicated, split it into a follow-up task and clearly document the limitation.

### 7. Replace old running instances on edited publish
- Current actor reload loads missing instances but does not necessarily restart existing actor runtimes for an updated definition.
- Prefer extending the normal publish success path to reload the edited definition and update/restart/reset existing runtime instances for that definition.
- First-pass replacement can reset existing instances of that definition to the new manifest initial state/data, then restart them with the new files.
- Document that data migration is out of scope unless a later task adds migrations.
- Ensure existing canvas widget elements continue pointing at valid actor instance ids or are patched if ids are replaced.
- Emit events/notifications so frontend widget registrations, tool lists, and previews refresh after replacement.
- If reliable existing-instance replacement is too large/risky, create a separate follow-up task for actor instance migration/restart and keep A57 focused on publish overwrite + definition/tool reload.

### 8. Tests/checks
- Test version bump helper.
- Test edit preparation copies a published widget to draft and bumps version without changing source files.
- Test edit preparation records phase/edit metadata and reconnect enters phase 2.
- Test UI action labels no longer show “New chat”.
- Test published widget picker uses Dialog and handles loading/empty/error states.
- Test normal publish API in edit mode replaces/overwrites original published files.
- Test successful publish triggers frontend tool reload/refresh.
- Test publish calls backend actor definition reload.
- Test existing actor instances for the edited definition are restarted/reset or otherwise clearly handled; if deferred, test/document the explicit limitation.

## NOTES
- “New widget” is the current blank session/new chat behavior with better product wording.
- “Edit existing widget” is not an in-place edit; it always works from a copied draft.
- Edit mode intentionally jumps to phase 2 because a complete `vibecanvas.json`, actor files, widget files, and tool definitions already exist in the copied local widget directory.
- Version bump is mandatory for edited published widgets.
- Replacing old running instances is new behavior and should be implemented deliberately, not as an accidental side effect of reload. If too complicated for A57, defer it into an explicit follow-up task while still reloading definitions/tools after publish.
- Data migration for old actor contexts is out of scope for the first pass; reset-to-initial is acceptable if documented.
