# A92 - canvas: cut API, CLI, and runtime over to CanvasService
[Overview](../BASED.md)

Perform the coordinated flag-day cutover to CanvasService, local per-user
history, and centralized widget state.

## Result

Canvas lifecycle, snapshot, indexed query, command, and revision subscriptions
now use the typed oRPC WebSocket API. The CLI implements remote
list/query/add/patch/move/group/ungroup/reorder/delete and dry-run commands
against the same contract.

The browser uses `CanvasDocumentService` to load snapshots, reconcile exact
events, resync gaps, issue optimistic guarded commands, and maintain a bounded
100-entry local-only undo/redo history. Direct Cangine IDs and nodes are the
product model. Widget portals are materialized only at runtime while widget
identity remains transactional persisted metadata.

The development database was destructively reset and recreated from the new
schema.
