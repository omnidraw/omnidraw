# A92 - canvas: coordinated CanvasService cutover with product parity
[Overview](../BASED.md)

Cut API, CLI, browser runtime, widgets, and product tools over to CanvasService
and Cangine nodes without changing or reducing the user-facing product.

## Recovery references

- Pre-cutover product source: commit `396e9b45`
- Authority-cutover checkpoint: commit `3db71817`
- Visual contract: `docs/internal/screens/SCREENS.md`, especially canvas screens
  `10` through `17`

## Plan

1. Retain the completed typed snapshot/query/command/event API and CLI cutover.
2. Restore presentation and product-policy files from the pre-cutover source as
   reference, not as an Automerge rollback.
3. Port grid, camera, toolbar, drawing, transform, selection, styles, context
   menu, images, gestures, and keyboard behavior to direct Cangine/editor APIs.
4. Port widget frames, placement, portals, runtime mounting, draft Preview, and
   AI chat canvas extensions to CanvasDocumentService and WidgetStateService.
5. Prove visual and behavioral parity before declaring the cutover complete.

- Image placement and retained resource behavior
- Widget frame actions, maximize/restore, direct placement, and state
- AI chat, provider settings, draft Preview, and widget-create flows
- Accessibility, lifecycle teardown, reconnect, restart, and tenant switching
