# A122 - server startup: import existing Pi credentials once
[Overview](../BASED.md)

Let a first Omnidraw server start reuse credentials from the user's existing Pi
installation. Import Pi's auth file only when Omnidraw has no private auth file,
without overwriting, merging, or weakening credential permissions.

## Context

Omnidraw embeds Pi through `ModelRuntime.create()` with a private credential
path in
[`AgentService.ts`](../../apps/backend/src/shell/agent/AgentService.ts). With the
default home layout that path is
`~/.omnidraw/agent/pi/agent/auth.json`; an `OMNIDRAW_HOME` or `--data-dir`
override changes only the Omnidraw-home prefix.

Pi's official [Providers documentation](https://pi.dev/docs/latest/providers)
states that interactive login stores API-key and OAuth credentials in
`~/.pi/agent/auth.json`, that Pi refreshes expiring tokens there, and that the
file is created with mode `0600`. The official
[SDK documentation](https://pi.dev/docs/latest/sdk) confirms that
`ModelRuntime.create()` uses that path by default and accepts a custom
`authPath`, which is the boundary Omnidraw already uses.

The source file is therefore compatible with Omnidraw's Pi runtime, but the two
locations must remain independent after bootstrap. A symlink would let login,
logout, token refresh, or credential removal in one application mutate the
other. Parsing or merging credentials in Omnidraw would also duplicate Pi's
format authority and become stale as Pi adds providers or credential forms.

## Plan

1. Add a shell-owned auth bootstrap helper with injected filesystem effects.
   Check the destination first and return without inspecting the source when
   any destination entry already exists.
2. If the destination is absent, inspect `~/.pi/agent/auth.json` through normal
   filesystem resolution so a symlink to a regular credential file remains a
   supported Pi setup. Treat a missing source as a normal no-op and reject a
   non-file source.
3. Copy the source as opaque bytes with exclusive-create semantics, create the
   private Pi directory with mode `0700`, and force the copied file to `0600`.
   If permission hardening fails, remove the newly copied destination.
4. Run the bootstrap at the live backend shell edge before `AgentService` and
   `ModelRuntime` start. Unexpected import failures should emit one warning and
   allow the server to continue into its existing login flow.
5. Share the Omnidraw Pi-directory projection between startup bootstrap and
   `AgentService` so the copied destination cannot drift from the configured
   `ModelRuntime.authPath`.
6. Add focused filesystem tests for copy, permission hardening, existing-file
   preservation, missing source, symlink source, invalid source, and path
   projection. Run the backend typecheck.

## Acceptance criteria

- On server startup, when Omnidraw's configured Pi `auth.json` is absent and
  `~/.pi/agent/auth.json` is a regular file or symlink to one, Omnidraw copies
  its exact bytes before creating `ModelRuntime`.
- The imported destination is a separate regular file with mode `0600`, inside
  an owner-only Pi directory where the platform supports POSIX permissions.
- An existing Omnidraw auth file, symlink, directory, or other entry is never
  overwritten, merged, chmodded, or replaced, and the source is not inspected.
- A missing source leaves the destination absent and does not warn or fail
  startup.
- An unreadable or invalid source, copy failure, or permission-hardening failure
  does not prevent the backend from starting; it emits a warning and leaves the
  existing interactive login/API-key flow available.
- Omnidraw does not parse or log credential contents and does not add a second
  credential schema.
- Later Pi or Omnidraw login/logout/token-refresh operations affect only their
  respective copied file.

## NOTES

- The current private path is `~/.omnidraw/agent/pi/agent/auth.json`, not
  `.omnidraw/pi/agents/auth.json`. The implementation follows the exact
  `ModelRuntime.authPath` already owned by `AgentService` rather than introducing
  another layout.
- This is deliberately one-time bootstrap behavior. Omnidraw does not
  continuously synchronize credentials from Pi and never overwrites local
  choices made after first start.
- `ModelRuntime` remains responsible for credential-format validation,
  provider availability, OAuth refresh, and persistence after import.
- No public package runtime changes or version bumps are required.
