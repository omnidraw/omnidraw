# A112 - chat tool: auto-return to select mode after placing a chat widget
[Overview](../BASED.md)

Pressing `c` selects the AI Chat tool. After drawing a chat widget, the tool
stays active, so the next drag draws another chat. Rect/line etc. should keep
that sticky behavior — only chat should snap back to select mode (as if you
pressed `Esc` / `1`).

## Context

How chat placement works today:

- `apps/frontend/src/services/canvas-composition.ts` (`frontendToolbarContributions`)
  registers the AI Chat toolbar tool: `kind: 'tool'`, shortcut `c`,
  `toolId: 'widget'`. Pressing `c` activates Cangine's generic `widget` tool.
- `packages/canvas/src/components/Canvas.tsx` maps contribution shortcuts and
  toolbar clicks to `editor.setActiveTool(...)`.
- `packages/canvas/src/runtime.ts` (~line 674) wires the Cangine creation
  factory `factories.widget`. It loops over `runtimeExtensions` and calls each
  extension's `createWidgetNodes(...)`; the first non-null result wins.
- `packages/ui-ai-chat/src/canvas-extension/index.ts`
  (`createAiChatCanvasExtension`) is currently the only extension implementing
  `createWidgetNodes`; it returns the chat widget node via `fnCreateAiWidgetNode`
  (`fn.canvas-widget.ts`, extension marker `type: 'ui-widget'`, `kind: 'ai'`).
- Cangine's standard widget tool commits the node, selects/focuses it, and then
  calls the `onWidgetCreated(nodeId)` hook (see
  `node_modules/@omnidraw/cangine/dist/editor/types.d.ts` —
  `TStandardCanvasEditorConfig.onWidgetCreated`). The tool itself stays active,
  same as rect/ellipse/connector. `packages/canvas/src/runtime.ts` does not
  pass `onWidgetCreated` today. This hook is the intended seam.

Constraint: `@omnidraw/canvas` must not import `@omnidraw/ui-ai-chat`
(one-way integration, see `packages/ui-ai-chat/README.md`). So the canvas
runtime cannot hardcode "chat widget => switch to select"; the extension must
opt in.

## Plan

### 1. Extension opt-in flag (`packages/canvas/src/extension.ts`)

Add an optional field to `ICanvasRuntimeExtension`:

```ts
/**
 * When true, the canvas returns to the select tool immediately after this
 * extension's widget creation commits (one-shot placement). Default: sticky.
 */
oneShotWidgetCreation?: boolean;
```

### 2. Runtime enforcement (`packages/canvas/src/runtime.ts`)

Inside `createCanvasRuntime` where the `factories.widget` closure lives:

- Track which extension produced the current widget creation in a local
  mutable variable, e.g. `lastWidgetCreationExtension`:
  - set it when an extension's `createWidgetNodes` returns non-null
  - reset to `null` when the loop falls through (no extension claimed it)
- Add `onWidgetCreated: () => { ... }` to the `createStandardEditorSession`
  `editor` config:
  - read and clear `lastWidgetCreationExtension`
  - if that extension has `oneShotWidgetCreation === true` and
    `editorSession?.editor.state.activeToolId === 'widget'`, call
    `editorSession.editor.setActiveTool('select')`

This mirrors the existing Escape handling in `Canvas.tsx`
(`editor()?.setActiveTool('select')`) and the `setSelectedConnectorSegmentMode`
pattern in `runtime.ts` (~line 1032). No effect on rect/ellipse/pen/connector:
those kinds never invoke `onWidgetCreated`.

### 3. Chat extension opts in (`packages/ui-ai-chat/src/canvas-extension/index.ts`)

In `createAiChatCanvasExtension`'s returned object, add
`oneShotWidgetCreation: true` next to `createWidgetNodes`.

### 4. Versioning and lockfile

- `@omnidraw/canvas` `src/` behavior change: bump `0.6.0` -> `0.6.1` in
  `packages/canvas/package.json` (patch; additive optional API + behavior fix),
  then `bun install` to regenerate `bun.lock`.
- `@omnidraw/ui-ai-chat` is unversioned/private: no bump.

### 5. Tests (`packages/canvas/tests/runtime.test.ts`)

Add coverage (follow existing runtime test setup):

- extension with `oneShotWidgetCreation: true`: after widget tool creation
  commits, active tool is `select`.
- extension without the flag: active tool stays `widget`.

### Out of scope

- Auto-focusing/opening chat content after placement (separate behavior).
- Other widget types (capsule previews etc. are not drawn via the widget tool).

## NOTES

- Cangine keyboard map: `w` also activates the widget tool; behavior applies
  there too, which is desirable.
- `onWidgetCreated` fires after commit + selection, so switching tools inside
  it does not disturb the creation gesture (pointer already up).
- `fnCanvasWidgetExtension` marker (`ui-widget`/`ai`) is an alternative gate,
  but it would couple `packages/canvas` to the chat contract; the opt-in flag
  keeps canvas generic.
