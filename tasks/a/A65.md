# A65 - agent tools: self-contained web_fetch tool
[Overview](../../BASED.md)

Build a fast, low-footprint `web_fetch` agent tool as a single self-contained file.

## Context
We need a new tool in `packages/service-agent/src/tools/` that fetches a URL without a browser and returns `raw`, `text`, or `markdown` output. It should be local/free, fast, bounded by timeout and byte limit, and detect likely SPA/app-shell pages instead of trying to render JavaScript.

Relevant target:
- `packages/service-agent/src/tools/`

Desired API shape:
- input: `url`, optional `format: "raw" | "text" | "markdown"`, optional `timeoutMs`, optional `maxBytes`
- result: `url`, `finalUrl`, `status`, `contentType`, optional `title`, `format`, `content`, `truncated`, `likelySpa`, optional `spaReason`
- defaults: `format: "markdown"`, `timeoutMs: 8000`, `maxBytes: 1_000_000`

Implementation constraints:
- keep the tool implementation self-contained in one file
- use native `fetch`, `AbortSignal.timeout`, and streaming byte limits
- do not use Playwright, Puppeteer, jsdom, Brave, Google, paid APIs, or browser automation
- prefer Cheerio + Turndown + GFM if dependencies are acceptable in this package
- detect likely SPA/app shell and return metadata; do not fail just because JavaScript is required
- validate only `http://` and `https://`; do not claim HTTP is upgraded unless implemented
- choose `Accept` headers based on requested format and use a normal browser-like `User-Agent`

## Plan
1. Inspect existing agent tool conventions in `packages/service-agent/src/tools/`.
2. Add required dependencies only if not already available and if they fit package policy.
3. Implement `web_fetch` as one self-contained tool file.
4. Validate URL protocol and fetch with timeout, redirects, user-agent, format-specific `Accept` header, and byte cap.
5. Check `content-length` early when present, then enforce the byte cap while reading the body.
6. Return raw bodies directly; parse HTML for text/markdown; trim noise elements.
7. Add SPA/app-shell heuristics for short content, app roots, JS bundles, loading shells, and JS-required text.
8. Add a small test or manual verification note for static HTML, text response, truncation, and SPA detection.

## NOTES
Requested behavior: default web tool should be strict, fast, predictable, local/free, and non-rendering. If a page needs JavaScript, report `likelySpa=true` with a reason.

Learnings from opencode's `webfetch` implementation:
- It uses a plain tool wrapper around native `fetch`, no browser/rendering layer.
- It validates `http://`/`https://`, applies a timeout, and caps responses at 5MB using both `content-length` and actual body size.
- It sets format-specific `Accept` headers plus a browser-like UA; this is worth copying in simplified form.
- HTML-to-markdown is handled with Turndown after removing `script`, `style`, `meta`, and `link`.
- Text extraction can be simple if Cheerio is available: remove noisy nodes, then use normalized text.
- Be careful that docs match behavior; opencode's description says HTTP is upgraded, but code does not do that.
