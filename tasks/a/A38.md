# A38 - widgets: fullscreen DOM window mode
[Overview](../../BASED.md)

Make the green widget button toggle fullscreen using the existing widget body div, preserving mounted widget state.

## Context
- Widget host chrome is currently Konva-driven in `packages/canvas/src/services/widget/fn.create-widget-node.ts`.
- Widget body DOM portal is created in `packages/canvas/src/services/widget/tx.attach-dom-portal.ts`.
- Header buttons are wired in `packages/canvas/src/services/widget/fx.attach-widget-listener.ts`.
- Widget registration and resize sync live in `packages/canvas/src/services/widget/WidgetManagerService.ts`.
- Camera viewport math lives in `packages/canvas/src/services/camera/CameraService.ts`.
- Scene container size and layers live in `packages/canvas/src/services/scene/SceneService.ts`.

Problem:
- Green fullscreen button should make a widget take the full available canvas parent div area.
- Fullscreen must render over toolbar/sidebar overlays with DOM z-index.
- The same widget body div instance must be reused. Do not recreate/remount widget content, because internal widget state must survive fullscreen enter/exit.

Important constraint:
- Fullscreen should be a window mode, not destructive geometry resize.
- Persist `data.window` mode if needed, but avoid replacing contained `x/y/w/h` with viewport-derived fullscreen values unless explicitly required.

## Plan

### 1. Model fullscreen as window mode
- Use widget data `window: "contained" | "fullscreen"`.
- Add local constants for fullscreen mode, previous contained bounds attr, and fullscreen z-index.
- Keep previous contained bounds on the Konva node before entering fullscreen.

### 2. Reuse same body div
- `txAttachDomPortal` should keep exactly one DOM body div per widget node.
- Fullscreen should move/restyle that existing div, not create a second div.
- Exiting fullscreen should put the same div back under normal camera/body transform behavior.

### 3. DOM fullscreen presentation
- When fullscreen, the body div should use viewport/container-fixed styling relative to the scene/stage container.
- It must cover the available parent canvas area, excluding sidebar naturally if the canvas container is already resized by layout.
- It must get z-index high enough to render over toolbar.
- Pointer events should remain enabled for widget content.

### 4. Konva chrome strategy
- Short term: hide or de-emphasize Konva chrome if DOM fullscreen chrome is introduced later.
- Long term preferred: render fullscreen window chrome/header/body as DOM while preserving the same body div instance.
- Do not duplicate widget body or remount hosted content.

### 5. Sync triggers
- Green maximize button toggles contained/fullscreen.
- On fullscreen enter/exit, call DOM portal sync immediately.
- While fullscreen, sync on scene resize.
- While fullscreen, camera changes should not visually move fullscreen DOM body, unless Konva fallback chrome still depends on it.

### 6. Restore contained mode
- On exit fullscreen, restore previous contained `x/y/w/h` from node attr.
- Restore DOM div to normal absolute transform mode using `body.getAbsoluteTransform().getMatrix()`.
- Preserve widget internal DOM state.

## NOTES
- The body div identity is part of the feature requirement. Tests should compare object identity before/after fullscreen toggle.
- Avoid using fullscreen as ordinary canvas resize. If persisted geometry is overwritten by viewport values, exiting fullscreen cannot restore the user's placed window reliably.
- DOM z-index is required for toolbar overlap. Konva z-order alone cannot draw over DOM toolbar elements.
- If canvas container excludes sidebar through layout, use `scene.container.clientWidth/clientHeight`; do not manually subtract sidebar width.
