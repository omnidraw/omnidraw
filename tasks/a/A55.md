# A55 - ai wizard: Preview tab powered by draft Actor
[Overview](../../BASED.md)

Build the Preview tab so generated widget UI runs against the shared draft Actor runtime from [A53](A53.md). Preview and Actor tabs must stay synchronized because both use the same draft actor state.

## Context
- Depends on [A53](A53.md).
- Complements [A54](A54.md).
- Preview should exercise real generated widget code and real generated actor backend functions before publish.
- It should not publish the widget or create normal DB-backed actor instances.

## Plan

### 1. Preview source loading
- Load generated draft widget files through the draft source API from A53 after approval/scaffold.
- Use latest `vibecanvas.json` to discover `widget.relWidgetDir` and widget entry files.
- Show a not-ready state before scaffold exists.

### 2. Sandbox bridge
- Reuse the widget SDK bridge shape where possible.
- Connect preview widget `actor.sendMessage(...)` to draft actor send API.
- Connect preview widget `actor.state` and `actor.context` to shared draft actor snapshots.
- Keep ORPC/internal services hidden from guest widget code.

### 3. Shared state with Actor tab
- Preview subscribes to the same draft actor snapshot/event stream as Actor Tab.
- Sending messages from widget UI updates Actor Tab.
- Sending messages from Actor Tab updates widget UI.

### 4. Runtime lifecycle
- Start/reload draft actor when preview opens or when draft files change.
- Provide manual reload if generated files are edited.
- Reset should reset the shared draft actor, affecting both tabs.
- Dispose preview sandbox cleanly when tab/widget unmounts.

### 5. Error display
- Surface widget compile/sandbox errors.
- Surface actor runtime errors.
- Show missing-file/not-ready errors with clear next steps.
