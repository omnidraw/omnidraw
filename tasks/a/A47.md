## ProseMirror research notes

Docs read:
- ProseMirror Guide: `https://prosemirror.net/docs/guide/`
- ProseMirror Reference: `https://prosemirror.net/docs/ref/`
- Tooltip/plugin-view example: `https://prosemirror.net/examples/tooltip/`
- Upload handling example: `https://prosemirror.net/examples/upload/`
- Autocomplete search results: `prosemirror-autocomplete`, `@quartzy/prosemirror-suggestions`

Important ProseMirror model:
- Core pieces are modular:
  - `prosemirror-model` for schema/document model
  - `prosemirror-state` for `EditorState`, selections, transactions, plugin state
  - `prosemirror-view` for `EditorView` DOM integration
  - `prosemirror-transform` for document changes used by transactions
- State is persistent/immutable. Editing creates transactions; the view applies transactions and calls `view.updateState(newState)`.
- Plugins are the main extension point for history, keymaps, suggestions, paste handling metadata, decorations, and plugin views.
- Commands are functions that can be bound to keys or UI controls.
- For a prompt composer, keep the schema intentionally small. Avoid a general rich text editor unless product needs it.

Useful ProseMirror APIs and patterns:
- `EditorState.create({ schema, plugins })` initializes the editor.
- `new EditorView(element, { state, dispatchTransaction, handlePaste, handleKeyDown, ... })` mounts the editor.
- `dispatchTransaction(tr)` is the integration point to sync Solid state and derive plain-text/structured prompt value.
- `Plugin` with `state.init/apply` can track active mention/slash query state.
- `Decoration`/`DecorationSet` can highlight the active trigger range and render placeholders or upload chips.
- Plugin views can attach external DOM UI to the editor lifecycle and position menus using `view.coordsAtPos(pos)`.
- Upload/image handling example uses placeholder decorations that are mapped through transactions so async completion still inserts at the right place.

Autocomplete package options:
- `prosemirror-autocomplete` supports triggers like `@mentions` and `/menus`, but assess maintenance and API shape before adding.
- `@quartzy/prosemirror-suggestions` exposes trigger matching and callbacks but does not render UI; good if we want custom Solid/Kobalte menu UI.
- A custom small plugin may be better for this composer because requirements are narrow and UI must match Vibecanvas.

### 2. Add a ProseMirror composer component

Prefer a dedicated local component or subfolder to keep tab orchestration simple:
- `packages/canvas/src/components/AiWizzard/ChatComposer/ChatComposer.tsx`
- `packages/canvas/src/components/AiWizzard/ChatComposer/fn.*.ts` only if pure logic is extracted.
- `packages/canvas/src/components/AiWizzard/ChatComposer/tx.*.ts` only if impure editor setup/update helpers are extracted and function-file rules are followed.

Solid integration shape:
- Mount `EditorView` in `onMount` against a `let root!: HTMLDivElement`.
- Destroy it in `onCleanup` to avoid leaked DOM listeners.
- Use `dispatchTransaction` to apply transactions and update the view.
- Report composer state upward as needed: plain text, structured tokens, image attachments, selected slash command.

### 3. Keep the schema prompt-focused

Initial schema should likely allow:
- doc -> one or more paragraph/block nodes, or just textblock if multiline is desired.
- text content.
- optional inline atom nodes for mentions and image attachments if they should be embedded inside the prompt.

Decision needed:
- If mentions/slash commands are only prompt metadata, keep them as plain text plus structured selection metadata.
- If mentions should become durable chips, define inline atom `mention` node with attrs like `{ id, label, kind }`.
- For pasted images, prefer external attachment chips below/in the composer first. Inline image nodes can come later if the chat backend expects rich content.

### 4. Implement mention and slash command UX

Behavior target:
- Typing `@` opens mention suggestions.
- Typing `/` at start of block or after whitespace opens slash command suggestions.
- Arrow keys move selection; Enter/Tab accepts; Escape closes.
- Mouse click accepts.
- Backspace/editing should close or update the query.

Implementation direction:
- Use a ProseMirror plugin to detect active trigger range from selection and document text around cursor.
- Store plugin state: `{ active: boolean, trigger: '@' | '/', from, to, query }`.
- Use a Solid signal or callback from plugin view to render a menu component outside the editable DOM.
- Position menu using `EditorView.coordsAtPos(from/to)` and account for the composer container bounds.
- On accept:
  - mention: replace trigger range with mention chip node or `@label ` text plus metadata.
  - slash command: replace/remove slash range and set selected command state, or insert command text if that is the desired prompt format.

### 5. Support image pasting

Behavior target:
- Pasting an image from clipboard adds it to the composer as an attachment.
- The UI should immediately show a local preview or placeholder.
- If upload is async, user should still be able to keep typing.

Implementation direction:
- Intercept paste via `handlePaste(view, event, slice)` or `handleDOMEvents.paste`.
- Inspect `event.clipboardData?.files` and `event.clipboardData?.items` for `image/*`.
- For local-only first pass, create attachment objects from `File` and object URLs, then render chips/previews in Solid outside ProseMirror.
- For upload-backed pass, use the ProseMirror upload example pattern:
  - add a placeholder decoration at current selection
  - start upload
  - map placeholder through transactions while the user edits
  - replace/remove placeholder on success/failure
- Decide storage/API path before implementing upload. Existing `apiService` is available to `AiWizzard`, but current `WidgetTab` does not use it.

### 6. Composer UI to match screenshot

Style target from screenshot:
- dark rounded composer card
- placeholder: `Ask for follow-up changes`
- bottom row with plus button, access/model/effort controls, mic, send button
- send button as circular up-arrow affordance

Need to fit current theme variables in `index.css`:
- use `var(--card)`, `var(--background)`, `var(--border)`, `var(--muted-foreground)`, `var(--primary)`, `var(--ring)`
- avoid Tailwind classes; this package is intentionally using package CSS
- ensure focus visible rings and keyboard access

### 7. Submission contract

Decide what Chat tab emits when user submits:
- Plain prompt text
- Mention references
- Selected slash command
- Attached images/files
- Optional rich ProseMirror JSON if needed for draft persistence

Suggested first shape:

```ts
type TChatComposerSubmit = {
  text: string
  mentions: Array<{ id: string; label: string; kind: string }>
  command?: { id: string; label: string }
  images: Array<{ file: File; previewUrl: string }>
}
```

Persist only what is needed. Avoid serializing browser-only `File` objects beyond the submit boundary.
