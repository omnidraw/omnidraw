# A123 - sidebar: align widget icons with row labels

[Overview](../BASED.md)

Make every widget icon sit on the same visual centerline as its widget name in
the sidebar, without changing row height, icon data, or the compact placement
action.

## Context

The supplied browser capture shows the **Click Counter** icon sitting slightly
lower than the adjacent label even though the selected row button is already a
28 px-high grid with centered items.

The relevant rendering path is:

- [`WidgetsSidebarSection.tsx`](../../apps/frontend/src/shell/framework/feature/sidebar/widgets/components/WidgetsSidebarSection.tsx)
  places `WidgetIcon` in the first column of `styles.widgetRowMain`.
- [`WidgetsSidebarSection.module.css`](../../apps/frontend/src/shell/framework/feature/sidebar/widgets/components/WidgetsSidebarSection.module.css)
  gives the row `align-items: center`, gives `.icon` a fixed `1rem` square, and
  makes its nested span/SVG a `1rem` block.
- [`WidgetIcon.tsx`](../../apps/frontend/src/shell/framework/feature/sidebar/widgets/components/WidgetIcon.tsx)
  can render four materially different shapes: custom text/emoji, sanitized
  custom SVG, a `lucide-static` SVG, or the Solid Lucide puzzle fallback.

The supported running-backend CLI resolves the captured draft as widget key
`click-counter`; its current manifest declares `icon: { svgIcon: "🎉" }`. The
capture therefore exercises `WidgetIcon`'s custom-text branch, not its sanitized
SVG branch.

The outer icon slot and label are already geometrically centered. The remaining
mismatch is inside that fixed slot: SVG markup is block-sized, while the custom
emoji still uses inherited browser font and line-box metrics inside its nested
span. Grid centering centers that wrapper box, not the visible glyph. A blanket
change to `WidgetIcon` would also affect the larger widget-detail header, so the
correction should remain sidebar-scoped unless the same defect is independently
reproduced there.

## Plan

![Sidebar widget icon sitting below the Click Counter label centerline](A123.webp)

### 1. Normalize the sidebar icon box

- Keep the existing widget row grid, padding, and `1rem` icon column.
- In `WidgetsSidebarSection.module.css`, make the nested icon host a centered
  fixed-size flex box with an explicit compact line height; keep nested SVGs as
  block content so they do not participate in text-baseline spacing.
- Compare the resulting visible centerline at normal browser zoom. If all icon
  variants retain the same small optical offset, apply one sidebar-host offset
  to `.icon`; do not add source-specific offsets or rewrite icon markup.
- Do not use `vertical-align` as the only fix: `.icon` is a grid item, so inline
  baseline alignment does not control its placement in this row.

### 2. Verify every supported icon form

- Render representative custom text/emoji, custom SVG, Lucide preset, and
  fallback puzzle icons beside the same widget-name text.
- Confirm the icon and label appear vertically aligned at 100% zoom in both
  light and dark themes.
- Confirm long names still truncate, warning icons remain centered, published
  `+ Add` and draft `+ Add draft` buttons stay centered, and row height does not
  change.
- Keep SVG sanitization, manifest values, `viewBox` geometry, and the widget
  detail-page icon unchanged.

### 3. Add focused regression coverage

- Extend the sidebar component fixture to render the supported icon forms and
  preserve their expected DOM paths.
- Use browser-level layout or screenshot evidence for the visual alignment;
  jsdom unit tests cannot validate glyph geometry or computed baselines.
- Run the frontend typecheck and tests. This small cosmetic correction does not
  require a new screen-atlas capture unless implementation changes the sidebar
  layout beyond the baseline adjustment.

## Acceptance criteria

- Widget icons and names share one visually consistent vertical centerline in
  sidebar rows at normal browser zoom.
- No supported icon form gains extra top/bottom whitespace or changes the row
  height.
- Published and draft placement actions remain vertically centered and retain
  their existing labels and warning/primary styling.
- The correction is scoped to sidebar rows; widget icon contract data,
  sanitization, the icon picker, and widget-detail header rendering do not
  change.

## NOTES
