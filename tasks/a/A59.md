# A59 - actor-ui: SolidJS actor state machine view
[Overview](../../BASED.md)

Create a new `@vibecanvas/actor-ui` package that renders a Vibecanvas actor manifest state machine as reusable SolidJS UI.

## Context
- This is split out from the AI wizard Actor tab work so it can be implemented independently.
- The package lives at `packages/actor-ui`.
- It consumes `TVibecanvasJson` / `TVibecanvasActor` manifest data and renders the actor state machine for inspection.
- The renderer does not need to be SVG. It may use regular SolidJS DOM/CSS, SVG, or another lightweight approach if it stays package-local.
- SolidJS must be declared through the root package catalog, e.g. `"solid-js": "catalog:"`.
- Relevant files:
  - `packages/service-actor/src/core/types.ts`
  - `packages/canvas/src/components/AiWizzard/tabs/ActorTab.tsx`
  - `tasks/a/A54.md`
  - root `package.json` catalog

## Plan

### 1. Package scaffold
- Add `packages/actor-ui/package.json` for `@vibecanvas/actor-ui`.
- Export the package from source, for example `./src/index.ts`.
- Add `solid-js` via catalog dependency.
- Add `@vibecanvas/service-actor` as a workspace dependency for manifest types.

### 2. State machine component
- Provide a SolidJS component that accepts actor manifest data.
- Minimum input should support either full `TVibecanvasJson` or `TVibecanvasActor`.
- Render states as visual nodes/items.
- Render transitions with message labels and target state information.
- Highlight the configured `initialState`.
- Show a friendly empty state when there are no states or transitions.

### 3. Reusable API
- Export stable component/types from `packages/actor-ui/src/index.ts`.
- Keep rendering inspect-only: no runtime actor calls, no draft actor calls, no message sending.
- Keep styling package-local and easy for `@vibecanvas/canvas` to import.

### 4. Integration follow-up
- A54 should consume this package for the Actor tab state machine view once available.
- This ticket does not need to implement the Actor tab form or manifest edit API.
