# A54 - ai wizard: Actor tab manifest editor
[Overview](../../BASED.md)

Build the Actor tab UI as a manifest inspection/editing surface for the wizard draft `TVibecanvasJson`. This tab must not connect to backend actor runtime features and must not run or manage any draft actor.

## Context
- This replaces the current placeholder `ActorTab` cards.
- Actor Tab is only for user inspection and manifest editing.
- No backend actor execution is connected from this tab.
- No `DraftActor`, draft actor API, actor runtime snapshot, or runtime message sending belongs in this tab.
- The tab edits limited `TVibecanvasJson` fields and renders a visual actor state machine inspection view.
- Relevant files:
  - `packages/canvas/src/components/AiWizzard/index.tsx`
  - `packages/canvas/src/components/AiWizzard/tabs/ActorTab.tsx`
  - `packages/api-agent/src/contract.ts`
  - `packages/sdk/src/widget.ts`
  - `packages/actor-ui` (tracked separately in [A59](A59.md))

## Plan

### 1. Inputs and source of truth
- Receive the current wizard phase and latest draft `TVibecanvasJson` from `AiWizzard`.
- Treat `TVibecanvasJson` as the source of truth for this tab.
- Do not subscribe to actor runtime events or snapshots.
- Do not call any draft actor start/reload/reset/send APIs.
- If no draft manifest exists yet, show an empty/not-ready state with guidance.

### 2. Manifest edit API
- Add or reuse typed API endpoints for reading and editing the draft `TVibecanvasJson`.
- Scope edits by the wizard/session identifiers already used by the wizard.
- The API must update only draft manifest files, not create actor instances and not start backend actors.
- Needed operations:
  - read latest draft `TVibecanvasJson`
  - patch/update limited manifest metadata fields
  - patch/update actor initial data/schema fields
- Editable fields for this task:
  - `name`
  - `description`
  - `initialData`
  - `dataSchema`
- `initialState` is inspect-only for now and must not be editable in this task.
- Return validation errors as manifest/edit errors, not runtime errors.

### 3. Actor form
- Replace placeholder cards with a form bound to the editable manifest fields.
- Render and edit:
  - name text input
  - description textarea
  - initial state display
  - initial data JSON editor
  - data schema JSON editor
- Validate JSON editors locally before sending updates.
- Show save status, dirty state, and validation errors clearly.

### 4. State machine inspection view
- Render a visual state machine view from `TVibecanvasJson.actor.states` and transitions.
- Prefer consuming the reusable SolidJS package from [A59](A59.md) when available.
- The view does not need to be SVG.
- The view is inspect-only in this task.
- Show states and transitions with labels.
- Highlight the configured `initialState`.
- If the manifest has no states/transitions, show an empty state instead of failing.

### 5. Approval/phase behavior
- In early phases, show candidate/manifest data if available, but keep the tab read/edit focused.
- Do not trigger backend runtime setup after approval from this tab.
- If approval/scaffold creates or updates `vibecanvas.json`, refresh the manifest form from the draft manifest API.
