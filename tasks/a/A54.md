# A54 - ai wizard: Actor tab powered by draft Actor
[Overview](../../BASED.md)

Build the Actor tab UI on top of the shared draft Actor runtime from [A53](A53.md). The tab should inspect the contract and interact with the same running draft actor state used by Preview.

## Context
- Depends on [A53](A53.md).
- This replaces the current placeholder `ActorTab` cards.
- Actor Tab is no longer only a local state explorer: it should send real input messages to the draft Actor so backend functions execute and state/data changes are real.
- It must share runtime state with Preview Tab.
- Relevant files:
  - `packages/canvas/src/components/AiWizzard/index.tsx`
  - `packages/canvas/src/components/AiWizzard/tabs/ActorTab.tsx`
  - `packages/api-agent/src/contract.ts`
  - `packages/sdk/src/widget-bridge.ts`
  - `tasks/a/A53.md`

## Plan

### 1. Data and phase inputs
- Receive wizard phase, actor candidate, latest `vibecanvas.json`, draft actor snapshot, and runtime diagnostics from `AiWizzard`.
- Phase 1 can show the candidate contract and approval action when no draft files exist yet.
- Runtime controls are available only when the draft actor is ready from generated files.
- Phase 2 should use generated `vibecanvas.json` and draft actor APIs.

### 2. Contract renderer
- Render actor metadata: name, description, slug, initial state.
- Render states and transitions from `manifest.actor.states`.
- Show input schemas and output schemas.
- Show function pipelines as executable contract paths, but do not import functions in the browser.

### 3. Runtime controls
- Show current draft actor state and context from the shared snapshot when the draft actor is ready.
- Let user select an input message available in the current state.
- Provide JSON payload editor for the selected message.
- Send message through draft actor API.
- Render validation/runtime errors from the backend.

### 4. Sync with Preview
- Subscribe to draft actor events/snapshots from A53.
- When Actor Tab sends a message, Preview updates through the same snapshot stream.
- When Preview sends a message, Actor Tab updates through the same snapshot stream.

### 5. Approval handoff
- In phase 1, show “Approve Actor” when a candidate exists.
- Approval should use deterministic approval API/service flow, not a chat prompt.
- After approval, start or reload the draft actor from generated files when possible.
