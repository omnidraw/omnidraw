# A114 - AI widgets: inspect exact draft artifact with a Preview screenshot

[Overview](../BASED.md)

Add one model-callable tool, `od_widget_preview_inspect`, that captures the
exact current filesystem draft, runs its exact Preview-signed Capsule artifact
under a deliberately isolated browser policy, performs a short declared
interaction sequence, and returns one widget-only screenshot plus compact
diagnostics and visible target geometry.

This first release is **artifact exact**, not full Preview-policy exact. It
grants no resources and denies guest network. The result states that narrowed
fidelity explicitly, so the agent cannot describe an isolated run as the same
execution authority as a user's normal Preview.

## Context

`od_widget_validate` currently validates source and can run the real host
Preview construction, but it does not mount the result in a browser. Relevant
current seams are:

- [`TWidgetPreviewBuildCheck`](../../packages/service-agent/src/tools/types.ts),
  which returns only construction success/errors;
- [`WidgetPreviewService.buildCheck`](../../apps/cli/src/services/WidgetPreviewService.ts),
  which captures and constructs a draft without mounting it;
- [`createWidgetPreviewOwner`](../../packages/ui-ai-chat/src/canvas-extension/preview-owner.ts),
  which owns the actual browser Capsule mount for a visible canvas Preview;
- [`fnToolSuccess`](../../packages/service-agent/src/tools/fn.result.ts), which
  currently emits text content only;
- [`ToolRegistry`](../../packages/service-agent/src/tools/ToolRegistry.ts), whose
  ordinary authorizer sees only `chatId` and `toolName` and therefore cannot
  approve frozen effect-bearing arguments.

The filesystem-first Preview from [A109](./A109.md) is process-owned and
ephemeral. Inspection must preserve that architecture: no durable Preview
revision, database row, canvas item, publication pointer, or recovered browser
handle.

Earlier [A103](./A103.md) described status/wait/test tools for a retired durable
Preview-controller design. Do not restore them. A114 is one bounded snapshot
tool for the current shared filesystem draft.

## Dependencies and scope

A114 starts only after these independently reviewable prerequisites pass:

- [A116](./A116.md): Capsule exposes a bounded production-supported
  authoring-inspection DTO boundary for target queries, geometry, visibility,
  canvas metadata, and structured runtime events while keeping the root closed.
- [A117](./A117.md): Omnidraw has a packaged managed browser runner and proves
  that a synthetic image tool result survives Pi, transcript/event handling,
  API projection, model delivery, and Chat rendering.

Those tasks are prerequisites, not hidden steps assigned to the A114
implementer. A114 integrates their qualified ports with exact draft capture and
the agent tool.

First-release scope:

- exact captured draft and executable-input identity;
- exact Preview-signed Capsule artifact identity;
- isolated browser execution with no resource bindings and denied guest
  network;
- one widget-only PNG screenshot;
- existing structured Capsule/runtime diagnostics with trusted `widget://`
  mapping when verified;
- bounded CSS/role/label queries;
- click, input, and frame-wait actions;
- action outcomes and compact visible target bounds;
- canvas presence, dimensions, bounds, and context kind only.

Explicitly deferred:

- selected resources or normal Preview bindings;
- full Preview-policy parity;
- startup/action effects and `ApprovalCoordinator` integration;
- console capture;
- shader/WebGL info-log instrumentation beyond existing structured runtime
  failures;
- canvas buffer emptiness or compositor-contribution classification;
- network traces, storage, source maps, DOM dumps, or a general browser
  debugging protocol.

## Fixed decisions

- `od_widget_preview_inspect` is the only new model-facing tool.
- Every call creates a fresh isolated mount. It never reads, clicks, reloads,
  replaces, or resets the user's visible Preview frame.
- “Exact” means exact source capture, construction inputs, Preview-signed bytes,
  runtime descriptor, Capsule artifact hash, build environment identity,
  viewport, and theme projection. It does **not** mean exact resource/network
  authority in this release.
- The completed result always reports:

  ```ts
  fidelity: {
    source: 'exact';
    artifact: 'exact';
    runtimePolicy: 'narrowed';
    bindings: 'none';
    network: 'denied';
    overall: 'artifact_exact';
  }
  ```

- `preview_exact` is reserved for a future mode that uses the normal Preview's
  exact bindings, effects, and network policy after frozen protected approval.
- Source maps remain process-owned. Browser runtime coordinates are accepted
  only when fenced by the exact artifact hash and runtime/lifecycle generation,
  then mapped by trusted Omnidraw code to allowlisted `widget://` locations.
- The screenshot contains only the widget viewport. It excludes Omnidraw,
  canvas, Chat, browser, runner, and diagnostic chrome.
- Screenshot bytes are an `image/png` tool-content block. They are not base64
  inside JSON or duplicated into structured details.
- DOM text and rendered pixels are untrusted widget output. No arbitrary
  JavaScript, DOM node, ShadowRoot, source map, CDP command, host selector, URL,
  or browser handle reaches the model.
- A completed union member requires both an artifact and screenshot. Failed,
  timed-out, and cancelled members carry a top-level failure code/message and
  only the partial evidence actually produced.
- Canvas output in A114 makes no `empty`, `nonEmpty`, or visual-contribution
  claim. Unknown rendering evidence is omitted instead of guessed.
- Inspection is not publication readiness and cannot Publish.

### 1. Freeze the MVP input

```ts
type TWidgetPreviewInspectTarget =
  | Readonly<{
      by: 'css';
      selector: string;
    }>
  | Readonly<{
      by: 'role';
      role:
        | 'button'
        | 'checkbox'
        | 'combobox'
        | 'link'
        | 'listbox'
        | 'menuitem'
        | 'option'
        | 'radio'
        | 'slider'
        | 'spinbutton'
        | 'switch'
        | 'tab'
        | 'textbox';
      name?: string;
      exact?: boolean;
    }>
  | Readonly<{
      by: 'label';
      text: string;
      exact?: boolean;
    }>;

type TWidgetPreviewInspectAction =
  | Readonly<{
      type: 'click';
      target: TWidgetPreviewInspectTarget;
    }>
  | Readonly<{
      type: 'input';
      target: TWidgetPreviewInspectTarget;
      value: string;
      /** Default: blur. */
      commit?: 'none' | 'blur' | 'enter';
    }>
  | Readonly<{
      type: 'waitFrames';
      count: number;
    }>;

type TWidgetPreviewInspectInput = Readonly<{
  /** Existing widget-tool semantics: mounted draft/display name. */
  name: string;
  /** Optional lowercase SHA-256 fence checked before browser execution. */
  expectedDraftDigestSha256?: string;
  viewport?: Readonly<{
    /** CSS pixels. Default 512; allowed 160..1280. */
    width?: number;
    /** CSS pixels. Default 384; allowed 120..1024. */
    height?: number;
    /** Default 1; only 1 or 2. */
    deviceScaleFactor?: 1 | 2;
  }>;
  settle?: Readonly<{
    /** Frames after ready and every action. Default 2; allowed 1..8. */
    frames?: number;
    /** Per-settle ceiling. Default 5,000; allowed 100..10,000. */
    timeoutMs?: number;
  }>;
  /** Maximum 16 actions. */
  actions?: readonly TWidgetPreviewInspectAction[];
  /** Default false; later actions become skipped after the first failure. */
  continueOnActionError?: boolean;
  /** Whole call including build. Default 120,000; max 180,000. */
  timeoutMs?: number;
}>;
```

Do not expose `effectPolicy`, resource selections, resource IDs, network rules,
or a parity switch in the MVP schema. Adding a model-controlled parity string
before frozen approvals exist would create a misleading and unsafe interface.

Validation and action semantics:

- Resolve `name` only through the current chat workspace's safe mounted draft.
  Never accept a path.
- Reject unknown keys. Bound CSS selectors to 512 UTF-8 bytes, role/label names
  to 256 bytes, input values to 4,096 bytes, actions to 16, and
  `waitFrames.count` to the integer range 1..120.
- Target actions must resolve exactly one currently visible target inside the
  inspected Capsule root. Zero/multiple matches are structured action failures.
- `click` uses a real browser pointer at revalidated geometry and fails when
  outside, occluded, disabled, stale, or no longer the same target.
- `input` rejects password/file/hidden/disabled/read-only controls. It uses
  real browser keyboard/fill behavior; `blur` moves focus, `enter` sends Enter,
  and `none` retains focus.
- Settlement is Capsule `ready()` plus the requested number of host animation
  frames. Never wait for “no DOM mutation” or “no animation.”
- Capture one final screenshot after the actions and final settlement.
- User cancellation aborts build, mount, actions, frame waits, screenshot, and
  cleanup.

Contract rules:

- A missing/unhealthy draft, authorization denial, invalid input, stale digest
  fence, unavailable prerequisite service, or corrupt host protocol is a
  structured tool error rather than a partially initialized result.
- Once exact draft capture succeeds and execution begins, build/mount/action/
  screenshot failures return the union when possible.
- `completed` means no error diagnostic and every action passed.
  `completed_with_errors` requires a screenshot but includes one or more error
  diagnostics or failed actions.
- `failure.code` is a stable product code; `failure.message` is bounded and
  safe. Do not force consumers to infer failure from the last diagnostic.
- Reuse existing `TWidgetDiagnostic` normalization/fingerprinting rules. Do not
  introduce a looser runtime-error contract.
- Return at most 100 diagnostics/64 KiB diagnostic text, 128 elements after
  scanning at most 4,096, and 16 canvases. Bound each message to 2,000
  characters and each element name/text to 512 characters. Apply the existing
  total model-data ceiling last.
- Never return HTML, arbitrary attributes, input values, password/file/hidden
  content, dataset/style text, stacks, source maps, URLs, storage, cookies,
  network details, host paths, runner details, or browser logs.
- Bound PNG bytes to 8 MiB. If exact capture exceeds the limit, return failed
  `SCREENSHOT_TOO_LARGE`; never resize, crop, lower DPR, or silently change
  format.

### 3. Reuse one exact construction authority

- Refactor the Preview/build edge so validation, normal Preview, and inspection
  share safe draft capture, executable-input hashing, construction,
  validation, and Preview signing. Do not implement a parallel Vite/Capsule
  builder in the tool or browser.
- Capture the draft once under the existing authoring operation. Compute the
  canonical draft and executable-input digests from those exact bytes.
- Check `expectedDraftDigestSha256` before browser execution. Report the safe
  observed digest in a stale-fence tool error.
- Lease a cached construction only when exact executable digest and complete
  compatibility identity match.
- Retain the verified source-map artifact only in a process-local inspection
  lease. Never send its bytes to the runner, guest, tool JSON, or model.
- Use an ephemeral identity derived from chat ID and tool-call ID. Create no
  canvas item, widget instance, durable state, diagnostic row, binding row,
  Preview revision, or publication record.
- Bind the exact resource-free server artifact and descriptors, but supply a
  gateway that rejects every resource access. Deny guest network regardless of
  the manifest's requested network group. These deliberate differences are
  represented by `fidelity`.
- Release construction/source-map leases and temporary state on every terminal
  path.

### 4. Integrate the A116 and A117 ports

- Add an injected `TWidgetPreviewInspectionCapability` to `service-agent`.
  Keep `tool.*.ts` thin; it must not import CLI, frontend, Playwright, or
  Capsule host code.
- Register the tool as the 17th exact AI Chat tool and update registry tests,
  prompt snapshots, and tool authorization coverage.
- Pass the exact signed artifact, public runtime metadata, isolated capability
  policy, viewport/theme projection, and one-time function bridge to A117.
- A117 mounts through A116 and returns bounded DTOs plus screenshot bytes. A114
  re-verifies returned artifact/generation identity before accepting any
  diagnostic or target evidence.
- Map eligible generated locations using the inspection lease's verified source
  map. Emit only normalized `widget://` paths; omit unavailable locations.
- Convert PNG bytes into one image tool-content block with only digest/size/
  dimensions in JSON details. Use the A117-qualified transport helper rather
  than extending the text-only helper ad hoc.
- Cancellation must cross the injected port and leave no browser context,
  Capsule handle, target, bridge, source map, buffer, or temp path alive.

### 5. Keep presentation and claims honest

- Teach the authoring prompt to use:
  edit → `od_widget_validate` → `od_widget_preview_inspect` → repair or finish.
- The agent may say the exact artifact rendered and the declared isolated
  interactions passed. It must not claim real Preview bindings, network, data,
  server effects, or full `preview_exact` execution.
- Render the screenshot in the Chat tool result with compact status, digest,
  fidelity, action outcomes, and truncation. Never duplicate image base64 in
  text or details.
- Preserve the user's existing **Open Preview** action. The screenshot is agent
  evidence, not a substitute for user review in the normal Preview authority.
- Update [`SCREENS.md`](../../docs/internal/screens/SCREENS.md) only if the tool
  result materially changes the documented Chat UI.

### 6. Verification

- Exact capture, digest-fence mismatch, edit-during-build rejection, and exact
  construction-cache reuse.
- Plain DOM screenshot with exact dimensions and no Omnidraw/browser chrome.
- Role/label/CSS queries; click; input with each commit mode; waitFrames;
  ordered actions; zero/multiple/occluded/disabled/stale targets; stop/continue
  behavior.
- Animated fixture proving frame-based settlement never waits for global
  quiescence.
- Build, mount, startup, callback, capability, budget, and mapped/unmapped
  runtime diagnostic cases.
- Canvas metadata for 2D, WebGL, WebGL2, WebGPU, context-lost, and unknown
  cases, with no pixel-emptiness field.
- Malicious/huge DOM text and prompt-like content remain bounded and untrusted;
  sensitive input values and forbidden host/browser fields remain absent.
- Resource access and guest network are denied, and the result always reports
  narrowed `artifact_exact` fidelity.
- Image content reaches model and Chat through A117 without JSON base64.
- Cancellation, timeout, runner crash, stale runtime generation, queue failure,
  and complete cleanup.
- One black-box `widget-debug-tools` scenario using only public agent tools.

## Acceptance criteria

- A completed call proves the exact current draft, executable input, signed
  artifact, Capsule hash, build environment, viewport, and narrowed policy.
- The result says `artifact_exact`, never `preview_exact`.
- A stale digest fence or edit race cannot produce misattributed evidence.
- The model and user receive one widget-only PNG image content block; JSON
  contains metadata only.
- CSS/role/label targets and click/input/frame actions are bounded to one exact
  visible target inside the closed inspected root and return ordered outcomes.
- Runtime diagnostics are bounded, artifact/generation fenced, and mapped to a
  trusted `widget://` location only when verified.
- Canvas output reports presence/geometry/context only and makes no pixel
  truth claim.
- The isolated guest cannot access resources or network, and the agent cannot
  request a wider policy through the MVP schema.
- Inspection creates no visible Preview mutation or durable canvas, widget,
  state, binding, diagnostic, Preview-revision, or publication authority.
- Every browser/Capsule/function/source-map/buffer/temp resource is released on
  success, failure, timeout, and cancellation.
- Full Preview parity, console/shader capture, and canvas visual classification
  remain out of scope rather than partially or misleadingly implemented.
