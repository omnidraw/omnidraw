# A89 - canvas persistence: shared Cangine contracts and JSONB canvas items
[Overview](../BASED.md)

Replace the durable Automerge canvas document with one queryable JSONB row per
authored Cangine node. This task changes contracts and persistence only.

## Scope boundary

The canvas UI, drawing tools, product policies, widgets, portals, AI chat,
selection/style controls, grid, keyboard behavior, and visual design are not
disposable persistence concerns. They must remain behaviorally and visually
equivalent while their storage adapters change.

## Plan

1. Keep `@vibecanvas/canvas-contract` dependency-light and use Cangine
   `TSceneNode` directly.
2. Store one authored node per STRICT `canvas_items` JSONB row.
3. Provide indexed generated columns for hierarchy, kind, and widget identity.
4. Keep runtime layers, portals, selections, previews, and transient UI state
   outside persistence.
5. Expose bounded tenant-scoped snapshot, query, and transactional mutation
   capabilities.

## Acceptance criteria

- Authored nodes are stored once and queried through indexed generated columns.
- One-item changes touch bounded rows and one canvas revision.
- No UI or product capability is removed merely because its old adapter used
  Automerge or the v1 projection model.
- Restored canvas and widget behavior consumes the shared contract without a
  compatibility persistence authority.
