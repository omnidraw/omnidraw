# A90 - canvas: authoritative server CanvasService
[Overview](../BASED.md)

Make CanvasService the only durable canvas authority while preserving the
existing canvas product and collaboration-visible behavior.

## Scope boundary

CanvasService owns authorization, snapshots, queries, commands, revisions, and
events. It does not own or replace canvas chrome, drawing tools, style controls,
widget frames, AI chat, gestures, accessibility, or visual design.

## Plan

1. Serialize command execution per canvas and authorize every operation.
2. Validate bounds, preconditions, hierarchy, Cangine nodes, and widget identity.
3. Commit only touched rows and exactly one canvas revision.
4. Publish exact post-commit events with bounded replay/resync.
5. Adapt the retained product runtime to this authority; do not delete product
   policy because its previous implementation called CRDT services.

- Every accepted action group produces one revision and one exact event.
- Unrelated stale fields remain editable; conflicting touched fields reject.
- The restored UI uses CanvasService without reintroducing Automerge or a
  secondary durable canvas authority.
- Product interaction and appearance match the screen atlas and retained tests.
