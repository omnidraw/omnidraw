# A62 - widgets: header three-dot menu
[Overview](../../BASED.md)

Add a Konva-rendered three-dot button to widget headers that opens a Solid/Kobalte menu positioned next to the header button in canvas viewport space.

## Context

Widget chrome is rendered in Konva while widget content is hosted in DOM portals. The header currently has traffic-light controls but no overflow menu.

- `packages/canvas/src/plugins/widget/Widget.plugin.ts`

## Plan

### 1. Draw the header menu affordance
- Add widget header menu constants.
- Add a right-aligned Konva three-dot hit target/group in `fn.create-widget-node.ts`.
- Reserve header title width for the menu button.
- Keep resize/update paths syncing title width and menu x-position.

### 2. Open a Solid/Kobalte overlay from Konva
- Prefer reusing/genericizing the existing global menu mount pattern from `ContextMenu.plugin.ts`.
- On Konva menu button click, cancel bubbling and compute a fixed viewport anchor near the button.
- Open one global menu state so opening a new menu closes the previous one.

### 3. Widget actions
- Share behavior with existing traffic-light controls where possible.
- Initial actions: minimize/restore, fullscreen/exit fullscreen, delete widget.
- Sync widget DOM portal after actions.

### 4. Click-away and cleanup
- Close on Kobalte `onOpenChange(false)`.
- Close on stage/container left mouse down, widget drag, widget removal, and runtime destroy.

## NOTES

Kobalte docs recommend `Popover` for anchored lighter overlays and `DropdownMenu` for dropdown button menu semantics. Since this is an overflow action menu, `DropdownMenu` may be semantically better, but `Popover` is acceptable if the UX needs non-menu content later.

Konva docs: shape events should use `node.on(...)`; cancel bubbling on the three-dot click to avoid host selection/drag behavior.
