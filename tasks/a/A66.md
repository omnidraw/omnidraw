# A66 - toolbar: group widget tools into hover flyouts
[Overview](../BASED.md)

Render widget tools that share the same group in one toolbar slot. The grouped slot has its own icon and opens member tool icons to the left, inward from the right-anchored toolbar.

## Context
- Toolbar implementation: [Toolbar.plugin.ts](../../packages/canvas/src/plugins/toolbar/Toolbar.plugin.ts)
- Widget config will define only the group name, not the group icon.
- Group presentation is product-owned in the toolbar-local `CONSTANTS.ts` registry.
- If a group has no registered icon, use a default group icon.
- No database table, API, or manifest field is needed for group presentation.
- The toolbar expands from one to at most three columns based on available canvas height.

## Plan
### 1. Build toolbar slot and column models
- Normalize non-empty group names and preserve registered tool order.
- Keep singleton groups as direct tools.
- Use the minimum one-to-three-column layout needed for the available canvas height.

### 2. Define grouping behavior
- Group widget tools by group name when present.
- Render ungrouped widget tools as normal toolbar slots.
- Render grouped widget tools as one toolbar slot per group.
- Use registered group icon when available; otherwise use default group icon.

### 3. Define hover flyout UX
- On hover/focus of a grouped slot, show member tool icons pulled out to the left.
- Keep activation behavior identical to direct toolbar tool activation.
- Ensure grouped flyout works with pointer movement and does not collapse before click.
- Portal flyouts into the stage container so scrollable toolbar columns do not clip them.

### 4. Validate interactions
- Verify single-item groups remain direct slots.
- Verify toolbar layout remains stable with multiple groups.
- Verify no widget config starts owning group icons.
