# B31 - binary: compiled app cannot find Turso native binding
[Overview](../BASED.md)

Compiled `vibecanvas` starts with `Cannot find native binding` because the Turso NAPI `.node` file is not available at runtime.

## Context

`bun run build:single` succeeds, but running `./dist/vibecanvas-darwin-arm64/bin/vibecanvas` fails in the compiled executable with:

```txt
error: Cannot find native binding. npm has a bug related to optional dependencies...
```

Relevant files:
- `scripts/build.ts` compiles the single-file binary and creates `dist/` packages.
- `apps/cli/src/setup-services.ts` creates `DbServiceTurso` for stateful commands/server.
- `packages/service-db/src/DbServiceTurso/DbServiceTurso.ts` imports `@tursodatabase/database`.
- `docs/external/llm.bun.md` references Bun docs for single-file executables, loaders, plugins, Node-API, and SQLite.

Observed investigation:
- `@tursodatabase/database` uses a NAPI/native platform binding.
- On darwin arm64 the required file is `turso.darwin-arm64.node` from `@tursodatabase/database-darwin-arm64`.
- `bun build --compile` bundles JS but does not make this native binding available to the compiled executable.
- Copying `turso.darwin-arm64.node` into the run working directory allows `--version` to start, confirming the missing native binding is the immediate cause.
