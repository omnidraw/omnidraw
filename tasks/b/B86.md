# B86 - ci: align the trusted Capsule build identity with 0.14.0
[Overview](../BASED.md)

Final acceptance reaches the complete product suite but rejects the trusted
widget build identity because the browser host installs Capsule `0.14.0` while
the CLI still signs and admits widget constructions as Capsule `0.13.0`.

## Context

[GitHub Actions run 31384081735](https://github.com/omnidraw/vibecanvas/actions/runs/31384081735)
failed after B85 cleared architecture boundaries. The local exact-commit final
acceptance run reproduced the hidden assertion:

```text
Expected: "0.14.0"
Received: "0.13.0"
```

Commit `c4cdc1ad` upgraded the root Capsule catalog and lockfile to `0.14.0`
but omitted `apps/cli/src/services/CONSTANTS.ts`. That constant is production
authority: it participates in widget construction, signing, cache identity,
Preview compatibility, and runtime admission, so changing only the version
string would leave a false `0.13.0` package digest attached to `0.14.0`.

The public npm `@omnidraw/capsule@0.14.0` tarball has SHA-256
`8ec771e3253c1c9e574285c34dac33003a982c9aa3b4d39f8c41f67b84ad3bed` and
the lockfile-pinned SHA-512 integrity. Capsule still exports build API `0.1.0`
and runtime build digest
`sha256:e7c239a3853ff6918c22dc5cea4246e863a89938f75fccbab0dd8e76023c775d`.

## Plan

1. Pin the trusted build identity to Capsule `0.14.0` and its exact tarball
   SHA-256 while retaining the unchanged exported runtime identity.
2. Strengthen the focused test to compare the complete identity against the
   root catalog, the documented Capsule build API export, and the pinned
   package/runtime digests.
3. Run the focused CLI test, complete product test, and final acceptance as
   needed, then push and monitor the next Linux run.
