# B38 - ai wizard: chat tab forgets selected model after tab switch
[Overview](../../BASED.md)

When switching away from the AI wizard Chat tab and back, the previously selected chat model should still be selected.

## Context

Affected area:
- [`packages/canvas/src/components/AiWizzard/`](../../packages/canvas/src/components/AiWizzard/)
- [`packages/canvas/src/components/AiWizzard/index.tsx`](../../packages/canvas/src/components/AiWizzard/index.tsx)
- [`packages/canvas/src/components/AiWizzard/tabs/ChatTab.tsx`](../../packages/canvas/src/components/AiWizzard/tabs/ChatTab.tsx)
- [`packages/canvas/src/components/AiWizzard/ChatComposer/ChatComposer.tsx`](../../packages/canvas/src/components/AiWizzard/ChatComposer/ChatComposer.tsx)

Observed behavior:
- User selects a model in the Chat tab composer.
- User navigates to another AI wizard tab, for example Actor/Tool/Preview/Settings.
- User returns to the Chat tab.
- The model selection is reset to the default/preference value, so the user must select the model again.

Current likely cause from quick inspection:
- `AiWizzard/index.tsx` renders Chat via Kobalte `Tabs.Content`.
- `ChatComposer` owns `selectedModelId` locally.
- On tab switching, Chat/Composer may unmount/remount or reset internal state.
- `AiWizzard` only calls `onAiWizardPreferenceChange` from `prompt(...)`, so changing the model without submitting a prompt is not persisted upward.
- `ChatTab.tsx` passes `defaultModel={props.aiWizardPreference?.model?.modelId ?? props.settings?.defaultModel}` and `defaultProvider={props.aiWizardPreference?.model?.provider ?? props.settings?.defaultProvider}` into `ChatComposer`, but does not receive model-selection changes from the composer.

Expected behavior:
- The last selected model is remembered as soon as the user selects it in the Chat tab.
- Returning to Chat shows that model selected.
- The user does not need to switch model again before submitting.
- Thinking level should be checked too, because it is part of the same composer preference path and may have the same reset behavior.

## Plan

1. Inspect `ChatComposer.tsx` model selection flow.
   - Find where `setSelectedModel(model)` is called.
   - Find where thinking level is changed.
   - Confirm whether tab switching unmounts the composer or whether a createEffect resets state.

2. Add an upward preference-change callback.
   - Add a callback prop to `ChatComposer`, for example `onPreferenceChange` or `onModelChange` plus `onThinkingLevelChange`.
   - When the user manually selects a model, call the callback with `{ provider, modelId }`.
   - When the user changes thinking level, call the callback with the selected thinking level.
   - Avoid firing the callback for default initialization unless intentional.

3. Thread the callback through `ChatTab.tsx`.
   - Extend `IProps` with a preference-change callback.
   - Pass it to `ChatComposer`.
   - Keep `onPrompt` unchanged, but avoid relying on prompt submission as the only time preference is saved.

4. Store the latest preference in `AiWizzard/index.tsx`.
   - Use existing `props.onAiWizardPreferenceChange` so the parent persists the preference.
   - Consider a local signal mirror so the current wizard instance updates immediately even if the parent prop update is async/delayed.
   - Keep existing prompt-time preference update for safety, but ensure model changes are saved before prompting.

5. Verify edge cases.
   - Selecting model then switching Actor/Tool/Preview/Settings and back preserves the model.
   - Selecting model, then sending prompt uses the selected model.
   - Starting a new chat should not unexpectedly reset the saved model unless product intentionally wants that.
   - If settings reload removes the selected model, composer should fall back to a valid default.
   - If no credentials/models exist, current behavior remains safe.

## NOTES

- The core bug is probably not model API persistence; it is UI state ownership. Model selection currently lives too low in the component tree and is lost when returning to the Chat tab.
- Prefer keeping the selected model in AI wizard preference state rather than forcing `ChatComposer` to survive tab unmounts.
