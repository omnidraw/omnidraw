# B50 - AI chat: keyboard navigation cannot reach or scroll long mention and slash lists
[Overview](../BASED.md)

Make long `@` mention and `/` command suggestion lists fully reachable from the keyboard while keeping the active option visible inside the AI Chat menu.

## Context

The attached screenshot shows an AI Chat resource-mention menu that is taller than the available contained-widget space. The highlighted option starts at the top, but keyboard navigation can move the internal selection below the visible clipped region without scrolling the menu.

Both mention and slash suggestions are implemented by [`ChatComposer.tsx`](../../packages/canvas/src/components/AiChat/ChatComposer/ChatComposer.tsx). The current implementation:

- derives one shared suggestion list for `@` mentions and `/` commands;
- truncates matching results with `.slice(0, 6)`, making every later match unreachable;
- handles Arrow Down/Up by changing `activeIndex` with wraparound;
- renders the active option with `aria-selected`, but does not associate it with the editor through `aria-activedescendant`;
- never scrolls the active option into view after `activeIndex` changes;
- styles the suggestion container with `overflow: hidden`, so clipped options cannot be reached by scrolling the menu itself;
- has no Page Up/Down, Home, or End navigation for long lists.

The result is two related keyboard bugs:

1. matches after the sixth result cannot be selected at all;
2. retained matches can be selected internally while the visible highlight remains outside the clipped menu viewport.

The issue applies equally to resources inserted through `@` and commands inserted through `/`, even if the current slash-command set is usually short.

## Fixed behavior

### Reachable results

- Do not silently discard valid matches at six. Every filtered mention and slash-command match must be keyboard-reachable.
- Keep rendering bounded through a scrollable viewport rather than by deleting results from the suggestion model.
- Filtering remains case-insensitive and preserves the source order unless a separate ranking task intentionally changes it.
- When the query or source list changes, reset or clamp the active index before rendering so it always identifies an existing option.

### Keyboard contract

While a non-empty suggestion menu is open and the composer editor owns interaction:

- Arrow Down selects the next option.
- Arrow Up selects the previous option.
- Page Down advances by one visible menu page while preserving a valid option.
- Page Up moves back by one visible menu page.
- Home selects the first option.
- End selects the final option.
- Enter and Tab accept the active option using the existing behavior.
- Escape dismisses the menu using the existing behavior.
- Navigation keys prevent their browser defaults so Page Up/Down and Home/End do not scroll the document, chat history, or canvas.
- Arrow wraparound may remain: moving past the final option selects the first and scrolls to the top; moving before the first selects the final option and scrolls to the bottom.

Keep DOM focus in the ProseMirror editor throughout navigation. Do not move focus into each option button, because typing must continue filtering the same trigger.

### Scroll behavior

- Give the suggestion list a bounded height based on the available AI Chat panel space and enable vertical overflow.
- Whenever keyboard navigation changes the active option, minimally adjust only the suggestion menu's `scrollTop` so the complete active row is visible.
- Do not use scrolling behavior that can move the chat history, containing widget, browser document, or canvas camera.
- A newly opened or newly filtered menu starts with the first option visible.
- Wraparound, Home, and End scroll directly to the relevant boundary.
- Pointer/wheel scrolling remains usable and must not leak into canvas pan/zoom while the menu can consume the gesture.
- The menu must remain usable in a small contained AI Chat widget, a resized widget, and fullscreen mode.

### Accessibility

- Give every rendered option a stable ID for the lifetime of that suggestion result.
- Set the editor/composer combobox relationship to the open listbox and expose the active option through `aria-activedescendant`.
- Preserve `role="listbox"`, `role="option"`, and `aria-selected` semantics.
- Announced selection and visible selection must always refer to the same item.
- Pointer selection and keyboard selection must continue accepting the exact displayed item.

## Plan

### 1. Add a deterministic long-list reproduction

- Render AI Chat with more than six mentions and more commands than fit in a constrained menu viewport.
- Open `@` and `/` suggestions from the editor and record initial active option, visible rows, scroll position, and focus owner.
- Reproduce both failures: the seventh match is absent, and Arrow Down moves the active index beyond the visible region without changing menu scroll.
- Cover the short-height layout shown in the screenshot rather than testing only an unconstrained jsdom container.

### 2. Separate result availability from viewport size

- Remove the six-result truncation from the filtered suggestion model.
- Keep the list bounded visually with a maximum block size and `overflow-y: auto`/equivalent.
- Add containment needed to prevent wheel/overscroll gestures from reaching the canvas beneath the widget.
- Ensure menu geometry responds to contained/fullscreen height changes without covering inaccessible controls or escaping the AI Chat panel.

### 3. Implement complete keyboard navigation

- Extend the shared suggestion key handler with Page Up/Down, Home, and End.
- Compute page movement from the number of fully visible rows, with a minimum movement of one, instead of hard-coding a device-specific pixel distance.
- Preserve Arrow wraparound and existing Enter/Tab/Escape behavior.
- Reset/clamp selection when trigger kind, query, mention source, command source, or result count changes.
- Consume handled keys at both the ProseMirror and document-capture paths exactly once.

### 4. Synchronize active option and menu scroll

- Retain a reference to the menu and stable references/IDs for option elements.
- After active selection or menu geometry changes, calculate the active row against the menu viewport and apply the smallest menu-local scroll adjustment.
- Avoid a broad `scrollIntoView` call unless it is proven not to scroll ancestors; prefer explicit menu-local scroll math.
- Handle first open, filtering, Page Up/Down, Home/End, Arrow wraparound, widget resize, and mouse selection consistently.
- Preserve editor focus and caret/trigger state while scrolling.

### 5. Complete listbox accessibility

- Connect the focused editor/composer to the suggestion listbox and active option.
- Keep active IDs stable across a render and replace them when the result identity changes.
- Ensure empty results remove stale `aria-activedescendant`/expanded relationships.
- Verify selection announcements for both mention labels/kinds and command labels/descriptions.

### 6. Add regressions and browser QA

- Test Arrow Down/Up visibility through every row and both wrap boundaries.
- Test Page Down/Up, Home, End, Enter, Tab, and Escape for both trigger kinds.
- Test that a result after index five can be selected and inserts the correct mention/command.
- Test filtering a scrolled list down to fewer results and replacing its source while open.
- Test editor focus/caret retention, active descendant, visible highlight, and matching `aria-selected` state.
- Test that menu navigation does not change document, chat-history, widget, or canvas scroll/camera state.
- Browser-QA a short contained widget like the screenshot, multiple resized heights, fullscreen AI Chat, pointer wheel, and keyboard-only operation.
- If S88 lands first, move these tests and fixes to the extracted AI Chat package rather than modifying obsolete canvas paths.

## Acceptance criteria

- Every matching `@` mention and `/` command is reachable without a mouse, including matches after the former six-item cutoff.
- Arrow Down/Up always keeps the active option fully visible in the suggestion viewport.
- Page Down/Up, Home, and End navigate and scroll predictably.
- Enter and Tab accept the same option that is visibly active and announced to assistive technology.
- Keyboard navigation keeps focus and typing authority in the composer editor.
- The suggestion viewport scrolls independently without moving the chat history, widget, document, or canvas camera.
- Filtering/source changes cannot leave an out-of-range, invisible, or stale active option.
- Behavior is shared and verified for mention and slash suggestions in contained, resized, and fullscreen AI Chat layouts.
