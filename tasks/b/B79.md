# B79 - Preview goes white and rebuilds slowly after server restart
[Overview](../BASED.md)

Restarting the server makes a widget Preview frame go empty white, then the
widget reappears only after a slow full rebuild, even though the widget was
already built.

## Context

Preview is process-owned: the signed Capsule bytes, the construction cache
(`EphemeralPreviewService.#constructionCache` in
`packages/service-agent/src/widget-filesystem/preview/index.ts`), and the npm
warm workspace (`apps/cli/src/services/WidgetNpmDistributionBuild.ts`) are all
in-memory and die with the server. After a restart `preview.open` re-runs the
whole pipeline: `npm ci` + `vite build` + Capsule construction + signing. That
is the "takes time".

On restart the catalog generation resets, so the browser's catalog event stream
emits a `fullResync`; B78's `refreshAllPreviews()` then calls `owner.refresh()`
→ `preview.open`. While the rebuild runs, `preview-owner.refresh()` clears the
host to "Building Preview…" and `CapsuleWidgetHostCoordinator.#ensureHost`
sees the generation change and calls `#destroyHost(..., true)`, destroying the
still-mounted old handle → the white flash.

The docs (`docs/internal/llm.widget-system.md`) say a frame that outlived its
host shows **Preview stopped — build again.** — but the accepted direction is
fast auto-recover: reuse the previous build and keep the old widget visible
until the new artifact is ready.

## Plan

### 1. Persist validated preview constructions across restarts

- Add a bounded disk cache under the widget temp root keyed by the exact
  `executableInputDigestSha256 + fnPreviewConstructionCompatibilityKey`
  pair, storing the signed Capsule bytes, runtime descriptor, browser function
  descriptors, and browser manifest.
- On `preview.open`, check the disk cache first; on an exact key match return
  the stored mount without re-running npm/vite/Capsule/sign.
- Wire the cache into `apps/cli/src/services/WidgetPreviewService.ts` and
  `apps/cli/src/setup-services.ts`.

### 2. Keep the old widget visible while refreshing

- In `preview-owner.refresh()`, do not clear the host or destroy the old handle
  up front. Run `preview.open` first (now fast); skip the remount entirely when
  the artifact digest is unchanged; only tear down and remount on a real change.
- Gate `#destroyHost` in `CapsuleWidgetHostCoordinator.#ensureHost` so a catalog
  generation change alone does not destroy the currently-mounted handle before
  the replacement is ready.

### 3. Verify

- Typecheck/tests: ui-ai-chat (vitest), service-agent, canvas-contract,
  frontend build.
- Manual: place a Preview, restart the server, confirm the widget stays visible
  and recovers quickly; confirm a real source edit still rebuilds.
- Add regression tests for the cache-reuse and digest-skip paths.
