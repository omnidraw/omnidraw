# B74 - Preview: keep generated SDK and Capsule bridge versions aligned
[Overview](../BASED.md)

Generated widget builds can pass construction but fail immediately at runtime
when their injected Capsule guest bridge comes from a different release than
the browser host.

## Context

The distribution builder injects a lifecycle bootstrap that imports
`@omnidraw/capsule/guest` from the widget install. A scaffold using public SDK
`0.5.0` with Capsule `0.10.2` therefore bundles the 0.10 bridge even while the
local host runs Capsule `0.11.0`. Mount verification succeeds, but the first
host delivery is rejected and Preview reports `BRIDGE_DELIVERY_FAILED`.

The standalone manifest boundary must resolve the workspace SDK's `catalog:`
dependency without falling back to an older, incompatible public pair. Local
development can supply the current staged SDK and external Capsule through the
existing Verdaccio registry. Release builds continue to consume exact registry
versions from staged package manifests and must only ship once that dependency
closure is public.

## Plan

### 1. Preserve one runtime dependency closure

- Generate widget manifests with the current SDK package version.
- Resolve the SDK Capsule catalog entry to the root's exact host version.
- Keep all generated dependency specifiers registry-compatible.

### 2. Make local development install that closure

- Route widget npm installs through the local scoped registry config in dev.
- Keep packaged CLI installs on the public npm registry config.
- Build and idempotently publish every unpublished version in the staged SDK's
  versioned workspace dependency closure before starting dev. Verdaccio keeps
  npmjs as the fallback for exact versions already available publicly.
- Keep public package staging responsible for replacing workspace protocols.

### 3. Verify the original failure path

- Assert generated constants match the workspace SDK and host Capsule.
- Run CLI and service-agent tests and typechecks.
- Rebuild the Breakout draft with the widget debug lab and confirm Preview no
  longer emits `BRIDGE_DELIVERY_FAILED`.
