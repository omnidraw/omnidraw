# B105 - Widget Preview: React select initialization blanks the Capsule guest
[Overview](../BASED.md)

Opening a conditionally rendered form with a controlled React `<select>`
removed the entire widget DOM inside Capsule, leaving an accepted Preview as a
blank white frame.

## Context

The Task Manager draft reproduces this after clicking **New task**. The Canvas
`widget-frame`, portal, mount target, and `<capsule-instance>` remain mounted,
but Capsule exposes no guest elements or runtime diagnostic after React commits
the form. The exact accepted artifact fails in both `widget inspect
--mode artifact` and resource-bound `--mode preview`; unrelated React state
updates remain healthy.

![Task Manager Preview after opening New task](B105.png)

Relevant ownership:

- `.omnidraw/widgets/drafts/task-manager/ui/main.tsx` supplies the reproducer.
- `@omnidraw/capsule` owns the isolated DOM and form-element compatibility
  boundary.
- `packages/sdk/src/internal/browser-host.ts` integrates Capsule and diagnostics.
- `apps/backend` Preview inspection plus the widget CLI provide exact-runtime
  regression and verification coverage.

## Plan

1. Add a failing deterministic regression that conditionally mounts the full
   Task Manager-shaped form through the real Capsule production host.
2. Correct the owning Capsule select behavior and update the exact
   Omnidraw Capsule dependency/build identity as needed.
3. Run focused tests, package checks, and the browser Preview regression.
4. Rebuild/restart the running application and validate/inspect the real Task
   Manager draft through the widget CLI.
