# B53 - widget publish: duplicate actor identity hides new resource slots
[Overview](../BASED.md)

Publishing an actor widget must load the canonical slug installation when a legacy folder declares the same actor name and slug.

## Context

The Todo Actor System draft declares a required read/write KV slot named `todos`, but the installed widget directory also contains a legacy `sdk-test` manifest with the same `Todo Actor System` name and `todo-actor-system` slug. [B51](B51.md) made database synchronization match moved manifests by path, slug, or name, but definition discovery still collapses candidates into a name-keyed map using filesystem order. When `sdk-test` is read last, publication validates the `todos` binding against the resource-less legacy manifest and fails with `RESOURCE_SLOT_UNKNOWN`.

Relevant files:

- `packages/service-actor/src/ActorSupervisor.ts`
- `packages/service-actor/src/core/fn.select-actor-definitions.ts`
- `packages/service-actor/src/core/fx.vibecanvas-actors.ts`
- `packages/service-actor/src/core/tx.actor-definitions.ts`
- `packages/service-actor/tests/ActorSupervisor.test.ts`

## Plan

![Publish error: Todo Actor System has no todos resource slot](B53.png)

1. Add a regression fixture with simultaneous canonical and legacy manifests sharing the same actor identity.
2. Move deterministic candidate selection into a pure function.
3. Prefer the manifest whose parent directory matches its slug and report ignored duplicates.
4. Exclude unresolved duplicate identities rather than silently choosing by filesystem order.
5. Verify actor tests, type checking, functional-core lint, and repository formatting checks.

## NOTES

- The persisted `kvstore` resource is ready; binding insertion is never reached because the wrong in-memory definition is selected first.
- A lone moved manifest remains valid even when its directory does not match its slug, preserving B51 behavior.
- Canonical selection is based on the manifest parent directory matching its declared slug, independent of filesystem enumeration order.
- Duplicate names without exactly one canonical candidate are excluded from the runtime map and surfaced as an error notification.
