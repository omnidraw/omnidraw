# B117 - CI: AI Chat preference acceptance clicks a hidden composer after durable updates
[Overview](../BASED.md)

The hosted Linux browser acceptance repeatedly times out after persisting an AI
Chat model because it immediately reuses a composer control that can be hidden
while the Canvas-authored widget state settles. Re-establish the chat view at
each durable preference boundary before the next interaction.

## Context

The failure occurs in
[`live-app.acceptance.ts`](../../tests/browser/live-app.acceptance.ts) after the
model-selection `canvas.execute` request has succeeded. Playwright resolves the
model button but reports it as invisible for the full 30-second click timeout.
The immediately preceding Bun 1.3.14 run failed at the same line as the Bun
1.4.0 run, so this is an existing browser-acceptance synchronization bug rather
than a Bun upgrade regression.

[`index.tsx`](../../packages/component-ai-chat/src/chat/components/index.tsx)
keeps chat and settings as separate views, and
[`showChatComposer`](../../tests/browser/live-app.acceptance.ts) is already the
acceptance helper that restores the chat view when the composer is hidden. The
test currently calls it only at scenario entry and after reload, not between
durable Canvas updates.

GitHub run 32466045377 captured no screenshot or trace; its artifact uploads
test source files. The actionable evidence is the Playwright call log and the
identical failure in parent run 32431983259.

## Plan

1. After each durable model/thinking update, re-establish the visible chat view
   before interacting with the next composer control.
2. Keep RPC assertions authoritative; do not replace them with sleeps or force
   clicks.
3. Run the live browser acceptance under Bun 1.4.0, push, and monitor hosted CI.
