# B91 - AI widget creation: local registry sync resolves a missing backend script

[Overview](../BASED.md)

Creating any new widget in local development fails with
`WIDGET_CREATE_FAILED` because the live backend gives the registry sync service
`apps/backend` as its repository root. The service consequently executes the
nonexistent `apps/backend/scripts/local-registry.mjs` instead of the tracked
root-level `scripts/local-registry.mjs`.

## Report

Reported and independently reproduced on 2026-08-13. A plain-DOM creation such
as:

```ts
od_widget_create({
  name: 'Pomodoro',
  description: 'A compact Pomodoro timer for focused work and restorative breaks.',
});
```

fails during local package synchronization with:

```text
WIDGET_CREATE_FAILED

Local widget package synchronization failed: Command failed:
node <repository>/apps/backend/scripts/local-registry.mjs publish-widget-packages

Error: Cannot find module '<repository>/apps/backend/scripts/local-registry.mjs'
```

The same Node error block appears twice in the returned tool message. No draft
is promoted into the shared draft catalog.

Impact is limited to local development mode, but within that mode the failure
blocks every new plain and React widget because both paths prepare the same npm
dependencies before installation and validation. Production mode does not
construct the local registry synchronizer.

## Confirmed cause

`layerLiveMechanics` enables local registry synchronization when `config.dev`
is true and `NODE_ENV` is not `production`. It constructs
`LocalWidgetPackageRegistrySync` with:

```ts
repositoryRoot: resolve(import.meta.dir, '..', '..', '..')
```

The owning file is under `apps/backend/src/shell/runtime`, so three parent
traversals resolve to `apps/backend`, not the repository root. The sync service
then appends `scripts/local-registry.mjs`, producing the exact missing path in
the report. The real script remains tracked at
[`scripts/local-registry.mjs`](../../scripts/local-registry.mjs).

Relevant boundaries:

- [`apps/backend/src/shell/runtime/layer.live-mechanics.ts`](../../apps/backend/src/shell/runtime/layer.live-mechanics.ts)
- [`apps/backend/src/shell/widget/LocalWidgetPackageRegistrySync.ts`](../../apps/backend/src/shell/widget/LocalWidgetPackageRegistrySync.ts)
- [`apps/backend/src/shell/agent/tools/tool.widget-workspace.ts`](../../apps/backend/src/shell/agent/tools/tool.widget-workspace.ts)
- [`apps/backend/src/shell/agent/workspace/WidgetWorkspace.ts`](../../apps/backend/src/shell/agent/workspace/WidgetWorkspace.ts)
- [`apps/backend/tests/LocalWidgetPackageRegistrySync.test.ts`](../../apps/backend/tests/LocalWidgetPackageRegistrySync.test.ts)
- related lazy-publication design: [`D9`](../d/D9.md)

The duplicated diagnostic has a separate confirmed cause. Node's `execFile`
error message already includes the child stderr, while the wrapper builds its
message from `error.message` and appends the captured stderr again.

Existing unit coverage does not catch the composition error. It injects
`repositoryRoot: '/workspace'` directly and proves only that the synchronizer
appends the correct relative script path to an already-correct root. Both
tests pass while the live root calculation is broken.

## Plan

### 1. Make repository-root ownership explicit

Supply the actual development repository root at the backend composition edge
instead of relying on a stale parent-depth assumption inside live mechanics.
Keep this as an explicit shell handle; do not fall back to `process.cwd()` or
silently search arbitrary parent directories.

Before spawning the registry command, validate the resolved script path and
return one focused development-configuration error containing the resolved
path and remediation when it is unavailable.

### 2. Preserve atomic draft creation

Keep synchronization inside the temporary scaffold phase. A failure must
continue to remove the transient directory and must not promote or mount a
partial draft. Do not move eager registry publication back into general dev
startup; D9 intentionally made this work lazy.

### 3. Normalize process diagnostics

Report the attempted command, exit/error summary, stdout, and stderr once.
Avoid combining an `execFile` error message that already embeds stderr with a
second raw stderr copy.

### 4. Add composition-level regression coverage

Test the live development composition, not only an injected synchronizer:

1. the configured repository root resolves the tracked root registry script;
2. the command is `node <root>/scripts/local-registry.mjs publish-widget-packages`;
3. one widget-create flow reaches dependency installation and promotes the
   validated draft when synchronization succeeds;
4. a missing sync script yields one concise error and leaves no catalog draft,
   mount, or transient directory; and
5. production/non-dev composition does not require or invoke the local script.

## Acceptance criteria

- A new plain or React widget can be created from a normal clean development checkout.
- Local synchronization invokes the tracked root-level `scripts/local-registry.mjs`.
- No live path references `apps/backend/scripts/local-registry.mjs`.
- A missing or invalid registry script produces one concise, actionable error.
- Failed synchronization leaves no promoted draft, chat mount, or transient scaffold.
- Successful creation still installs dependencies, validates, promotes, mounts, and performs the initial build.
- Registry publication remains lazy and production mode remains independent of the development registry script.
- A regression test fails if the live composition resolves the backend directory as the repository root again.

## NOTES

- No mockup is useful. This is a backend composition/path-resolution defect
  with no intended visual change.
- The originally reported `omnidraw-oss` checkout was no longer present during
  validation. The current repository independently reproduced the same
  computed path, `MODULE_NOT_FOUND` failure, and duplicated diagnostic.
- Scaffolding begins in a temporary directory before synchronization, so
  "failure before draft creation" is externally accurate: the temporary
  scaffold is cleaned and never becomes catalog authority.
