# B52 - ci: build generated SDK before package tests
[Overview](../BASED.md)

Make clean-checkout tests build the browser SDK artifact before Vitest imports widget sandbox code.

## Context

Widget sandbox modules import `packages/sdk/dist/widget.js?raw` because the sandbox needs compiled browser JavaScript as source text. The SDK `dist` directory is generated and ignored, so local tests passed only when an earlier build had left the artifact behind. Clean CI checkouts failed during Vite import analysis before the affected test files could run.

## Plan

- Build `@vibecanvas/sdk` before the root package-test fanout.
- Verify the SDK build and root test command.

## TODOS

- [x] Make the root test script build the SDK first.
- [x] Verify the clean-artifact failure mode is removed.
- [x] Run the root test suite.

## NOTES

The SDK build is deliberately sequential. Adding its test script to the parallel fanout would race consumers importing `dist/widget.js`.

### LOGS

- Traced the CI failure to the ignored `packages/sdk/dist/widget.js` artifact.
- Confirmed the repository build already generates the artifact through `@vibecanvas/sdk build`, while the root test path did not.
- Added the SDK build as the root `pretest` phase, keeping it sequential before the package fanout.
- Ran `bun run test`; the SDK build passed before the package fanout. The local run later stopped on four unrelated CLI tests because this sandbox cannot bind `Bun.serve({ port: 0 })` (`EADDRINUSE`).
- Ran the widget sandbox import path through `tx.attach-dom-portal.test.ts`: 1 file and 7 tests passed.
