# B64 - widgets: restore direct drag placement after Cangine cutover
[Overview](../BASED.md)

Restore published-widget pointer placement through the Cangine canvas adapter
and show the explicit **Add to canvas** action only while a canvas is active.

## Context

The sidebar still starts placement through
[`WidgetPlacementCoordinator.ts`](../../packages/ui-ai-chat/src/widget-placement/WidgetPlacementCoordinator.ts),
but the Cangine canvas extension replaced `beginPointerSession()` with a stub
that always returned `false`. The center-add path remained implemented, which
made the compact `+` action work while drag placement silently did nothing.

Relevant files:

- [`packages/ui-ai-chat/src/canvas-extension/index.ts`](../../packages/ui-ai-chat/src/canvas-extension/index.ts)
- [`packages/ui-ai-chat/src/widget-placement/`](../../packages/ui-ai-chat/src/widget-placement/)
- [`packages/ui-ai-chat/src/sidebar/widgets/components/WidgetsSidebarSection.tsx`](../../packages/ui-ai-chat/src/sidebar/widgets/components/WidgetsSidebarSection.tsx)
- [`docs/internal/screens/assets/17-canvas-widget-placement.webp`](../../docs/internal/screens/assets/17-canvas-widget-placement.webp)

## Plan

1. Reintroduce a canvas-owned pointer session using Cangine camera conversion
   and transient widget-frame previews.
2. Commit the dropped widget through the same published placement boundary as
   the keyboard action.
3. Publish active-canvas availability through the placement coordinator.
4. Replace the compact `+` with **Add to canvas** and hide it when no canvas is
   active.
5. Cover coordinate clamping, pointer completion/cancellation, coordinator
   availability, and sidebar behavior.

No new mockup is needed: the screen atlas already documents direct widget
placement, and this change restores that interaction while making its fallback
label explicit.
