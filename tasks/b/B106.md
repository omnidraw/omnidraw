# B106 - Widget Preview: integrate Capsule guest-reported error diagnostics

[Overview](../BASED.md)

Integrate Capsule's bounded guest-reported-error event into Omnidraw after the
Capsule change is released. Preview must turn that event into a durable,
non-destructive explanation without exposing guest-controlled error content.

## Context

B105 fixed the concrete missing `HTMLSelectElement.options` compatibility gap,
but exposed a broader observability hole. Capsule already reports exceptions
that escape guest module, callback, or job execution. It does not currently
report failures caught internally by React or another framework because its
guest `console.error` is a no-op.

Omnidraw's SDK already maps Capsule mount error events into bounded widget-host
diagnostics. The Canvas Preview currently presents only fatal diagnostics;
nonfatal guest diagnostics do not produce a durable in-frame explanation.

Relevant ownership:

- `packages/sdk/src/internal/browser-host.ts` maps Capsule diagnostics.
- `apps/frontend/src/shell/framework/feature/canvas-extension/index.ts` owns
  the visible Preview failure presentation.
- `apps/frontend/src/shell/framework/feature/canvas-extension/widget-fatal-lifecycle.ts`
  owns fatal mount retirement.
- `apps/frontend/src/shell/inspection/main.ts` and the widget CLI expose
  diagnostic-clone evidence.

## Plan

1. Upgrade to the released Capsule version that emits a bounded,
   message-free, nonfatal guest-reported-error event.
2. Map the new event to a stable Omnidraw widget-host diagnostic without
   forwarding guest-controlled text, arguments, stacks, or host details.
3. In Preview mode, show a persistent, non-destructive in-frame explanation
   for the nonfatal event while leaving the mount available for inspection.
4. Preserve the current fatal behavior: quarantine, dispose, and replace the
   mount with the existing Preview failure surface.
5. Carry the diagnostic through artifact and manifest-bound Preview
   inspection, then verify the running application with the widget CLI.

## NOTES

- Capsule `0.16.0` supplies the bounded guest-reported-error event. Omnidraw
  consumes that exact event; it does not use an empty-DOM heuristic because a
  widget is allowed to render no elements.
- Do not treat every guest-reported error as fatal. Framework warnings and
  authored `console.error` calls are guest-controlled and may be recoverable.
- Published-widget presentation is a separate product-policy decision. This
  task's required visible surface is the authoring Preview.
- Reuse the existing Preview failure visual language; a new mockup is not
  required unless implementation introduces a new interaction model.
