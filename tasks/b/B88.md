# B88 - ci: configure the Chromium sandbox for Preview inspection
[Overview](../BASED.md)

The real Preview inspection runner finds the pinned Chromium executable but
cannot launch it on the Ubuntu runner because the product deliberately enables
Chromium's full process sandbox and CI has not installed the bundled sandbox
helper with its required ownership and mode.

## Context

[GitHub Actions run 31385811558](https://github.com/omnidraw/vibecanvas/actions/runs/31385811558)
confirmed B87 by passing the packed canvas browser consumer. The next host
suite failed in `preview-inspection-runner.test.ts` with
`BROWSER_LAUNCH_FAILED` from the production `PreviewInspectionBrowserService`.

`fnPreviewInspectionChromiumLaunchOptions` sets `chromiumSandbox: true` because
Preview executes untrusted widget artifacts. Disabling that option to make CI
green would weaken a product security boundary. Chromium's documented setup
for raw Linux builds instead requires the bundled `chrome_sandbox` helper to
be root-owned, mode `4755`, and selected through `CHROME_DEVEL_SANDBOX`.

## Plan

1. Resolve the executable from the exact lockfile-installed Playwright runtime.
2. Configure its sibling `chrome_sandbox` as the CI runner's setuid helper and
   export the path for all later acceptance processes.
3. Extend the workflow architecture guard, verify locally, then push and
   monitor the next Linux run.
