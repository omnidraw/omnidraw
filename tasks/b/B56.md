# B56 - canvas input: synthesize click and double-click from valid pointer sequences
[Overview](../BASED.md)

Emit semantic click and double-click events only after a complete, stationary
pointer interaction instead of treating every primary pointer-up as a click.

## Context

- `EventListener.plugin.ts` currently emits a click for a primary pointer-up
  over an element without requiring a matching pointer-down.
- The current double-click test synthesizes two pointer-up events, so it
  preserves the incorrect behavior rather than protecting browser-like input
  semantics.
- A drag, capture cancellation, mismatched pointer, or displaced release can
  therefore trigger selection, text editing, or another click action after the
  gesture has already done different work.

## Plan

```mermaid
stateDiagram-v2
  [*] --> Pressed: primary pointer-down
  Pressed --> Cancelled: cancel / drag / excessive movement
  Pressed --> Click: matching stationary pointer-up
  Click --> DoubleClick: second valid click in threshold
  Cancelled --> [*]
  Click --> [*]
  DoubleClick --> [*]
```

1. Track the minimum pointer identity, button, target, time, and movement state
   needed to validate a click candidate.
2. Invalidate the candidate when capture, cancellation, dragging, or movement
   makes a click impossible.
3. Build double-click recognition from two valid clicks, retaining the current
   semantic target policy.
4. Cover mouse, touch, and pen sequences without duplicating interaction state
   already owned by the input plugin.

## Acceptance criteria

- Pointer-up without a qualifying pointer-down emits no click.
- A drag, cancelled capture, or release outside the accepted target/movement
  policy emits no click.
- Double-click is emitted only after two independently valid clicks.
- Existing selection and text-edit entry behavior remains correct for ordinary
  mouse, touch, and pen interactions.

## NOTES

- Keep click recognition at the semantic input boundary; tools should not each
  reconstruct raw pointer sequences.
- Thresholds must be explicit constants with deterministic tests.
