# B77 - widget Preview never renders: template config reads missing omnidraw.json and validator rejects widget-preview frames
[Overview](../BASED.md)

Creating a widget from the `react` or `plain` template never renders a Preview.
The build pipeline fails at vite config load with
`ENOENT .../omnidraw.json`, so `od_widget_validate` reports
`WIDGET_COMMAND_FAILED` and the Preview frame shows no content.

## Context

The build tree is staged without the authored presentation manifest. The
filesystem workspace deliberately strips `omnidraw.json` from the build input
(`captureDraftBuildInput` in
`packages/service-agent/src/widget-filesystem/workspace/NodeWidgetFilesystemWorkspace.ts`)
and injects only the executable projection as `.omnidraw/build-manifest.json`
(`WidgetFilesystemBuildService`). The design doc states the contract:

> The full presentation-bearing manifest is not copied into the build tree.
> Omnidraw writes a generated `.omnidraw/build-manifest.json` containing only
> the executable fields. Build scripts run in that staged tree.

But both scaffolded `vite.config.mjs` templates read `./omnidraw.json`:

- `packages/service-agent/src/tools/templates/react/vite.config.mjs.tpl`
- `packages/service-agent/src/tools/templates/plain/vite.config.mjs.tpl`

The real Preview/validate/publish build runs `npm run build` inside the staged
scratch workspace (`.omnidraw/temp/widget-builds/npm-workspace-*`), which has
`vite.config.mjs`, `package.json`, `ui/`, and `.omnidraw/build-manifest.json`
but no `omnidraw.json`. The config fails to load, so the build fails before a
single module is produced and the preview never renders.

The confusion is that `npm run build` succeeds when run manually inside the
draft folder, because `omnidraw.json` exists there; only the staged workspace
differs. No test catches this because the real-Capsule integration test mocks
`distributionBuild`, so vite never runs.

## Plan

### 1. Fix the templates

- Point both `vite.config.mjs.tpl` files at the injected executable projection:
  `readFileSync(new URL("./.omnidraw/build-manifest.json", import.meta.url))`.
- The projection contains `schemaVersion`, `ui` (with `entry`), `server`, and
  `resources`, which is exactly the fields the config reads (`manifest.ui.entry`).

### 2. Fix already-created drafts

- Update the stale `vite.config.mjs` in existing template-created drafts so
  their Preview/validate passes immediately.

### 3. Guard against regression

- Add a test asserting the scaffolded vite config reads the staged
  `.omnidraw/build-manifest.json` and not the excluded `omnidraw.json`.

### 4. Verify

- Reproduce the original path: `od_widget_validate`/Preview on a fresh
  template draft must build and render.
- Run service-agent typecheck and tests.

## NOTES

- The executable projection JSON is exactly:
  `{"schemaVersion":1,"ui":{...},"server":null,"resources":[]}` (observed in a
  leftover staged `npm-workspace-*/.omnidraw/build-manifest.json`).
- vite's config-load step resolves `./` relative to the workspace root (the
  observed failed path was `[widget-workspace]/omnidraw.json`), so
  `./.omnidraw/build-manifest.json` resolves correctly.
- A second, independent blocker surfaced once the build passed: preview frame
  placement was rejected by the server. `TCanvasWidgetExtensionV1` gained a
  `widget-preview` variant (bd691539 S138) but `validateWidgetExtension` in
  `packages/canvas-contract/src/validation.ts` never handled it, so the
  extension fell through to `WIDGET_EXTENSION_TYPE` and
  `CanvasService` threw `INVALID_COMMAND`. Reproduced headlessly via
  `fnValidateCanvasItems` on a `widget-preview` frame, and verified the draft
  catalog entry is healthy (so `open` was not failing on `WIDGET_DRAFT_MISSING`).
- No mockup is useful for these build/validation contract bugs.
