# B112 - widget Config: replace split icon fields with one visual picker
[Overview](../BASED.md)

The draft Config exposes icon storage details as separate **Icon type** and
**Icon value** fields. Replace them with one visual Lucide picker and reveal a
custom-value textarea only when **Custom SVG or emoji** is selected.

## Context

The current draft Config in
[`WidgetDetailPage.tsx`](../../apps/frontend/src/shell/framework/feature/sidebar/widgets/WidgetDetailPage.tsx)
renders a native type selector beside a generic one-line value input. Choosing
Lucide still requires the author to know and type an exact icon key, and the UI
does not preview the selected glyph.

The repository already contains an unused
[`ToolIconPicker`](../../apps/frontend/src/shell/framework/feature/sidebar/ToolIconPicker/ToolIconPicker.tsx)
that is close to the desired interaction: it lists Lucide glyphs, supports
filtering, and conditionally shows a custom textarea. Do not wire it in
unchanged:

- its dropdown/listbox behavior is hand-built instead of using Kobalte's
  keyboard, focus, dismissal, and ARIA behavior;
- its styles were global rather than using the now-current local
  [`ToolIconPicker.module.css`](../../apps/frontend/src/shell/framework/feature/sidebar/ToolIconPicker/ToolIconPicker.module.css);
- `normalizeCustomToolIcon` silently truncates non-SVG text to the first
  grapheme and sanitizes SVG before persistence, so the saved source may differ
  from what the author pasted;
- selecting custom while its value is empty can leave the parent value on the
  previous Lucide icon.

Use the component guidance in
[`llm.kobalte.md`](../../docs/external/llm.kobalte.md) and the visual rules in
[`llm.style-guide.md`](../../docs/internal/llm.style-guide.md). There are 1,992
supported `lucide-static` keys, so this is a searchable local collection:
Kobalte `Combobox` is a better fit than an unfiltered native `select`. Render
its content in a portal and include the hidden select expected by Kobalte.

The serialized contract remains owned by `@omnidraw/sdk`:

- `null` means no authored icon;
- `{ lucidIcon: "Camera" }` selects one known Lucide key (the public field is
  intentionally spelled `lucidIcon` and must not be renamed);
- `{ svgIcon: "…" }` contains either one trimmed grapheme or one accepted SVG
  element, at most 16 KiB.

See
[`contracts/tool-icon.ts`](../../packages/sdk/src/contracts/tool-icon.ts),
[`fn.filesystem-path.ts`](../../packages/sdk/src/contracts/core/fn.filesystem-path.ts),
and [`schema.ts`](../../packages/sdk/src/contracts/schema.ts). The backend
already validates the exact contract during digest-fenced Config save, and
[`WidgetIcon.tsx`](../../apps/frontend/src/shell/framework/feature/sidebar/widgets/components/WidgetIcon.tsx)
already renders Lucide and custom SVG values safely. This task does not change
the manifest, backend authority, publication behavior, or public package API.

The widget-system behavior remains the same: Config save edits only the draft
manifest, then metadata publication or Build and Publish remains explicit. See
[`llm.widget-system.md`](../../docs/internal/llm.widget-system.md).

## Plan

![Current split icon controls](B112.png)

1. Refactor the existing frontend `ToolIconPicker` into a controlled,
   Kobalte-backed visual combobox. Show **No icon**, **Custom SVG or emoji**,
   and supported Lucide choices. Show each Lucide glyph next to its name in the
   trigger and option row, and allow name filtering without making all icons
   permanently visible.
2. Replace the split icon fields in `WidgetDetailPage` with the single picker.
   Keep custom mode selected while its value is being edited, and reveal a
   multiline, non-spellchecked textarea only in that mode.
3. Preserve the author's exact custom value in form state. Validate against the
   SDK's existing icon rule and show a concise inline error; do not silently
   truncate, rewrite, or persist sanitized markup. Never submit an empty or
   malformed `{ svgIcon }`, and never emit both icon properties.
4. Move picker styling to a component-local CSS module using semantic theme
   tokens, square borders, compact monospace layout, visible focus, Kobalte
   state attributes, and a restrained portal popover.
5. Extend focused tests for initial values, keyboard-accessible selection,
   Lucide glyph/name display, custom textarea visibility and preservation,
   no-icon selection, saved payloads, invalid custom input, dirty state, and
   build/publication gating.
6. Update the draft Config reference capture in the
   [screen atlas](../../docs/internal/screens/SCREENS.md) after the interaction
   is implemented.

## Acceptance criteria

- Draft Config contains one field labelled **Icon**; the old **Icon type** and
  **Icon value** controls are gone.
- The closed control shows the selected Lucide glyph and name.
- The dropdown is keyboard accessible, searchable by Lucide name, and shows a
  glyph beside every Lucide result.
- Choosing **Custom SVG or emoji** reveals a textarea; choosing any other option
  hides it.
- A valid paste saves exactly as `{ svgIcon }`; a Lucide choice saves exactly as
  `{ lucidIcon }`; **No icon** saves `null`.
- Empty/invalid custom input is explained inline and cannot produce a malformed
  manifest payload.
- Saving still uses the observed manifest digest, refreshes the catalog, and
  retains existing dirty-state and publication/build gating.
- No SDK schema, backend authority, or public package API is changed.
