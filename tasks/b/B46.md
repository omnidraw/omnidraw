# B46 - db resource: structured tables should default to SQLite STRICT mode
[Overview](../BASED.md)

User tables created through the DbResource structured schema workbench were flexible-typing SQLite tables even though host bookkeeping tables were already STRICT. Add an explicit structured option, default new user tables to STRICT, preserve legacy table modes during rebuilds, and keep advanced/raw SQL unchanged.

## Context

- Structured `createTable` generated only the optional `WITHOUT ROWID` suffix.
- Rebuild SQL already attempted to preserve `STRICT` and `WITHOUT ROWID`, but detected them anywhere in the original SQL rather than only in the trailing table options.
- Turso 0.6.1 reads combined `STRICT, WITHOUT ROWID` tables but its CREATE TABLE parser rejects SQLite's valid combined option syntax. A narrow Bun SQLite compatibility execution path is required for those structured changes while Turso remains the normal DbResource engine.

## Plan

1. Add `strict?: boolean` to the structured operation contract and default omission to true.
2. Validate STRICT columns against SQLite's supported `INT`, `INTEGER`, `REAL`, `TEXT`, `BLOB`, and `ANY` types.
3. Generate and preserve exact trailing table options, including combined STRICT/WITHOUT ROWID tables and non-STRICT legacy tables.
4. Expose STRICT and WITHOUT ROWID switches in the schema workbench.
5. Add provider and API contract regressions, then run service-actor tests, type checks, and functional-core lint.
