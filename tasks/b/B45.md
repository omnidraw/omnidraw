# B45 - image paste: pending local preview can persist without media upload
[Overview](../../BASED.md)

Pasting an image can leave a usable local bitmap but no `media_files` row; another browser then receives an image element with no usable source.

## Context
The image insertion path is split between a local-only preview and an asynchronous upload:

- `packages/canvas/src/plugins/image/Image.plugin.ts` handles paste, creates the upload portal, registers pending inserts, and immediately selects the preview node.
- `packages/canvas/src/plugins/image/tx.insert-image.ts` creates that preview with `sourceUrl: null`, waits for `api.file.put`, and is intended to commit the image element only after upload returns a persisted URL.
- `packages/api-file/src/api.put-file.ts` awaits `context.db.file.create()` before returning a URL, so the intended successful insertion path cannot return a URL without first inserting a `media_files` row.
- `packages/canvas/src/plugins/transform/Transform.plugin.ts` independently serializes selected runtime nodes and writes them to CRDT on proxy drag/transform. It does not check whether the selected node is a pending image or whether its ID already exists in CRDT.

This creates an ownership hole: the pending image is deliberately selectable and draggable before upload completion, while the global transform path can serialize it through the image element definition. Its metadata still has `url: null` and `base64: null`. A drag or resize can therefore create/update the CRDT image independently of `txInsertImage()`. The originating browser continues to show the already-decoded in-memory bitmap, but another browser hydrates the source-less CRDT element as empty. A failed or stalled upload also produces no `media_files` row, matching the observed state.

The existing image insertion tests mock `file.put` and test pending cleanup, but they do not combine a deferred/failed upload with the real transform plugin, nor do they verify the browser-to-ORPC-to-database upload path.

## Plan

### 1. Reproduce both failure lanes
- Add an integration test with a deferred image upload, select the local preview, then drag and resize it through the transform plugin.
- Assert no CRDT image is created while the upload is pending, including partial x/y patches.
- Exercise the real websocket `api.file.put` path with browser-compatible binary input and verify a `media_files` row is inserted before a URL is returned.
- Capture the actual upload error or stalled state seen in the browser instead of assuming the transform leak is the only failure.

### 2. Make pending ownership explicit
- Mark pending image nodes with an explicit runtime-only state owned by the image plugin.
- Ensure generic transform, reorder, grouping, style, clone, and serialization paths cannot persist pending nodes.
- Preserve local move/resize interaction if desired, but keep those changes only on the runtime node until upload succeeds.
- On successful upload, attach the persisted URL, clear pending state, then commit exactly one complete CRDT image using the node's latest geometry.

### 3. Make upload failure terminal and visible
- Ensure failed, disconnected, or timed-out uploads remove the local preview and cannot leave a source-less CRDT element.
- Surface the underlying upload error to the user.
- If a legacy source-less image was already written by this race, remove it during failure cleanup when safe.

### 4. Verify cross-browser persistence
- Paste, move, and resize while upload is delayed; then complete the upload and verify one DB row and one CRDT image with a non-null URL.
- Open the same canvas in a second browser context and verify the image loads from `/files/:id.ext`.
- Cover upload rejection/disconnect and confirm zero DB rows, zero CRDT image elements, and no remaining preview.

## NOTES
- The local bitmap is not proof of successful persistence; it is installed from the clipboard object URL before upload finishes.
- Do not fix this by persisting `blob:` URLs or base64 clipboard data. The durable source must remain the URL returned after `media_files` insertion.
- The invariant should be: a CRDT image element is either absent, or it has a durable source that another browser can load.
