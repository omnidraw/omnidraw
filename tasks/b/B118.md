# B118 - resource forms: keep focus while editing dialog values
[Overview](../BASED.md)

Typing in the key-value JSON editor moves focus back to the first Key field after one character. Keep modal focus stable across reactive form updates and cover the shared resource dialogs.

## Context

The key-value and secret entry editor in [`GenericResourcePage.tsx`](../../apps/frontend/src/shell/framework/feature/resource/GenericResourcePage.tsx) derives dialog openness from the complete editor state. Each input replaces that state while the shared dialog effect in [`owned-primitives.tsx`](../../apps/frontend/src/shell/framework/feature/resource/owned-primitives.tsx) also observes the open callback. Reactivation invokes [`modal-focus-scope.ts`](../../apps/frontend/src/shell/framework/components/ui/modal-focus-scope.ts), which focuses the first enabled control.

Database row and structure editors keep their input state local and do not currently reproduce the jump, but the shared primitive should preserve focus whenever an open dialog updates reactively.

## Plan

![JSON value focus returning to the Key field](B118.png)

1. Make the shared dialog focus scope react only to real open/close transitions while Escape uses the current close callback.
2. Add a primitive regression for reactive state changes while a dialog remains open.
3. Add resource-editor coverage for typing multiple characters in KV and secret value controls, and verify database structure form focus remains stable.
4. Run targeted frontend tests and typechecking.
