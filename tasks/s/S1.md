# S1 - double bun run dev -> find new port

## Plan
- Simplify local dev startup behavior around port selection.
- Ensure multiple concurrent `bun run dev` sessions do not collide on backend ports.
- Ensure each frontend connects to its matching backend, not always `localhost:3000`.

## NOTES
- Category: subtraction.
- Current backend fallback lives in `apps/cli/src/plugins/server/ServerPlugin.ts` as `serveWithPortFallback(...)`.
- Current behavior intentionally disables fallback when `compiled === false`; test coverage exists in `apps/cli/tests/server.plugin.test.ts` (`stays strict in dev mode`). This is why second dev backend fails on port `3000`.
- Vite frontend already falls back because `apps/frontend/vite.config.ts` sets `server.port: 3002` without `strictPort`.
- Frontend proxy targets are hardcoded to backend port `3000`:
  - `/api` -> `http://localhost:3000`
  - `/files` -> `http://localhost:3000`
- ORPC and terminal websocket paths use same-origin host, so they will follow the Vite proxy if the proxy target is correct:
  - `packages/orpc-client/src/index.ts`
  - `packages/canvas/src/plugins/terminal/widget.ts`
- Automerge bypasses the Vite proxy in dev and hardcodes `ws://localhost:3000/automerge` in both:
  - `apps/frontend/src/services/automerge.ts`
  - `packages/canvas/src/automerge.ts`
- Recommended robust implementation:
  - Add a small dev coordinator script that chooses a backend/frontend port pair.
  - Start CLI with `--port <backendPort>`.
  - Start Vite with `--port <frontendPort>` and env like `VIBECANVAS_BACKEND_PORT=<backendPort>`.
  - Read that env in `apps/frontend/vite.config.ts` for `/api`, `/files`, and `/automerge` proxy targets.
  - Change Automerge dev websocket to same-origin `/automerge` so Vite proxy can route it.
- Minimal implementation:
  - Make backend fallback active in dev too.
  - Add `/automerge` Vite proxy.
  - Compute/inject backend port for Vite proxy. Avoid leaving any `localhost:3000` frontend hardcode.
