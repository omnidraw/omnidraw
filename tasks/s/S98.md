# S98 - widgets: replace fullscreen header with SolidJS host chrome
[Overview](../BASED.md)

Replace the bespoke imperative fullscreen title strip with SolidJS chrome that visually and behaviorally matches the widget's contained Konva frame.

## Context

Contained widgets already render a complete host header in Konva:

- `../../packages/ai-chat/src/widget/fn.create-widget-node.ts` draws the themed header, red/yellow/green traffic lights, title, divider, and three-dot menu.
- `../../packages/ai-chat/src/widget/fx.attach-widget-listener.ts` owns the contained traffic-light and menu interactions.
- `../../packages/ai-chat/src/widget/CONSTANTS.ts` defines the shared dimensions and control geometry.
- `../../packages/ai-chat/src/widget/fn.get-host-theme-colors.ts` maps application themes to widget-host colors.

Fullscreen is different. `../../packages/ai-chat/src/widget/attach-dom-portal.ts` constructs and styles a separate header with imperative DOM calls, hard-coded colors, and one bespoke **Exit Fullscreen** button. It does not look or behave like the contained frame. This file also moves custom title-bar actions into that header and must continue preserving the mounted widget body across mode changes.

`../../packages/ai-chat/src/widget/WidgetManagerService.ts` already owns instance removal, minimize/fullscreen transitions, and the widget actions menu. The SolidJS header should invoke those existing host actions rather than introducing a second state-transition implementation.

The current fullscreen AI Chat treatment is shown below. It demonstrates the full-workspace placement and title strip to replace; the written target is the standard widget traffic-light chrome, not a literal copy of this thin blue strip.

## Plan

![Current fullscreen AI Chat header reference](S98.webp)

### 1. Define one fullscreen host contract

- Add a small SolidJS fullscreen-header component beside the widget host code.
- Give the component presentation data and action callbacks: label, host colors, custom title actions and state, close, minimize, exit fullscreen, and open menu.
- Keep widget mutation, deletion, context-menu ownership, and Konva-node access outside the component.
- Reuse the existing host constants so the DOM header has the same height, traffic-light size/spacing, title spacing, divider, and menu dimensions as the Konva frame.

### 2. Match the contained Konva header

- Render red, yellow, and green traffic-light buttons at the left, followed by the ellipsized widget label.
- Render registered widget title actions and the three-dot host menu at the right, in the same order as the contained frame.
- Use `fnGetHostThemeColors` output instead of fullscreen-only hard-coded colors, including the `widget` versus `ui-widget` header treatment.
- Support hover, pressed, focus-visible, disabled, and tooltip/accessible-label states without relying on color alone.
- Keep the header at `WIDGET_HOST_HEADER_HEIGHT`; size the existing fullscreen body beneath it without recreating or remounting widget content.

### 3. Make every control functional

- Red closes the widget through the existing delete-instance path, including normal history/cleanup behavior.
- Yellow minimizes the fullscreen widget back to its preserved contained position as a collapsed widget; it must not leave an empty fullscreen shell or overwrite contained geometry.
- Green exits fullscreen to the preserved expanded contained frame.
- The three-dot control opens the existing widget actions menu, anchored to the DOM button.
- Registered title-bar actions, such as AI Chat **Settings**, continue to use the existing `TWidgetTitleBarPortal` handlers and pressed/disabled/label updates.
- Button and menu interactions must stop canvas drag/pan propagation while remaining keyboard operable.

### 4. Integrate SolidJS without remounting the widget

- Mount one SolidJS header root for each hosted widget and update its visibility/state when the window mode, label, title-action state, or theme changes.
- Keep contained mode rendered by Konva; show the SolidJS chrome only while fullscreen.
- Preserve the current invariant that the same widget body `div` and sandbox/render lifecycle survive fullscreen enter and exit.
- Dispose the Solid root, subscriptions, callbacks, and menu state when the widget node or DOM portal is removed.
- Remove the old manually-created fullscreen title, SVG, Exit Fullscreen button, and inline style block after parity is covered.

### 5. Verify behavior and visual parity

- Add a focused Solid component test for labels, traffic lights, title actions, menu control, accessibility attributes, and callback dispatch.
- Update fullscreen portal integration tests to prove header/body sizing, Solid visibility, same-body identity, and complete cleanup.
- Add interaction coverage for red close, yellow minimize-to-contained, green exit-to-contained, menu anchoring, and a custom title action.
- Add light/dark and `widget`/`ui-widget` color assertions based on the shared host palette rather than duplicated literals.
- Manually compare contained and fullscreen headers at normal and narrow widths; verify long labels truncate while right-side actions remain usable.
- Refresh the fullscreen capture in `../../docs/internal/screens/SCREENS.md` after implementation because the visual state changes materially.

## NOTES

- SolidJS is required only for fullscreen chrome. Do not replace the contained Konva frame in this task.
- Visual parity should come from shared constants and theme data, not from trying to mount Konva above fullscreen DOM.
- The body element's object identity remains an acceptance criterion; header replacement must not reset AI Chat, sandbox, actor subscription, scroll, or widget-local state.
- Do not let the Solid component directly patch Automerge or mutate Konva attrs. It should dispatch host actions through an injected boundary.
- The supplied image was compressed from a 290,149-byte PNG to a 68,980-byte WebP without changing its 1367×1558 dimensions.
