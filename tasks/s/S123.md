# S123 - Preview: move actions into one Manage dropdown
[Overview](../BASED.md)

Replace the row of Preview actions with one **Manage** dropdown. This gives the
title bar a clear drag area and removes the hidden Cancel-button bug.

## Context

Preview currently puts **Pause**, **Cancel**, **Retry**, **Reset**, and
**Publish** directly in the title bar. The controls take most of the available
space and make it unclear where the frame can be dragged.

There is also a real input bug:

- [`fn.canvas-widget.ts`](../../packages/ui-ai-chat/src/canvas-extension/fn.canvas-widget.ts)
  always includes the Cancel control in the Cangine frame node.
- [`canvas-extension/index.ts`](../../packages/ui-ai-chat/src/canvas-extension/index.ts)
  hides and disables only the DOM button after a build finishes.
- Cangine still hit-tests the unchanged frame node, so the blank space where
  Cancel used to appear remains clickable.
- Clicking or starting a drag in that space activates Cancel and shows
  “Preview build is no longer cancellable.”

The new dropdown must fix that split state. Moving the actions without fixing
their activation state would only move the bug into the menu.

[`A97`](../a/A97.md) separately owns the host log terminal below Preview
content. This task changes only the title-bar actions and their input behavior.

## Plan

![Preview with one open Manage dropdown](S123.png)

### 1. Replace the action row

- Keep the close, minimize, and maximize traffic lights.
- Replace all Preview-specific title-bar buttons with one right-aligned
  **Manage** dropdown.
- Put these actions in the dropdown:
  1. **Pause live updates** / **Resume live updates**
  2. **Cancel build**
  3. **Retry**
  4. **Reset**
  5. **Publish**
- Keep the current action behavior. This is a UI simplification, not a change
  to Preview build, reset, or publication rules.
- Use Cangine's normal dropdown and menu interaction path so pointer, keyboard,
  focus, escape, and outside-click behavior stay consistent with other canvas
  menus.

### 2. Make one state control visuals and input

- Replace the DOM-only `createTitleBarPortal` state patching with one transient
  control-state boundary used by Cangine rendering, accessibility, menus,
  hit-testing, and activation.
- Support transient label and disabled state for dropdown items:
  - Pause changes to Resume while live updates are paused.
  - Cancel is disabled when there is no pending cancellable build.
  - Publish is disabled when the current Preview is not publishable.
- Do not persist build or menu state into the durable canvas document.
- If Cangine does not yet expose the required transient dropdown-item state,
  add the smallest reusable interaction-controller API, update the dependency,
  and remove the Vibecanvas DOM shadow state.
- Recheck runtime state when an action is dispatched. A stale menu activation
  must safely do nothing; it must not cancel a different build, publish a stale
  revision, or show the misleading cancellation toast.

### 3. Restore predictable frame dragging

- Only the visible **Manage** button may consume pointer input in the right-side
  control area.
- The title and every other visible part of the title lane must start normal
  frame selection and dragging.
- Hidden or disabled controls must have no retained pointer target.
- Opening or using the dropdown must not start a frame drag or canvas pan.

### 4. Remove old plumbing and verify

- Route Cangine `dropdown-item` activations to the existing Preview runtime
  actions and remove the five separate title-button activations.
- Delete DOM queries and state mutations that are no longer needed.
- Add pointer-level regression coverage that opens the dropdown, invokes each
  available action, and drags the frame from the reclaimed title lane.
- Cover Cancel and Publish enabled/disabled transitions, Pause/Resume label
  changes, a stale activation, keyboard navigation, and menu cleanup on frame
  remount or removal.
- Update the AI draft Preview screenshot and description in
  [`SCREENS.md`](../../docs/internal/screens/SCREENS.md).

## Acceptance criteria

- Preview shows one **Manage** control instead of separate Pause, Cancel, Retry,
  Reset, and Publish buttons.
- The dropdown contains all five actions with correct live labels and disabled
  states.
- The frame can be dragged from the reclaimed title lane.
- No hidden or disabled action can be hit by pointer, keyboard, or stale menu
  activation.
- Clicking or dragging the old Cancel location never shows “Preview build is
  no longer cancellable.”
- Preview control state remains transient and is not written to `canvas_items`.
