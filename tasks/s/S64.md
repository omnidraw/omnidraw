# S64 - db: store actor manifest paths relative to config
[Overview](../BASED.md)

Stop persisting absolute actor `manifest_path` values. The DB should store paths relative to the Vibecanvas config directory, e.g. `widgets/<slug>/vibecanvas.json`.

## Context

`actor_definitions.manifest_path` was added in [`packages/service-db/src/DbServiceTurso/migration-files/005-add-actor.sql`](../../packages/service-db/src/DbServiceTurso/migration-files/005-add-actor.sql) with an absolute-path check. No migration is needed for this task; update runtime usage only.

Current usage findings:
- [`packages/service-db/src/model.ts`](../../packages/service-db/src/model.ts) validates `manifest_path` with `z.string().startsWith("/")`; this must allow relative config paths.
- [`packages/service-db/src/DbServiceTurso/tx.actor.ts`](../../packages/service-db/src/DbServiceTurso/tx.actor.ts) inserts and updates `manifest_path` as provided by callers.
- [`packages/service-actor/src/ActorService.ts`](../../packages/service-actor/src/ActorService.ts) knows `configPath`, derives `absWidgetDir = join(configPath, 'widgets')`, and later uses `dirname(vcJson.manifest_path)` as if the path is absolute in `getWidgetCode`.
- [`packages/service-actor/src/ActorSupervisor.ts`](../../packages/service-actor/src/ActorSupervisor.ts) discovers absolute manifest paths from `fxListVibecanvasJsons`, writes those paths into `vibecanvasDefMap`, syncs them to DB, and uses `dirname(def.manifest_path)` as actor `rootDir`.
- [`packages/service-actor/src/core/fx.vibecanvas-actors.ts`](../../packages/service-actor/src/core/fx.vibecanvas-actors.ts) returns discovered absolute `vibecanvasJsonPath` values.
- [`packages/service-actor/src/core/tx.actor-definitions.ts`](../../packages/service-actor/src/core/tx.actor-definitions.ts) compares DB rows by `manifest_path` and sends `manifest_path` through insert/update. Matching should use the persisted relative path once conversion is added.
- Tests currently seed absolute-style paths in [`packages/service-db/src/tests/BunServiceTurso/tx.migrations.test.ts`](../../packages/service-db/src/tests/BunServiceTurso/tx.migrations.test.ts), [`packages/service-db/src/tests/BunServiceTurso/fx.actor.test.ts`](../../packages/service-db/src/tests/BunServiceTurso/fx.actor.test.ts), and absolute fixture paths in [`packages/service-actor/tests/ActorSupervisor.test.ts`](../../packages/service-actor/tests/ActorSupervisor.test.ts).
- Prior exploration [`tasks/e/E28.md`](../e/E28.md) assumed DB paths are workspace-prefixed/absolute and should be considered outdated after this task.

Desired behavior:
- Persist `actor_definitions.manifest_path` relative to the config directory, not absolute filesystem paths.
- Keep runtime file loading absolute by resolving stored relative paths against `configPath` at service boundaries.
- A discovered manifest at `<configPath>/widgets/counter/vibecanvas.json` should persist as `widgets/counter/vibecanvas.json`.
- Do not add or edit migrations for this change.

## Plan

### 1. Introduce path conversion at the actor service boundary
- Keep discovery free to work with absolute paths if simplest.
- Before syncing definitions into DB, convert discovered manifest paths to config-relative paths.
- When creating actor root dirs or reading widget code, resolve `manifest_path` against `configPath` before `dirname(...)`.

### 2. Update DB validation and tests
- Relax `ZActorDefinition.manifest_path` from absolute-only to relative config-path validation.
- Update service-db tests to seed relative values like `widgets/counter/vibecanvas.json`.
- Update service-actor tests so DB/storage assertions expect relative paths while runtime actor roots still resolve to fixture directories.

### 3. Preserve DB sync semantics
- `txSyncDbActorDefinitions` should compare and persist the relative value.
- Confirm updates do not duplicate rows when an existing definition already has the same relative manifest path.
