# S143 - functions: keep OSS execution direct, local, and trusted (order 4/8)
[Overview](../BASED.md)

Adapt the existing direct Bun child runner to the portable server module
without introducing Cloudflare execution or claiming a local security
sandbox.

## Context

OSS already executes one function call in one disposable Bun child, loads the
guest module in a blank `node:vm` context, bridges resources over IPC, and
retains no invocation history. This is the correct local product behavior. The
refactor only changes the artifact/ABI consumed by that runner and clarifies
its name and trust model.

## Plan

### 1. Consume the portable module directly

- Replace envelope decoding with exact digest and fixed-ABI validation of the
  raw ES module selected by the pinned Preview or publication.
- Load only the canonical named export from `functions.json` and recheck its
  immutable registration against the pinned descriptor before execution.
- Use the same raw module for bounded descriptor extraction during host
  acceptance and for live invocation.
- Reject missing, additional, malformed, accessor-backed, or descriptor-
  mismatched exports before a handler starts.

### 2. Preserve direct trusted-host execution

- Continue spawning a disposable local Bun child for every descriptor
  extraction and invocation. Do not add workerd, Miniflare, Wrangler, Workers
  for Platforms, a remote executor, containers, or a cloud fallback.
- Rename sandbox-shaped local types such as `BunChildSandboxDriver` where they
  imply hostile-code isolation. A cage, blank environment, `node:vm`, process
  group, and denied `fetch` remain useful defense in depth, but the product
  contract is trusted host execution.
- Keep the child on the local host with the OSS process's deployment authority.
  Documentation must warn that installed widget server code is trusted to the
  same degree as other local code.
- Construct the same authority-free guest global surface used by the portable
  profile. Trusted host execution is not permission for widget code to access
  files, environment variables, processes, sockets, network, OS APIs, or
  adapter globals.
- Reject an artifact before execution if it uses a construct unavailable in
  the managed Worker profile. The OSS runtime implements exactly the portable
  language, not a trusted Bun superset.

### 3. Preserve bounded direct-call semantics

- Retain input and output schema validation, timeout, cancellation,
  disconnect handling, memory tier, CPU/RSS observation, output/log byte
  limits, resource call count, bounded diagnostics, and process-group reaping.
- Retain function effect ceilings and manifest resource revalidation.
- Retain process-local, single-use write permits consumed at the provider
  commit edge, with no automatic replay after an unclear write.
- Retain one request/one terminal response and no queue, retry, status, lease,
  receipt, usage table, logs API, or history.

### 4. Match the portable bridge

- Construct the fixed SDK context shape inside the worker and adapt
  `context.resources.read/write` to the current IPC gateway.
- Translate local cancellation and resource/provider failures to the same
  bounded SDK failure envelope expected from the managed adapter.
- Keep local process metrics private; do not add managed billing or usage
  evidence to OSS contracts.

## NOTES

- Group: `[R]` portable widget server and resource hard cut.
- Depends on [S142](./S142.md).
- “Direct on host” allows the current disposable child and `node:vm`
  defense-in-depth boundary; it forbids replacing local execution with a
  managed sandbox service.
- This task must not weaken current cleanup or resource authorization because
  OSS code is trusted.
- The no-OS rule is a portability and least-authority contract. The local
  trusted-host warning remains necessary because the child is not a hostile
  code security boundary.
- OSS has no per-user, monthly, metering, or cloud-plan limit. Existing
  author-declared per-call timeout and cancellation behavior remains technical
  lifecycle behavior, not a managed-offering quota or the cost-model bound
  `N`.
