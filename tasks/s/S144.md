# S144 - resources: make function resource calls a portable SDK ABI (order 5/8)
[Overview](../BASED.md)

Freeze the widget-facing KV, secret-store, and database behavior as an
SDK-owned serializable protocol that local IPC and a managed Worker bridge can
both implement.

## Context

The SDK owns resource declarations, but the executable call/result types and
most operation semantics still live in backend-private types. The OSS worker
passes `unknown` values over Bun IPC. A Workers for Platforms adapter will
cross a Fetch/subrequest boundary and a Turso adapter must encode database
values consistently. Sharing only TypeScript shapes is insufficient: both
hosts need the same bytes, limits, operations, results, and failures.

## Plan

### 1. Define one operation registry

- Make the SDK the canonical owner of widget-facing operation names, effects,
  input/result schemas, and limits for all three resource kinds.
- Preserve KV and secret-store `get`, `has`, `list`, `set`, `delete`,
  and `compareAndSet` behavior, including pagination, revisions, conditional
  outcomes, and bounded values.
- Preserve database named-operation invocation and explicitly enabled
  arbitrary `query` and `execute` calls, including bounded batches.
- Keep resource catalog identity, concrete `resourceId`, storage keys,
  credentials, paths, provider handles, write capabilities, and permit claims
  host-only.

### 2. Add a canonical wire codec

- Define a versioned request/result/failure envelope for a function's resource
  bridge. It carries only invocation correlation, logical slot, operation,
  effect, and validated input.
- Audit current author-visible values first, then add canonical tagged encoding
  for values JSON cannot faithfully represent, especially signed 64-bit
  integers and byte arrays. Preserve ordinary author-facing JavaScript values
  on both sides of the codec.
- Reject non-finite numbers, cyclic values, unsupported prototypes, duplicate
  keys after normalization, excessive nesting/items/bytes, and malformed tags.
- Define deterministic database column/row encoding so column order, null,
  integer, float, text, blob, and JSON behavior cannot drift between local
  Turso Database and Turso Cloud.

### 3. Stabilize authorization and failures

- Keep `fn` resource-free, `fx` read-only, and `tx` read/write.
- Require every call to intersect the function descriptor, current manifest
  declaration, exact current resource binding, operation effect, and host
  policy again at invocation time.
- Export bounded SDK failure codes for malformed input, undeclared slot,
  unknown operation, effect denial, conflict/CAS miss, unavailable resource,
  query failure, limit, cancellation, timeout, and ambiguous write outcome.
- Exclude driver messages, SQL engine details, stack traces, credentials,
  resource IDs, paths, and tenant identity from the portable failure envelope.

### 4. Keep host mechanics private

- OSS maps the portable envelope to Bun IPC and the local Resource Store.
- Managed maps it to a private Worker bridge/outbound path and Turso.
- Cancellation is a host lifecycle signal; do not serialize an
  `AbortSignal` object. Each adapter projects its native request/abort state
  onto the SDK semantics.
- Keep retries, idempotency stores, billing, metering, and transport details out
  of the widget ABI. Writes are never automatically replayed after an unclear
  outcome.
- Keep authenticated user and organization identity out of the resource
  envelope and all guest-controlled bytes.
