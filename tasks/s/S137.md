# S137 - functions: delete durable invocation and usage, keep direct calls

[Overview](../BASED.md)

Remove the durable function job system and retain one bounded, synchronous
server-function call path.

## Context

Server functions still exist in published widget output, but invocation
status, attempts, queues, retries, logs, usage, and write permits no longer
belong in the database.

The target behavior is defined in
[widget-filesystem-design.md](../../docs/internal/widget-filesystem-design.md).

## Plan

### 1. Keep direct execution

- Load the current generated function descriptor from the filesystem catalog.
- Validate input, output, timeout, cancellation, concurrency, and declared
  resource effects.
- Return bounded diagnostics in the current response and retain no history.

### 2. Keep resource safety without durable jobs

- Use short-lived, single-use in-memory write permits.
- Do not retry a write automatically after an unclear result.
- Stop and reap the child on timeout, cancellation, or disconnect.

### 3. Delete durable control code

- Remove function definition, invocation, attempt, lease, idempotency,
  resource-permit, and usage tables and their indexes.
- Delete queue workers, recovery, receipts, control stores, status/cancel/log/
  attempt/usage APIs, events, and fixtures.
- Slim the public `function-runtime` contracts instead of deleting the package.
