# S125 - canvas: remove duplicate host resize observer
[Overview](../BASED.md)

Delete Vibecanvas's second canvas-host `ResizeObserver` and rely on Cangine's
engine-owned automatic host sizing and device-pixel-ratio observation.

## Context

[`runtime.ts`](../../packages/canvas/src/runtime.ts) currently creates an
application `ResizeObserver` after the Cangine editor session attaches:

- the observer watches the same engine host passed to `createInfiniteCanvas`;
- every callback calls `engine.resize()`;
- boot also calls `engine.resize()` once manually; and
- shutdown disconnects the observer before destroying the engine.

Cangine `0.3.0` already owns this lifecycle in its public engine surface:

- engine construction creates the host-surface controller;
- the controller measures the host immediately;
- it installs its own `ResizeObserver`;
- it observes device-pixel-ratio/resolution changes;
- automatic resize publications update the camera viewport and render graph;
- `engine.resize()` with no explicit size merely returns the engine to the
  automatic mode it already uses; and
- `engine.destroy()` disconnects the owned observation.

The extra Vibecanvas observer therefore adds a second callback path for one
host-size change without adding product policy. It can cause duplicate
measurement and resize publication, expands runtime teardown, and makes
runtime tests mock a browser primitive that Cangine already abstracts.

This subtraction does not change canvas layout, CSS, camera persistence,
runtime replacement, widget resize behavior, or manual explicit engine sizing.
No mockup is useful because there is no intended visual change.

## Plan

### 1. Remove application resize ownership

- Remove the nullable `ResizeObserver` field from `buildRuntime`.
- Remove the observer construction, callback, and `observe(config.container)`
  call from boot.
- Remove the manual boot-time `engine.resize()` call.
- Remove observer capture, nulling, and `disconnect()` from shutdown.
- Do not replace this code with a window resize listener, polling, a Solid
  effect, or another host measurement.
- Keep `createInfiniteCanvas({ host: config.container })` as the only host-size
  ownership handoff.

### 2. Simplify runtime tests

- Delete the local `TestResizeObserver` fake from
  [`runtime.test.ts`](../../packages/canvas/tests/runtime.test.ts).
- Remove the global `ResizeObserver` stub and the mocked `engine.resize()`
  event used only by the deleted application path.
- Preserve runtime composition and reverse-order teardown assertions for
  extensions, image drop, editor session, document service, and engine.
- Add or retain a narrow consumer assertion that runtime boot does not create
  an application resize observer or request manual sizing.
- Rely on Cangine's own host-surface tests for resize measurement,
  device-pixel-ratio handling, coalescing, and observer destruction; do not
  duplicate those algorithms in Vibecanvas tests.

### 3. Qualify automatic sizing

- Run the complete canvas package tests and typecheck.
- Browser-check initial canvas sizing and one host resize caused by sidebar or
  window layout change.
- Confirm canvas rendering, picking, camera viewport dimensions, selection
  overlays, widget portal placement, and canvas-maximized frames follow the
  resized host.
- Confirm repeated runtime replacement and shutdown leave no active
  Vibecanvas-owned observer or callback.
- Run `git diff --check` and record exact results in this task.

## Acceptance criteria

- `packages/canvas` does not construct, observe, retain, or disconnect a
  `ResizeObserver` for the Cangine host.
- Canvas runtime boot does not call `engine.resize()` merely to initialize or
  re-enter automatic sizing.
- Cangine remains the only owner of host measurement, resize observation,
  device-pixel-ratio observation, and render-graph resize publication.
- Initial sizing and later host resizing keep rendering, input coordinates,
  selection overlays, and widget portals aligned.
- Runtime shutdown still tears down all product-owned resources in reverse
  order and delegates final surface-observer cleanup to `engine.destroy()`.
- The canvas tests, typecheck, browser qualification, and `git diff --check`
  pass with results logged.
- Production and test code are smaller; no replacement observer path is added.

## NOTES

- `engine.resize({ width, height })` remains a valid explicit manual-size API,
  but Vibecanvas does not currently need manual canvas sizing.
- `WidgetInteractionController` may own separate observation for its overlay
  or focus surface. This task removes only the duplicate application observer
  around the engine host.
- Cangine host-resize internals remain Cangine's test responsibility.
