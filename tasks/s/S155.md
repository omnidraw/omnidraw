# S155 - frontend: restore Kobalte primitives on Solid 2
[Overview](../BASED.md)

Restore the Solid 2-compatible Kobalte component line to the private frontend,
move accessibility and overlay mechanics back to the library, and delete the
owned primitive implementations introduced during S153 without reverting
S153's Solid 2, lifecycle, request-fencing, or product-behavior fixes.

## Context

The implementation authority is
[`llm.kobalte.md`](../../docs/external/llm.kobalte.md), audited from Kobalte's
`solid2` branch at `a892187065cf7e0d07e91db02310bd28a5619236`.
It explicitly identifies `@kobalte/core@2.0.0-alpha.0` as the Solid 2 line and
pins the same coherent runtime family already selected by S153:
`solid-js@2.0.0-rc.0` and `@solidjs/web@2.0.0-rc.0`. Kobalte therefore did not
need to be removed to complete the Solid 2 cut.

Use the parent of the Solid 2 migration as the behavioral and component
inventory baseline:

- pre-Solid-2 baseline: `582640038cbf93752101dcc5f43c1c5db8cdb475`;
- Solid 2 migration: `fe2616d25`;
- audited current state: the S153 follow-up state on 2026-08-20.

The old commit is a comparison reference, not a patch to replay. It used
`@kobalte/core@^0.13.12` with Solid 1 and the older Kobalte API. Restoration
must use Kobalte 2 subpath imports and callable roots such as `<Dialog>`, not
deprecated root-barrel imports or `<Dialog.Root>` aliases.

This is a subtraction task because it removes duplicated generic UI machinery
now maintained locally: `owned-primitives.tsx` (783 lines),
`modal-focus-scope.ts` (225 lines), `anchored-popup.ts` (123 lines), and most of
the custom Toast implementation. Product-specific components and policies stay
in the frontend; Kobalte remains headless and unstyled.

### Behavior that must not be reverted

The pre-Solid commit predates correctness fixes that must survive the library
restoration. In particular:

- retain Solid 2 compute/apply discipline, `@solidjs/web` JSX/Portal ownership,
  lowercase `tabindex`, and zero strict-read/owned-scope diagnostics;
- retain generation and identity fences for resource loads and mutations,
  Widget Detail deletion planning/commit, and dialog close/reopen races;
- retain secondary-owner-document behavior, including resource secret
  visibility and portal/focus ownership;
- retain the current application loading boundary, keyed route branching, and
  settled lifecycle behavior;
- retain current product labels, pending/disabled policy, notification text,
  tab selection, destructive-action focus policy, and visual classes;
- retain current viewport-edge, overflow-container, keyboard, focus-return,
  modal-containment, Toast expiry, and accessibility regression coverage.

Do not restore files wholesale from `582640038`. Translate only the primitive
composition while keeping current application logic. Do not change Canvas or
`@omnidraw/component-ai-chat`; neither is part of the 18-file Kobalte baseline,
and the latter is a public package with its own overlay implementation.

## Plan

### 1. Restore one coherent dependency graph

- Add exact `@kobalte/core@2.0.0-alpha.0` to the root catalog and the private
  frontend dependency list. Do not use a tag, caret prerelease range, peer
  override, forced install, or a second Solid copy.
- Regenerate and sanitize `bun.lock`. Prove the installed graph contains one
  exact `solid-js@2.0.0-rc.0`, one exact `@solidjs/web@2.0.0-rc.0`, and the
  existing exact RC.0 compiler preset. Keep loopback registry URLs out.
- Keep `jsxImportSource: "@solidjs/web"` and the explicit Solid 2 Vite compiler
  module target. Import Kobalte only through component subpaths such as
  `@kobalte/core/dialog`; the deprecated root barrel is forbidden.
- Treat any peer change published after this task was written as a new matrix
  decision. Do not mix RC.0 and RC.1 to obtain a newer tag.

### 2. Restore simple controls and collections first

- Replace the local Button facade and native rewrites with Kobalte Button and
  ToggleButton where those files used them in the baseline. Preserve explicit
  `type="button"` and submit behavior.
- Restore TextField, Checkbox, Switch, and Select anatomy, including labels,
  hidden/native inputs, validation state, `FormData`, and native reset.
- Restore Tabs with List, Trigger, and Content parts. Preserve current selected
  styling through Kobalte `data-*` state, orientation, Home/End, arrow keys,
  focusability, and controlled external updates.
- Use Kobalte 2 callable roots and documented parts. Do not recreate the old
  Solid 1 wrapper API merely to minimize the textual diff.

### 3. Restore menus, comboboxes, and floating content

- Move Sidebar item/widget actions and database object actions back to
  DropdownMenu with Trigger, Portal, Content, and Item anatomy.
- Move ToolIconPicker back to Combobox and TextField with its real collection,
  filtering, selected value, accessible label, and listbox anatomy.
- Use Kobalte's portal and popper collision behavior: same owner document,
  theme variables, flip/slide near viewport edges, bounded height, and escape
  from local overflow clipping. Do not retain fixed coordinates or a parallel
  application popper implementation.
- Verify pointer open, ArrowDown/ArrowUp entry, item arrows, Home/End, typeahead
  or filtering, selection, Escape, outside/focus-out dismissal, trigger focus
  restoration, programmatic focus departure, scroll, resize, and bottom-edge
  placement.

### 4. Restore modal dialogs and alert dialogs

- Compose every current dialog from Kobalte Dialog or AlertDialog Trigger,
  Portal, Overlay, Content, Title, Description where useful, and close/action
  parts. Preserve current CSS and product markup without overriding generated
  ARIA relationships.
- Keep dialogs controlled by the current application state. Kobalte owns focus
  scope, outside inertness, Escape/backdrop dismissal, scroll locking, and
  focus restoration; application code continues to own pending and async
  continuation policy.
- Initially focus the least destructive AlertDialog action. Test programmatic
  and hotkey focus escape, Tab/Shift+Tab loops, nested/topmost overlay behavior,
  exact owner-document isolation restoration, and unmount while open.
- Preserve all captured resource/widget/open generations. A Kobalte
  `onOpenChange` callback must not let a stale request close or mutate a later
  review.

### 5. Restore Kobalte Toast while keeping the application facade

- Keep the existing `showToast`, `showErrorToast`, `showSuccessToast`, and
  `showWarningToast` API used by product code, but implement it through
  Kobalte's `toaster`, Toast parts, one portaled Region, and List.
- Preserve the current limit of three visible entries, 5-second progress and
  expiry contract, severity roles/labels, close action, Escape/right-swipe,
  Alt+T focus, interaction pause, page-idle pause, and the ordering expected by
  callers.
- Ensure focused dismissal cannot leave global expiry paused. Prefer Kobalte's
  built-in pause bookkeeping rather than retaining a second timer state
  machine.

### 6. Delete replacement infrastructure and compatibility residue

- Delete `feature/resource/owned-primitives.tsx` after all resource/database
  consumers import Kobalte directly. Avoid replacing it with another generic
  private wrapper layer.
- Delete `components/ui/modal-focus-scope.ts` after the last current dialog
  uses Kobalte focus management.
- Delete `components/ui/anchored-popup.ts` after SidebarItem, ToolIconPicker,
  and resource DropdownMenu use Kobalte popper placement. Confirm there are no
  non-Kobalte consumers before deletion.
- Reduce `components/ui/Toast.tsx` to the product facade and Kobalte
  composition. Remove local queue, timer, swipe, global focus, and region
  mechanics that Kobalte now owns.
- Remove custom data attributes, CSS branches, test polyfills, and helper tests
  that exist only for deleted implementations. Retain product styling and
  behavior tests, rewritten around roles, names, state, focus, and geometry.
- Reject remaining frontend generic implementations of dialog focus scopes,
  command-menu roving focus, combobox/listbox navigation, floating collision,
  hidden form controls, or Toast queue lifetime unless a documented product
  requirement cannot be expressed through Kobalte 2.

### 7. Qualify Solid 2 behavior and the real application

- Port the focused coverage in `Toast.test.tsx`, `owned-primitives.test.tsx`,
  `DbResourcePage.test.tsx`, `GenericResourcePage.test.tsx`,
  `SidebarCreateDialogs.test.tsx`, `CanvasSidebarDeletion.test.tsx`,
  `WidgetDetailPage.test.tsx`, and `WidgetsSidebarSection.test.tsx`. Delete the
  owned-primitives suite only after its behavioral assertions live with the
  consuming surfaces.
- Run every changed surface against the Solid development build and fail on
  strict reads, writes in owned scopes, halted reactivity, or async work
  outside a loading boundary. Do not silence diagnostics.
- Run frontend typecheck, focused Vitest, the complete frontend test/build and
  inspection gates, architecture/dependency checks, frozen/public-lockfile
  checks, and a clean application start.
- Verify with Chrome in the real source-run application: create/rename/delete
  Canvas dialogs, create and mutate generic/database resources, database
  object actions, sidebar menus, Widget Detail tabs/delete, ToolIconPicker, and
  multiple Toast lifecycles. Exercise pointer and keyboard paths, a viewport
  edge, an overflow container, modal focus escape, and focus restoration.
- Record exact commands, results, browser routes/actions, diagnostics, and any
  deliberate exception in this task log. A human performs the final visual
  verification.

## Acceptance criteria

- The frontend uses exact `@kobalte/core@2.0.0-alpha.0` with one exact
  `solid-js@2.0.0-rc.0` and one exact `@solidjs/web@2.0.0-rc.0`; the compiler
  preset remains in the same peer-compatible RC.0 family.
- All 18 pre-Solid Kobalte surfaces again use the appropriate Kobalte 2
  primitive, or the task records a narrow exception with a concrete unsupported
  product requirement and focused evidence. Old Kobalte 0.x code is not copied
  back wholesale.
- Imports use `@kobalte/core/<component>` and callable Kobalte 2 roots. There
  are no deprecated root-barrel imports, `.Root` aliases, legacy
  `solid-js/web` imports, or Solid-owned DOM JSX types.
- `owned-primitives.tsx`, `modal-focus-scope.ts`, and `anchored-popup.ts` are
  gone once consumer scans prove them unused. The Toast facade contains no
  duplicate queue/focus/timer/swipe implementation.
- Menus, comboboxes, selects, tabs, dialogs, alert dialogs, and Toasts preserve
  their documented ARIA anatomy, keyboard navigation, generated relationships,
  hidden inputs, focus entry/containment/restoration, dismissal, and disabled
  behavior.
- Portaled content stays in the trigger's owner document, inherits the intended
  theme, escapes overflow clipping, and flips/slides within viewport bounds.
- Current async identity/generation fences remain effective across route
  changes, close/reopen, unmount, and stale success/error completion. No stale
  continuation changes a later resource, widget, dialog, navigation, or Toast.
- Focused and complete frontend gates pass under Solid's development runtime
  with zero Solid diagnostics. Production and inspection builds pass, and the
  lockfile has no mixed Solid family or loopback registry URL.
- Chrome verification shows no unintended visual, focus, interaction, or
  accessibility regression across the restored surfaces. The final worktree is
  left for human verification without an implementation commit unless the
  human explicitly requests one.
- No Canvas, AI Chat public-package runtime, backend, database schema, RPC,
  durable authority, or public package version change is introduced.

## NOTES

- S153's plan already named `@kobalte/core@2.0.0-alpha.0` in the coherent
  Solid 2 RC.0 ecosystem set. This task corrects the implementation choice to
  replace Kobalte with owned primitives; it does not reopen the Solid 2 cut.
- The roughly 1,929 additions/717 deletions across the 18 compared files are
  not a removal target by themselves. Much of that code is legitimate Solid 2,
  request-fencing, and product behavior. Delete only duplicated primitive
  mechanics proven to be owned by Kobalte.
- Kobalte is private frontend infrastructure here. Adding it back does not
  justify a public package version bump.
- The public Kobalte website documents the Solid 1 line. Use the local Solid 2
  authority first and the audited upstream `solid2` branch only when an exact
  prop is absent.
