# S150 - widgets: make selected text copyable by default
[Overview](../BASED.md)

Remove the surprising non-copyable-text default from AI-created Capsule
widgets. Request Capsule's bounded plain-text clipboard authority in new
widget scaffolds and rebuild the affected Click Counter draft with that exact
manifest contract.

## Context

The supplied Preview shows a real browser selection inside **Click Counter**,
but copying the selected words produces no clipboard text. This is not a
Canvas shortcut collision:

- Capsule deliberately separates mutable text selection under `DOM` from
  plain-text copy, cut, and paste under `CLIPBOARD`; see
  [`docs/internal/llm.capsule.md`](../../docs/internal/llm.capsule.md).
- Omnidraw admits the complete Capsule API-group registry at the host ceiling,
  but [`CONSTANTS.ts`](../../apps/backend/src/shell/widget-runtime/contract/CONSTANTS.ts)
  currently sets `OMNIDRAW_CAPSULE_AUTHORING_APIS` to only `DOM`.
- [`fn.widget-create.ts`](../../apps/backend/src/shell/agent/tools/fn.widget-create.ts)
  copies that narrow default into every generated `omnidraw.json`.
- [`browser-host.ts`](../../packages/sdk/src/internal/browser-host.ts) correctly
  mounts the exact signed API subset declared by the artifact. It must not
  silently widen a `DOM`-only widget or bypass Capsule's clipboard boundary.
- [`Canvas.tsx`](../../packages/canvas/src/components/Canvas.tsx) does not
  cancel modified shortcuts such as `Cmd/Ctrl+C`, and
  [`CanvasExtensionBridge.ts`](../../packages/canvas/src/internal/CanvasExtensionBridge.ts)
  contains widget keyboard events without preventing their browser default.

Capsule's current `CLIPBOARD` group couples copy, cut, and paste. This task
makes an explicit product-policy choice to include that bounded plain-text
authority in the default authoring scaffold so ordinary selected widget text
behaves like ordinary selected browser text. Existing signed artifacts do not
gain the authority automatically and must be edited, validated, and rebuilt.

## Plan

![Selected Click Counter text that cannot currently be copied](S150.webp)

### 1. Change the authoring default

- Change `OMNIDRAW_CAPSULE_AUTHORING_APIS` from `['DOM']` to
  `['DOM', 'CLIPBOARD']`, preserving Capsule's canonical group order.
- Keep `OMNIDRAW_CAPSULE_ALLOWED_APIS` as the host admission ceiling and keep
  `browser-host.ts` mounting only the artifact's declared subset.
- Update the existing scaffold expectations and fixtures affected by the new
  generated manifest. Do not add a new regression-test case or test suite.
- Do not add a host clipboard listener, call `navigator.clipboard` on behalf of
  the guest, synthesize copy events, or add widget-specific JavaScript copy
  handlers. Capsule already projects the selected plain text when the signed
  group is present.

### 2. Make the authority discoverable to AI authors

- Update the Capsule authoring prompt to state plainly that `DOM` makes text
  selectable while `CLIPBOARD` is required for copy, cut, and paste.
- Tell the model to preserve the scaffolded `CLIPBOARD` group for ordinary UI
  unless the user explicitly requests a narrower non-copyable artifact.
- Keep clipboard access described as bounded plain text. Do not imply ambient
  `navigator.clipboard`, rich clipboard data, files, or images are exposed.

### 3. Repair and verify the affected draft

- With the backend running, use the supported `omnidraw widget` CLI to resolve
  the exact Click Counter draft. Do not open catalog storage directly.
- Add `CLIPBOARD` to its `omnidraw.json`, run host-owned validation, and inspect
  the accepted Preview using the validation result's exact digest, generation,
  and build identity.
- Manually select text in the Preview and verify `Cmd/Ctrl+C` copies the exact
  plain text into a trusted field outside the widget. Check the browser context
  menu copy path as well.
- Run the existing scaffold test and backend typecheck needed to catch stale
  expectations. No new regression tests are required.

## Acceptance criteria

- Newly scaffolded plain-DOM and React widgets declare
  `ui.apis: ["DOM", "CLIPBOARD"]` in canonical order.
- Selected ordinary text in the rebuilt Click Counter Preview copies as exact
  plain text with `Cmd/Ctrl+C` and the browser context-menu action.
- The Canvas host neither intercepts the copy nor widens an artifact's signed
  API request.
- Existing `DOM`-only artifacts remain unchanged and fail closed until their
  manifest is intentionally edited, validated, and rebuilt.
- Authoring guidance accurately distinguishes selection from clipboard
  authority and does not promise rich or ambient clipboard access.
- No new regression tests or test suites are added for this change.

## NOTES

- This is a subtraction because it removes the product's hidden non-copyable
  authoring default and avoids custom host or guest clipboard workarounds.
- Granting `CLIPBOARD` currently grants bounded plain-text copy, cut, and paste
  together; Capsule 0.16.0 does not expose a copy-only group.
- The current Click Counter manifest was not inspected during planning because
  the backend was not running. Resolve it through the supported CLI before
  editing and treat `DOM`-only as a hypothesis until confirmed.
- The supplied 792×866 PNG was stored as a 29,372-byte lossless WebP.
