# S136 - widgets: switch runtime authority to files and delete widget control tables

[Overview](../BASED.md)

Make the scanned filesystem catalog authoritative for widget discovery,
placement, and runtime loading, then remove the database widget control plane.

## Context

[A108](../a/A108.md) defines portable contracts and [A109](../a/A109.md)
builds the filesystem edge. This task changes product authority and deletes
the superseded widget, release, artifact, Preview, binding, and group code.

Canvas persistence stays one `canvas_items` row per authored Cangine node.
`CanvasService` remains the only durable canvas authority, and
`WidgetStateService` remains the only widget-instance state authority.

## Plan

### 1. Switch reads and writes

- Build the startup catalog only from validated published folders.
- Resolve placement and runtime mounts by `widgetKey`.
- Keep `instanceId`, geometry, resource choices, and state stable when the
  current publication changes.
- Render a missing-widget frame without deleting canvas data.

### 2. Reshape canvas and state

- Replace definition/revision fields in `canvas_items` with generated
  `widget_key` and stable `widget_instance_id` lookup fields.
- Rekey `widget_instance_states` to `(canvas_id, element_id)`, keep
  `instance_id` unique, and verify item identity before state access.
- Move concrete local resource choices into canvas item data.

### 3. Delete the old control plane

- Delete the 14 widget/revision/artifact/instance/binding/group/draft/Preview
  tables named in the design report.
- Remove their stores, services, events, recovery jobs, artifact GC, API
  handlers, fixtures, exports, and compatibility reads.
- Leave schema file consolidation to [S135](./S135.md); do not add a migration.
