# S92 - dropped: preserve or upgrade pre-cutover databases
[Overview](../BASED.md)

Dropped. Vibecanvas has no customers on the Automerge database format, so the
CanvasService cutover is a hard cutoff.

## Fixed decision

- Do not migrate or preserve v0.4.7 Automerge canvas data.
- Do not add an upgrade fixture, compatibility reader, dual-write path, export
  flow, or migration warning.
- Do not retain the old migration prefix as a supported production input.
- A fresh current database is the only supported database shape.
- Development databases from before the cutoff may be deleted manually when
  needed; product code does not detect or repair them.

## Result

The former S92 plan was based on a nonexistent customer-upgrade obligation. Its
proposed v0.4.7 preservation tests, migration-history immutability work, and
upgrade path must not be implemented.

Current migration code may continue to reject incompatible databases. That
rejection is a safety invariant, not a promise to guide or migrate users.
