# S134 - release 0.5.0: remove binary distribution, normal build, docs and CI cleanup
[Overview](../BASED.md)

Prepare the repository for the 0.5.0 library release. The compiled `omnidraw`
binary distribution (build, signing, npm wrapper app, GitHub release pipeline,
self-upgrade) is removed entirely. `bun run build` becomes a normal workspace
build. The `@omnidraw/*` library packages keep the existing manual local
publish flow; the app is no longer published anywhere. Outdated docs and dead
scripts are deleted; all test gates stay.

## Context

Release 0.5.0 ships only the `@omnidraw/*` library packages (already public at
0.5.0 per [AGENTS.md](../../AGENTS.md) published-package policy). The binary
CLI distribution is discontinued.

Decisions (confirmed with maintainer):
- Binary distribution: **delete everything binary** (scripts, wrapper app, CI
  workflow, CLI self-upgrade).
- Root `bun run build`: **build all workspace packages** (normal tsc/vite
  builds, canvas kernel first).
- npm deploy: **libraries publish manually** from a maintainer machine via the
  existing `deploy:packages:list` flow; the app is not published. CI verifies
  only, no publish workflow.
- Script cleanup: **keep everything test-related**; delete only clearly dead
  scripts and the binary machinery.

## Plan

### 1. Normal build

- Root `build`: `bun run build:canvas-kernel && bun run --filter '*' build`
  (kernel first for ordering, then every workspace package with a build
  script: tsc libraries + vite frontend).
- Keep `prebuild` / `build:canvas-kernel` (still used by dev/test).
- Delete root scripts: `build:single`, `prebuild:single`,
  `verify:turso-native-encryption`, `verify:turso-native-encryption:host`,
  `publish:npm`, `release:github`, `test:binary`, `test:upgrade:local`.

### 2. Delete binary machinery

- Delete files: `scripts/build.ts`, `scripts/publish-npm.ts`,
  `scripts/release.ts`, `scripts/release-channel.ts`, `scripts/release.test.ts`,
  `scripts/install.sh`, `scripts/test-binary.ts`,
  `scripts/test-local-upgrade.ts`, `scripts/omnidraw.entitlements.plist`.
- Delete `apps/omnidraw/` entirely; run `bun install` to regenerate the
  lockfile.
- Remove CLI self-update: `cmd.upgrade.ts`, `check-update.ts`,
  upgrade/uninstall wiring in parse-argv/config/CliPlugin/
  fn.print-command-result, and the cli-update tests; fix affected CLI tests.

Keep everything else in `scripts/`: all `test-*.ts` gates, boundary

- `scripts/test-final-acceptance.ts`: drop the binary gate, keep the rest.
- `scripts/tsconfig.architecture.json`: drop `test-binary.ts`.

### 5. npm deploy strategy (documented, no new CI)

Libraries `@omnidraw/*` publish manually from a maintainer machine: bump the
package `version` on `src/` changes per AGENTS.md policy, `bun run build`
stages standalone `dist/` (via `scripts/prepare-package-dist.ts`),
`npm publish ./dist --access public`. `bun run deploy:packages:list` shows
what needs publishing. The app is not published. CI verifies only
(`test:final-acceptance`, `verify:package-dists`). No publish workflow, no
changesets.

- npm pre-checks in the old release workflow listed darwin-x64 and musl
  packages that `build.ts` never produced - stale; moot after deletion.
- `verify:turso-native-encryption*` root scripts only invoked flags of the
  deleted `scripts/build.ts`; native encryption still works at runtime via the
  pinned `@tursodatabase/database` addon, so no replacement is added.
- `docs/internal/llm.capsule.md` has relative links into the external capsule
  repo (`./public-api.md`, `./CAPSULE.md`, `./api-groups-v1.generated.md`) that
  do not exist in `docs/internal/` - noted, not fixed here.
- Full verification exposed stale acceptance assertions left behind by earlier
  repository changes. They now reflect the current package versions, Preview
  persistence boundary, function revision identity, and intended default OSS
  tenant-scope consumers.
