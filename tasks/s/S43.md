# S43 - canvas: normalize clone-drag through CloneService
[Overview](../BASED.md)

Centralize repeated clone-drag session mechanics in `CloneService` so element and group plugins only own type-specific cloning details.

## Context
Clone-drag is currently hand-rolled across multiple canvas element types. The repeated shape is:

- create a preview clone
- move it to `scene.dynamicLayer`
- start Konva drag
- handle `dragend`
- stop drag safely
- move the clone to `scene.staticForegroundLayer`
- attach runtime listeners
- persist CRDT create ops
- assign render order
- update selection/focused node
- redraw dynamic/static layers
- sometimes record undo/redo history

The intended normalization point already exists but is empty:

- [`packages/canvas/src/services/clone/CloneService.ts`](../../packages/canvas/src/services/clone/CloneService.ts)

Primary duplicated implementations to shrink:

- [`packages/canvas/src/plugins/shape2d/tx.create-clone-drag.ts`](../../packages/canvas/src/plugins/shape2d/tx.create-clone-drag.ts)
- [`packages/canvas/src/plugins/image/tx.create-image-clone-drag.ts`](../../packages/canvas/src/plugins/image/tx.create-image-clone-drag.ts)
- [`packages/canvas/src/plugins/text/tx.create-text-clone-drag.ts`](../../packages/canvas/src/plugins/text/tx.create-text-clone-drag.ts)
- [`packages/canvas/src/plugins/pen/tx.clone.ts`](../../packages/canvas/src/plugins/pen/tx.clone.ts)
- [`packages/canvas/src/plugins/shape1d/tx.runtime.ts`](../../packages/canvas/src/plugins/shape1d/tx.runtime.ts)
- [`packages/canvas/src/services/group/tx.create-group-clone-drag.ts`](../../packages/canvas/src/services/group/tx.create-group-clone-drag.ts)

This task is narrower than the broader service migration in S42. Do not use this as a reason to rewrite unrelated element registration, selection, transform, or render-order code.

## Plan
### 1. Inventory current clone semantics
Compare clone behavior for shape2d, image, text, pen, shape1d, and group.
Record which implementations currently create history records and which only commit CRDT state.
Check whether each flow preserves z-index, parent group, backend assets, attached text, and runtime listener setup.

### 2. Define the common clone session contract
Add a shared transaction/helper, likely named `txCreateCloneDragSession`, owned by `CloneService` or a sibling `tx.*.ts` file under `services/clone`.
Keep type-specific work injected through callbacks:

- create preview clone
- finalize clone metadata
- serialize clone to `TElement` or `TGroup` payloads
- attach listeners
- commit extra side effects such as backend image cloning
- recreate clone for redo, where history is supported

### 3. Wire `CloneService`
Make `CloneService` a real runtime service if needed by the helper.
Provide only shared clone session behavior; do not move element-specific serialization or rendering into it.
Prefer portal/callback injection over direct plugin imports to avoid dependency cycles.

### 4. Migrate implementations incrementally
Start with the simplest element clone path first, likely text or pen.
Then migrate shape1d and shape2d.
Migrate image after preserving backend file clone behavior.
Migrate group last because it clones a subtree and persists both groups and elements.

### 5. Verify behavior and remove old duplication
Keep public behavior identical:

- alt-drag starts a clone instead of moving the original
- clone follows pointer on dynamic layer while dragging
- clone lands on static foreground layer
- clone becomes selected and focused
- undo/redo still works wherever it worked before
- image clone still duplicates backend image asset when supported
- group clone still re-ids the whole subtree

## NOTES
- Keep `fn.*`, `fx.*`, and `tx.*` file rules intact. The shared clone helper will mutate Konva layers, CRDT, selection, and history, so it belongs in `tx.*.ts`, not `fn.*.ts`.
- Image clone has special backend asset cloning via `txCloneBackendFileForElement`; keep that as an injected side effect.
- Group clone persists both `TGroup[]` and `TElement[]`; do not force it through a single-element API if that makes the helper awkward.
- Some clone implementations currently record history and some do not. Preserve existing behavior first, then normalize history behavior in a separate deliberate pass if desired.
