# S135 - db: rewrite the single-user Turso baseline and remove identity scope

[Overview](../BASED.md)

Replace the current migration history with one clean 14-table Turso baseline
for the undeployed single-user application.

## Context

The authoritative schema is the Target database section of
[widget-filesystem-design.md](../../docs/internal/widget-filesystem-design.md).
The current schema has 39 tables. The target keeps 14 and removes 25.

There is no deployed database to preserve. Do not add migration 007, an export
tool, compatibility views, dual writes, or a data copier.

## Plan

### 1. Rewrite the baseline

- Replace `000-initial.sql` with the final 14-table schema.
- Fold any retained constraints from migrations 001-006 into 000, then remove
  those obsolete migration files.
- Keep `@omnidraw/service-db` private and unversioned.

### 2. Make persistence single-user

- Delete `accounts`, `organizations`, `organization_memberships`, and
  `canvas_members`.
- Remove `org_id`, `account_id`, access policy, role, membership, owner,
  invite, and seat keys from all retained tables, stores, services, tests, and
  contracts.
- Rename `agent_chats` and its store/API vocabulary to `chats`.

### 3. Use the current Turso type system

- Keep every application table `STRICT`.
- Use `TIMESTAMP` for UTC whole-second wall-clock values and rename wall-clock
  `*_ms` fields to `*_sec`.
- Use `CURRENT_TIMESTAMP` defaults, explicit update timestamps, `JSONB`,
  `BOOLEAN`, useful domains, and generated columns.
- Keep interval fields such as `timeout_ms` as integer durations.

### 4. Regenerate schema authority

- Regenerate embedded migrations, expected schema, fingerprints, fixtures, and
  schema documentation.
- Reject old local database fingerprints with an explicit development-reset
  message.
- Pin exact table, column, foreign-key, index, type, and generated-column tests.
