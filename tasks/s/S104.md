# S104 - remove filesystem service, API, canvas plugin, and SQL table
[Overview](../../BASED.md)

Remove the full filesystem stack: server service, API domain, canvas plugin, client helpers, package, SQL table, and tests. Edit the existing SQL file directly (no new migration — nothing deployed yet).

## Context

`file_systems` is actively used (unlike `pty_session_metadata` which is dead schema). Every `vibecanvas serve` boot registers `config.cwd` as an API-accessible filesystem capability. The API permits operations relative to that root.

| Area | Current state |
|---|---|
| Database | Active. `file_systems` has real repository reads/writes in `DbServiceTurso`. |
| Server service | Active. `FilesystemServiceNode` registers a host root, performs reads/writes/moves, and maintains filesystem watches. |
| CLI boot | Active. `FilesystemPlugin.ts` creates a "Local Workspace" database record and binds it to `config.cwd` on boot. |
| API | Active. `packages/api/src/filesystem/contract.ts` exposes listing, tree traversal, read, write, move, inspect, and watch operations over oRPC. |
| Canvas | UI-disabled but retained. `runtime.ts` comments out `createFilesystemPlugin()`, while the full widget remains under `plugins/filesystem`. |
| Frontend | A path-picker component still calls `api.filesystem`, but the source scan found no caller of that component. |
| PTY | Depends on filesystem authority for its working directory and image uploads, so remove both together. |

## Plan

### Step 1: Remove server service and CLI composition

- Delete `packages/service-filesystem/src/FilesystemServiceNode.ts` and `IFilesystemService`.
- Delete `packages/service-filesystem` package.
- Remove `FilesystemPlugin.ts` and its registration in `main-app.ts`.
- Remove CLI service construction/registration from `setup-services.ts`.

### Step 2: Remove API domain

- Delete `packages/api/src/filesystem/`.
- Remove root API contract, handlers, context intersections, package exports/dependencies.
- Remove filesystem injection from `OrpcPlugin.ts`.

### Step 3: Remove dormant client/UI code

- Delete `packages/canvas/src/plugins/filesystem/`.
- Remove exports, toolbar type remnants.
- Remove the unused frontend path-picker component/styles after confirming no dynamic use.
- Remove filesystem-specific clipboard upload support in `@vibecanvas/orpc-client`.

### Step 4: Remove related event/watch plumbing

- Filesystem event publication/subscription/cursor methods in `service-event-publisher` become unused after the service is gone.
- Remove filesystem isolation, API, setup, plugin, and service tests; update the aggregate isolation script and root test filter.

### Step 5: Remove state and schema

- Delete the `file_systems` repository/model and its initial boot record.
- Edit the existing SQL file directly to remove the `file_systems` table (no new migration — nothing has been deployed yet).
- The migration must also remove `pty_session_metadata` and rebuild/remove the legacy actor `file_system_id` foreign-key/column path, because both reference `file_systems`.
- Update embedded migration registration, expected schema, schema constraints, recovery/binary tests, and the recorded migration identity.
