# S124 - packages: remove deleted-package residue and stale docs
[Overview](../BASED.md)

Clear local residue from already-deleted packages and make current package
documentation match the repository.

## Context

The package audit found one tracked workspace package with no current consumer:

- [`packages/service-kv`](../../packages/service-kv) declares
  `@vibecanvas/service-kv`, but no workspace manifest depends on it and no
  runtime or test source imports it.
- Its only repository-level integration is the root `test` filter.
- This package is intentionally reserved for planned service work and must be
  kept even while it is unused.

The audit also found ignored directories left behind by completed subtraction
tasks:

- `packages/service-automerge`
- `packages/service-pty`
- `packages/service-filesystem`
- `packages/service-actor`
- `packages/actor-ui`
- `packages/ui-actor-legacy`

These directories have no tracked source or package manifest. They contain
only build metadata, installed dependencies, or nothing. The corresponding
implementations were removed by [`S103`](S103.md), [`S104`](S104.md),
[`S107`](S107.md), and [`S116`](S116.md).

Current documentation still lists `service-actor` and `ui-actor-legacy` as
live packages. Some internal baseline documents also describe the retired
actor packages in the present tense. Historical task records should remain
intact because they explain why the code was removed.

## Plan

### 1. Preserve the planned KV service

- Keep [`packages/service-kv`](../../packages/service-kv), its package
  manifest, source, types, TypeScript configuration, lockfile entry, and root
  test filter.
- Keep `service-kv` in the package map and document that it is reserved for
  planned service work.
- Do not treat lack of a current consumer as sufficient reason to delete this
  package.

### 2. Clear deleted-package residue

- Remove the ignored local directories for `service-automerge`, `service-pty`,
  `service-filesystem`, `service-actor`, `actor-ui`, and `ui-actor-legacy`.
- Confirm no tracked source, manifest, generated index, or lockfile entry
  treats any of them as a live package.
- Keep architecture tests that intentionally forbid imports from retired actor
  packages; those assertions protect the subtraction and are not dead package
  usage.

### 3. Correct current documentation

- Remove retired packages from the package map in
  [`AGENTS.md`](../../AGENTS.md).
- Update current internal architecture and baseline documentation that claims
  `service-actor` or `ui-actor-legacy` still exists.
- Where a baseline must retain historical evidence, label it explicitly as a
  pre-removal snapshot instead of presenting it as the current architecture.
- Do not rewrite completed task files merely because they mention the deleted
  packages.

### 4. Verify the smaller workspace

- Search manifests, source, scripts, lockfiles, and current documentation for
  stale live-package references.
- Run the architecture boundary tests.
- Run the root test command or, if that is too broad for the change, every
  package test affected by root workspace discovery plus the architecture
  suite.
- Confirm Bun workspace discovery retains `service-kv` and succeeds without
  the ignored residue directories.

- Workspace discovery and the relevant test suites pass.

## NOTES

- No mockup is needed because this task has no user-interface change.
- The ignored residue is not part of Git, but removing it prevents local tools

- `service-kv` is the only declared package found without an inbound workspace
  dependency or source import. This is intentional: the package is kept for
  planned work. All other declared packages have at least one workspace
  consumer.
