# S66 - ai wizard: cap chat input height
[Overview](../../BASED.md)

Limit the AI wizard chat composer input height so large pasted text scrolls inside the input instead of breaking the layout.

## Context

The problem is in [`packages/canvas/src/components/AiWizzard/tabs/ChatTab.tsx`](../../packages/canvas/src/components/AiWizzard/tabs/ChatTab.tsx), where the chat tab renders [`ChatComposer`](../../packages/canvas/src/components/AiWizzard/ChatComposer/ChatComposer.tsx).

The visible layout styles live in [`packages/canvas/src/components/AiWizzard/index.css`](../../packages/canvas/src/components/AiWizzard/index.css), especially:
- `.ai-chat-composer`
- `.ai-chat-composer__body`
- `.ai-chat-composer__editor-root`
- `.ai-chat-composer__editor`

Current risk: pasting a very large prompt can make the ProseMirror/contenteditable input grow without a useful cap. This can push or distort the chat layout. Desired behavior: the input area has a maximum height and shows a vertical scrollbar for overflowing pasted content.

## Plan

### 1. Confirm composer DOM ownership

- Inspect `ChatComposer.tsx` to confirm which element owns the editable content and whether ProseMirror adds nested editor nodes.
- Confirm whether the max height belongs on `.ai-chat-composer__body`, `.ai-chat-composer__editor-root`, `.ai-chat-composer__editor`, or a nested ProseMirror class.

### 2. Add CSS-only layout cap first

- Prefer a CSS-only fix in `index.css` unless DOM structure prevents it.
- Add a max height to the actual scroll container.
- Add `overflow-y: auto` so large pasted text scrolls.
- Keep existing minimum height and focus styling.
- Ensure horizontal overflow does not appear for long lines: keep wrapping behavior or add `overflow-wrap: anywhere` if needed.

### 3. Preserve chat tab layout

- Verify the composer remains at the bottom of `ChatTab.tsx` and does not consume the whole sidebar height.
- Check interaction with image attachments and controls below the editor.
- Decide if only the editor should scroll, or if editor + attachments should be capped together. Preferred: text editor scrolls; controls stay visible.

### 4. Add/adjust render test if practical

- Existing tests for this area are in [`packages/canvas/tests/components/AiWizzard/tabs/ChatTab.render.test.ts`](../../packages/canvas/tests/components/AiWizzard/tabs/ChatTab.render.test.ts).
- JSDOM cannot prove real layout height well, but it can verify the relevant class is rendered.
- If there is a CSS test harness or snapshot pattern, add coverage for the max-height/overflow rule. Otherwise rely on manual verification.

### 5. Manual verification

- Open the AI wizard chat tab.
- Paste a large multi-paragraph prompt.
- Expected: input area stops growing at the chosen max height and shows a vertical scrollbar.
- Expected: send/cancel/model/action controls remain visible.
- Expected: chat history remains usable and no sidebar/page layout break occurs.
