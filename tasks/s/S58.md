# S58 - widget SDK bridge: sandbox-local reactive actor proxy
[Overview](../../BASED.md)

Design and implement the widget SDK so guest code only imports `actor` from `@vibecanvas/sdk/widget`, while host bridge code supplies serialized actor snapshots and message calls.

## Context

We are building actor-backed generative widgets. Guest widget code should stay simple:

```ts
import { actor } from '@vibecanvas/sdk/widget'

actor.state.value
actor.context.value
await actor.sendMessage('in.addTodo', { title: 'New' })
```

Relevant files:

- `packages/sdk/src/widget.ts`
  - Public sandbox-side widget SDK entrypoint.
  - Should stay tiny and author-facing.
- `packages/sdk/src/widget-bridge.ts`
  - Internal bridge wiring for host-provided snapshots and send calls.
  - Should hold bridge TODOs and implementation details.
- `packages/canvas/src/services/widget/tx.mount-arrow-sandbox.ts`
  - Injects `@vibecanvas/sdk/widget` into Arrow sandbox source.
  - Rewrites guest imports to `/__vibecanvas_sdk.js`.
- `packages/api-actors/src/contract.ts`
  - Actor API already has definition APIs and actor instance snapshot API:

```ts
const actorsContract = oc.router({
  definitions: {
    list: oc.output(ZActorDefinition.array()),
    get: oc.input(z.object({ name: z.string() }))
      .output(ZActorDefResponse),
    events: oc
      .input(z.object({}))
      .route({ method: 'GET' })
      .output(eventIterator(ZActorEvent)),
  },
  instances: {
    snapshot: oc
      .input(z.object({ instanceId: z.string() }))
      .output(ZActorSnapshot)
  }
});
```

Missing pieces for full runtime:

- API for actor `sendMessage`.
- Event system to inform a widget sandbox when actor state/context changes.
- Real host bridge implementation for `@arrow-js/sandbox`.

These missing pieces can be mocked initially. The first goal is the SDK architecture: sandbox-local Arrow reactivity that can be driven by serialized host snapshots.

## Plan

### 1. Keep guest SDK tiny

`packages/sdk/src/widget.ts` should expose only:

- `actor.state.value`
- `actor.context.value`
- `actor.sendMessage(name, payload)`

No `defineWidget`. No guest-visible `host-bridge:*` imports. No canvas element APIs for now.

### 2. Bridge uses serialized values only

Host cannot transfer real reactive objects/functions into QuickJS. The SDK module loaded inside the sandbox owns Arrow `reactive()` refs. Host bridge calls pass serialized snapshots and message payloads.

Flow:

```txt
host actor instance
  -> serialized snapshot
  -> sandbox SDK bridge
  -> mutate sandbox-local actor.state/context refs
  -> Arrow template rerenders
```

### 3. Hide host bridge from guests

Guest imports only:

```ts
import { actor } from '@vibecanvas/sdk/widget'
```

Host/sandbox setup rewrites that to injected SDK source. The injected SDK may internally call private bridge functions, but the guest must not import `host-bridge:*` directly.

### 4. Implement initial snapshot first

Use existing `instances.snapshot` API or a mock equivalent to provide initial:

```ts
{
  state: string,
  context: unknown,
}
```

Bridge applies it to sandbox-local `actor` refs.

### 5. Mock send and event stream initially

Until API exists:

- `sendMessage` can call a mocked host function and log payloads.
- Snapshot updates can be manually pushed or mocked.

Later replace with:

- `actors.instances.sendMessage`
- long-poll or event stream for actor snapshot updates.

## NOTES

- Arrow reactivity must live inside the sandbox. Host-owned reactive objects do not cross into QuickJS.
- Bridge values should be JSON/structured-clone safe: strings, numbers, booleans, null, arrays, plain objects.
- Do not pass DOM nodes, class instances, services, Automerge handles, Konva nodes, or callbacks as values.
- Host bridge functions are real host functions, but guest code should call them only through the SDK proxy.
- Long-poll design is likely simplest for updates:

```txt
sandbox SDK calls nextActorEvent(cursor)
host holds promise
actor snapshot changes
host resolves with { cursor, type: 'snapshot', snapshot }
sandbox SDK mutates actor refs
sandbox SDK calls nextActorEvent(cursor) again
```
