# S88 - extract AI Chat, widgets, and sidebar from canvas
[Overview](../BASED.md)

Create `@vibecanvas/ai-chat` as an independently testable frontend/runtime package. Move the AI Chat UI, the AI canvas widget, the generic widget host/runtime, and the workspace sidebar out of `@vibecanvas/canvas`; invert canvas composition so canvas has no dependency on AI Chat and no direct ownership of widget transport/browser effects.

## Context

The current ownership is spread across two packages and makes `@vibecanvas/canvas` carry most of the AI/widget dependency graph:

- [`packages/canvas/src/components/AiChat`](../../packages/canvas/src/components/AiChat) owns chat connection, event streaming, approvals, provider settings, Markdown rendering, ProseMirror composition, attachments, model/thinking selection, and chat CSS.
- [`packages/canvas/src/plugins/ai/Ai.plugin.ts`](../../packages/canvas/src/plugins/ai/Ai.plugin.ts) registers the AI widget, creates/clones chat identity, mounts Solid, and persists AI preferences into the canvas document.
- [`packages/canvas/src/services/widget`](../../packages/canvas/src/services/widget) owns generic widget nodes, DOM portals, title-bar actions, fullscreen/minimize behavior, actor event routing, Arrow sandbox mounting, clone/delete/history behavior, widget loading/error states, and tool registration.
- [`packages/canvas/src/plugins/widget/Widget.plugin.ts`](../../packages/canvas/src/plugins/widget/Widget.plugin.ts) discovers and reloads published widget definitions.
- [`packages/canvas/src/runtime.ts`](../../packages/canvas/src/runtime.ts) constructs `WidgetManagerService` and statically installs both AI and widget plugins. This prevents canvas from being built or tested as a canvas-only runtime.
- [`apps/frontend/src/feature/sidebar`](../../apps/frontend/src/feature/sidebar) owns the workspace sidebar and its canvas/resource/tool-group dialogs. It directly imports frontend router, stores, ORPC singleton, Automerge cache, theme singleton, toast singleton, browser events, and a canvas toolbar constant.
- [`apps/frontend/src/pages/canvas.tsx`](../../apps/frontend/src/pages/canvas.tsx) couples AI resource refresh to the sidebar through a global `RESOURCE_CATALOG_CHANGED_EVENT`.
- [`packages/canvas/package.json`](../../packages/canvas/package.json) consequently owns Arrow sandbox, actor API/service, ProseMirror, Markdown, and AI-facing UI dependencies even when only the drawing runtime is wanted.

Current tests to relocate include:

- [`packages/canvas/tests/components/AiChat`](../../packages/canvas/tests/components/AiChat)
- [`packages/canvas/tests/services/widget`](../../packages/canvas/tests/services/widget)
- AI/widget portions of the runtime and scene-hydrator integration tests

The package is not isolated today even though `apiService` is passed in. AI/widget code still directly accesses `console`, `Date`, `crypto`, `document`, `window`, timers, `URL.createObjectURL`, `FileReader`, and `navigator.clipboard`. The sidebar additionally performs navigation, API calls, store mutation, cache mutation, theme mutation, notifications, and global event dispatch itself.

This extraction must preserve the active product behavior established by [S83](S83.md) and [S84](S84.md). It must not accidentally hide or “fix” the reconnect race tracked by [B49](../b/B49.md). [A76](../a/A76.md) should build its version-aware Widgets catalog in the extracted sidebar/widget package rather than regrowing the frontend or canvas package.

## Fixed decisions

### Package ownership

Create:

```text
packages/ai-chat/
  package.json
  tsconfig.json
  vitest.config.ts
  src/
    index.ts
    chat/
    canvas-extension/
    widget/
    sidebar/
  tests/
    chat/
    canvas-extension/
    widget/
    sidebar/
```

`@vibecanvas/ai-chat` owns:

1. The complete AI Chat Solid surface and styles.
2. AI chat session/preference identity and the AI `ui-widget` registration.
3. Generic widget host/portal/runtime code currently under canvas `services/widget`.
4. Published widget discovery/reload currently under canvas `plugins/widget`.
5. Widget title-bar contracts used by AI Chat.
6. The complete workspace sidebar and its dialogs/styles, including Tool Group and resource creation UI.
7. `ToolIconPicker`, because its only current consumer is the sidebar Tool Group dialog and it uses widget manifest icon contracts.
8. The moved AI/widget/sidebar tests and package-local test portals.

`@vibecanvas/canvas` continues to own drawing geometry, Konva scene/runtime services, element registration, CRDT/history, selection/transform, toolbar rendering, and the generic runtime-extension seam. It must not import `@vibecanvas/ai-chat`.

The temporarily disabled filesystem and terminal widget implementations remain in canvas for this task unless they are first re-enabled. They may compile against the new public widget extension API, but S88 must not silently enable, delete, or redesign them; [S62](S62.md) and [S63](S63.md) remain their product tasks.

### Dependency direction and composition

Use this one-way graph:

```text
frontend -> ai-chat -> canvas -> runtime/core services
frontend ------------> canvas
canvas -X-> ai-chat
```

Add a public canvas extension contract rather than importing AI code from `runtime.ts`. The exact names may follow repository conventions, but the seam must support:

- extension service construction from the already-created canvas services;
- extension plugins appended at deterministic points before scene hydration;
- extension startup/shutdown cleanup;
- an element-definition invalidation hook so late widget definitions can ask scene hydration to retry without a widget-specific hook in canvas;
- typed extension configuration without adding AI API fields back to base `IRuntimeConfig`.

`Canvas`/`buildRuntime` accept an injected list or factory of extensions. The frontend imports `createAiChatCanvasExtension(...)` from `@vibecanvas/ai-chat` and passes it to canvas. Core canvas tests construct no AI extension by default. AI package integration tests construct canvas plus the extension.

Do not create a package cycle through type-only imports. AI Chat may depend on the public canvas extension/host contracts; canvas must expose only the minimum contracts needed and remain unaware of the concrete widget manager.

### Effect boundary

All environment and application effects used by the new package must enter through explicit, narrow portals/props. Do not pass one giant frontend service locator merely to hide global access.

Define package-owned ports for these capabilities:

- **AI agent API:** settings/auth, chat connect/prompt/cancel/new session, approval list/resolve, actor resource list, and agent events.
- **Published widget API:** definition list/get/delete and actor events/snapshots/messages needed by the widget sandbox.
- **Sidebar workspace API:** canvas CRUD, resource CRUD/list, tool-group CRUD/list, and widget catalog reads required by the current sidebar. Keep this compatible with A76 replacing the current N+1 widget-group read later.
- **Browser platform:** document/event target, UUID, clock/date formatting, timers, object URL create/revoke, file-to-data-URL reading, clipboard write, and resize observation where required.
- **Application shell:** navigation/current route, canvas collection updates, Automerge cache eviction, theme read/write, notifications/logging, sidebar visibility, resource/widget catalog invalidation.
- **Canvas widget host:** element registration, tools, CRDT writes, scene lookup/draw, selection, history, render order, context menu, confirm dialog, theme colors, camera, and lifecycle hooks exposed through the canvas extension context.

Pure mapping/parsing functions remain in `fn.*` files. Browser/API reads go through `fx.*`; external mutations go through `tx.*` where extraction creates or touches those files. Follow the repository function-file rules and inject every portal rather than accessing globals directly.

Production adapters live at composition edges:

- `apps/frontend` adapts router/store/theme/toasts/cache/ORPC/browser facilities to AI Chat and Sidebar ports.
- the canvas extension factory adapts canvas public services/hooks to widget host ports;
- tests use in-memory fake ports and controlled async iterators, clocks, IDs, files, clipboard, and timers.

### Sidebar scope

Move the whole existing sidebar feature, not only a resource subsection. Preserve Canvases, Resources, Tool Groups, theme toggle, visibility toggle, dialogs, route selection, and styling during extraction.

The package Sidebar must not import:

- `@/store`, `@/services/*`, or `@/components/ui/Toast`;
- `useNavigate`/`useLocation` directly;
- the ORPC singleton;
- canvas source-path constants;
- `window`/`document` event buses.

It receives state and operations through a typed sidebar controller/port. Replace `RESOURCE_CATALOG_CHANGED_EVENT` and the sidebar-to-toolbar `TOOL_GROUPS_CHANGED_EVENT` coupling with an injected typed invalidation channel/subscription. Canvas toolbar may retain a compatibility adapter during migration, but the package contract is not a stringly typed global event.

A76 remains a separate feature task. Update its referenced target paths/architecture notes after extraction so its provider, widgets hierarchy, and detail route work land under `packages/ai-chat/src/sidebar` (or a package-local widget catalog module), with only route adapters in `apps/frontend`.

### Behavior preservation

The move must preserve:

- chat history restoration and streaming reconciliation;
- exact widget/session scoping of events and approvals;
- model/thinking preference persistence in the canvas element;
- fresh session identity for created and cloned AI widgets;
- image attachments, mentions, Markdown, tool rows, cancellation, new chat, settings/auth, clipboard, and protected approval actions;
- AI settings title-bar action in contained and fullscreen widget modes;
- published Arrow widgets, loading/error recovery, actor event reconnect, clone/resize/group/delete/history behavior;
- sidebar navigation, CRUD dialogs, theme behavior, catalog refresh, and toolbar-group refresh;
- runtime boot/shutdown cleanup with no leaked iterators, timers, event listeners, object URLs, DOM portals, or Solid roots.

B49 is a prerequisite or coordinated lane for reconnect lifecycle changes. During S88, preserve exact request-generation behavior as-is unless implementing B49 explicitly; add moved regression coverage so extraction cannot make duplicate connections or approval cancellation harder to diagnose.

## Plan

### 1. Establish baseline and ownership inventory

- Run current canvas AI Chat/widget tests and frontend build/typecheck before moving files.
- Record the complete import graph for `components/AiChat`, `plugins/ai`, `plugins/widget`, `services/widget`, sidebar, ToolIconPicker, and their tests.
- Classify every dependency as canvas core, AI/widget/sidebar-owned, frontend adapter-only, or stale/unused.
- Record package size/dependency baselines so “slimmer canvas” is measurable by removed source paths and dependencies, not only file relocation.

### 2. Add a canvas-only extension seam

- Introduce public extension types and a deterministic extension install phase in canvas runtime composition.
- Remove AI-specific `apiService`, `onOpenResource`, and `onResourceCatalogChanged` requirements from base canvas runtime config; retain only capabilities genuinely needed by drawing/image/core runtime.
- Replace `widgetManager` as a required base runtime service with an extension-provided service.
- Replace `widgetRegister` with a generic element-definition invalidation mechanism used by scene hydration.
- Let `Canvas` accept extensions from the frontend and pass them to `buildRuntime`.
- Update the canvas test harness so core tests run without AI/widget setup and extension integration can be tested separately.

### 3. Scaffold `@vibecanvas/ai-chat` and define ports

- Add package metadata, explicit exports, Solid/Vite/Vitest setup, and only the dependencies actually owned by chat/widget/sidebar.
- Define narrow chat, widget transport, sidebar workspace, browser platform, application shell, and canvas host interfaces.
- Add production adapter factories without importing frontend aliases into the package.
- Add compile-time fixture/fake builders for isolated tests.
- Export stable public entrypoints such as the AI canvas extension, Sidebar, sidebar invalidation contract, and package CSS; keep internal helpers private.

### 4. Move and isolate AI Chat UI

- Move all files from `components/AiChat` and their tests.
- Inject chat/settings/approval/resource APIs instead of reading the broad ORPC client throughout components.
- Inject logging, file reading, clipboard, object URLs, IDs, date formatting, document listeners, and timers.
- Keep async iterator ownership explicit and close streams on disposal/reconnect.
- Preserve B49-relevant freshness checks and add deterministic tests with overlapping controlled connect promises.
- Keep UI components mostly declarative; place deterministic message/Markdown/tool/approval mapping in package-local pure functions.

### 5. Move the widget host and AI widget extension

- Move `services/widget`, `plugins/widget`, `plugins/ai`, and widget tests into package-local `widget` and `canvas-extension` modules.
- Convert `WidgetManagerService` construction to consume the canvas extension host plus injected browser/widget transport ports.
- Remove direct `document`, `window`, `crypto`, `Date`, timer, and `console` access from manager/plugin/sandbox orchestration.
- Keep existing `fn/fx/tx` boundaries and correct any direct global access exposed by the move, especially `fx.draw-host`, `fn.to-widget-element`, sandbox waits, clone IDs/timestamps, DOM portal creation, and listener timers.
- Register generic published widgets and the AI widget through the extension in the required order before scene hydration.
- Keep title-bar contracts package-owned so AI Chat no longer imports canvas widget internals.
- Preserve the raw SDK sandbox source loading and ensure build scripts resolve it from the new package.

### 6. Move and isolate Sidebar

- Move sidebar components, dialogs, styles, constants/contracts, and ToolIconPicker into the new package.
- Split route/store/API/browser orchestration from the rendered Sidebar through injected props/controller ports.
- Add frontend adapters that map current ORPC, router, store, Automerge cache, theme, toast, and route state into those ports.
- Replace global resource/tool-group events with a typed injected invalidation bus whose subscribe/unsubscribe behavior is testable.
- Update `App.tsx`, canvas/resource pages, and DB resource pages to use the package export and adapter invalidation methods.
- Preserve current behavior first; do not implement the broader A76 catalog UI inside this move.

### 7. Recompose frontend and remove old ownership

- Construct the AI canvas extension in `apps/frontend/src/pages/canvas.tsx` (or one frontend composition module) using ORPC, browser, navigation, notification, and invalidation adapters.
- Pass the extension to `Canvas`; keep canvas page concerned only with canvas/application composition.
- Import Sidebar from `@vibecanvas/ai-chat` and remove `apps/frontend/src/feature/sidebar` after all callers migrate.
- Remove old AI/plugin/widget exports, service-map entries, runtime construction, and source directories from canvas.
- Remove the canvas deep export used only by ToolIconPicker and stop frontend deep imports from canvas.

### 8. Slim dependencies and documentation

- Move ProseMirror and AI/widget-specific Arrow, actor API/service, icon, Markdown, and related UI dependencies to `packages/ai-chat/package.json` when no remaining canvas source imports them.
- Remove only dependencies proven unused from `packages/canvas/package.json`; account for disabled filesystem/terminal sources before removing shared Arrow/CodeMirror/terminal dependencies.
- Update canvas `AGENTS.md`/architecture to describe the canvas-only runtime and extension seam.
- Add a short AI Chat package guide documenting ownership, ports, composition, cleanup, and isolated-test setup.
- Update A76 and B49 file references after moves, regenerate `@FILES.md`, and update workspace test filters if the root test script should run the new package explicitly.

### 9. Verification and boundary enforcement

- Run package-local chat, widget, sidebar, and extension tests in jsdom with no frontend singleton setup.
- Run canvas tests without the AI extension to prove core isolation.
- Run focused canvas-plus-AI extension tests for create, hydrate, clone, settings title action, fullscreen, resource invalidation, published widget reload, and teardown.
- Add architecture tests or lint checks that reject imports from AI Chat into canvas and reject frontend aliases/singletons or unapproved runtime globals in the AI Chat package.
- Run affected typechecks, functional-core lint, canvas/ai-chat/frontend tests, full workspace tests, and all application builds.
- Browser-QA chat streaming/settings/attachments/approvals, AI clone identity, published widgets, sidebar CRUD/navigation/theme, fullscreen, and repeated mount/unmount/reconnect.

## Acceptance criteria

- `packages/ai-chat` exists as `@vibecanvas/ai-chat` and owns AI Chat, the AI canvas widget, generic widget host/runtime, Sidebar, dialogs, styles, and their focused tests.
- `packages/canvas/src/components/AiChat`, `plugins/ai`, `plugins/widget`, and `services/widget` no longer exist.
- `apps/frontend/src/feature/sidebar` no longer exists; frontend contains only composition adapters/state used by the package Sidebar.
- Canvas has no dependency or import on `@vibecanvas/ai-chat` and runs/tests without it.
- AI Chat integrates through an injected canvas extension supplied by frontend.
- The new package does not import frontend aliases, stores, service singletons, or router hooks.
- Browser, clock, ID, timer, clipboard, file, URL, logging, transport, navigation, cache, notification, theme, and invalidation effects are injected and fakeable.
- Isolated package tests need neither a live server nor the frontend application singleton graph.
- Existing AI Chat, approval, widget, and Sidebar behavior remains intact.
- Canvas package source count and AI/widget dependency surface are materially reduced; removed dependencies are documented in the task log.
- A76 points to the extracted sidebar/widget ownership, and B49 regressions continue to cover exact widget/session connection freshness.
- Focused tests, full workspace tests, functional-core lint, typechecks, and application builds pass.

## Non-goals

- Redesigning the AI Chat UI.
- Implementing A76's version-aware Widgets catalog/detail pages.
- Fixing B49 by weakening approval scope or returning empty approval lists.
- Re-enabling filesystem or terminal widgets.
- Changing backend chat workspace, widget draft, publish, resource, or approval semantics.
- Moving drawing toolbar, Konva element services, CRDT/history, or scene hydration out of canvas.
- Creating a canvas-to-AI package dependency or a type-only package cycle.

## NOTES

- The generic widget host moves with AI Chat because it is the integration mechanism for AI Chat and published AI-created widgets; leaving it in canvas would retain the largest actor/sandbox/effectful dependency cluster and would not satisfy the requested slimming.
- Scene hydration itself stays in canvas. The extension only registers widget element definitions and emits generic invalidation when definitions become available.
- Disabled terminal/filesystem source files complicate dependency removal. Dependency pruning must use actual remaining imports rather than assuming every Arrow or CodeMirror package can move.
- Sidebar extraction should establish the provider/port seam that A76 requested. Do not duplicate that future catalog provider in frontend.
