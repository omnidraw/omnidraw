# S142 - widgets: emit one host-neutral server module instead of a Bun envelope (order 3/8)
[Overview](../BASED.md)

Move server construction onto the fixed SDK contract and publish exact
self-contained ES-module bytes that both private adapters can consume.

## Context

`WidgetArtifactBuilderCapsule` currently calls `Bun.build` with
`target: "bun"`, places the result inside a JSON/base64
`omnidraw.server-artifact.v1` envelope, and publishes that envelope as
`server-dist/main.artifact`. The local runner decodes the envelope before
loading its one JavaScript output. This extra container is Bun-oriented,
duplicates byte/digest validation, and is not the module a Workers for
Platforms upload adapter needs.

## Plan

### 1. Build a standards-only module

- Keep the host-owned exact-lock scratch build, source snapshot, cancellation,
  and accepted-generation fence, but route server compilation through the
  SDK-owned portable construction rules.
- Bundle `@omnidraw/sdk/server`, author-selected schema libraries, and every
  allowed dependency into one deterministic ESM file targeting the reviewed
  ES standard supported by both the OSS loader and Workers.
- Remove `target: "bun"`. Require no unresolved imports, dynamic imports,
  CommonJS loader calls, native addons, filesystem access, process globals, or
  runtime-specific module specifiers in the output.
- Define the runtime surface as ECMAScript built-ins plus the frozen
  SDK-provided function context only. Widget code has no filesystem, path,
  process/environment, subprocess, OS, native module, socket, DNS, network,
  module-loader, timer, shared-memory, or host-binding capability.
- Keep build identities explicit so the same source is only expected to produce
  the same bytes under the same SDK, dependency lock, compiler, and policy
  identity.

### 2. Separate authored module from host wrapper

- Generate a canonical module that exports only the registered server
  functions and their SDK markers. It does not export a default Fetch handler
  or access Cloudflare `env`.
- Make the private managed adapter generate its WFP Fetch wrapper around these
  exact bytes without re-bundling or rewriting the authored module.
- Upload that wrapper only as a Workers for Platforms user Worker. Do not route
  widget execution through Cloudflare Sandbox, Containers, Durable Objects, or
  a build/chat sandbox.
- Make the OSS adapter load the same bytes directly. Adapter-specific wrapper,
  IPC, headers, bindings, and deployment metadata never participate in the
  canonical widget artifact digest.

### 3. Simplify publication

- Publish the raw module at one fixed path such as
  `server-dist/main.mjs`, plus canonical `functions.json`.
- Attest the exact module and descriptor bytes in `release.json` and catalog
  validation.
- Delete JSON/base64 server-artifact envelope construction and parsing, the
  synthetic output list, loader/kind metadata, and double digest checks that
  exist only because bytes are nested in JSON.
- Keep Preview and publication on the same accepted construction; neither may
  rebuild server source while signing or publishing.

### 4. Enforce the portable source policy

- Reject direct Bun, Node, Cloudflare, Wrangler, workerd, process, filesystem,
  subprocess, OS, native addon, socket, DNS, module-loader, timer,
  shared-memory, and ambient network dependencies at offline check and host
  acceptance.
- Keep the allowed package policy narrow and explicit. SDK/server and ordinary
  bundleable pure dependencies are source inputs, not runtime imports.
- Treat outbound network as unavailable to widget functions. The OSS runner
  continues to deny it and managed must enforce the same result through its
  generated wrapper and outbound-worker policy.
- Make cloud portability an OSS admission rule. If the neutral compiler or
  managed Worker runtime cannot support a construct, OSS check/build rejects
  it even when Bun could execute it locally.

  artifact ABI.
