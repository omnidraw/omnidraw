# S148 - widgets: remove collaborative state and its APIs
[Overview](../BASED.md)

Delete the collaborative-state feature end to end. Keep Capsule's bounded local
store, but remove shared/durable widget-instance state rather than leaving a
hidden backend or SDK capability behind.

## Context

The inspector tab shown below is only the visible edge of a complete vertical:

- [`WidgetDetailPage.tsx`](../../apps/frontend/src/shell/framework/feature/sidebar/widgets/WidgetDetailPage.tsx) renders the tab.
- [`widget-collaborative-state.ts`](../../apps/frontend/src/shell/widgets/widget-collaborative-state.ts) adapts browser mounts to three private RPC operations.
- [`packages/sdk/src/collaborative-state-client.ts`](../../packages/sdk/src/collaborative-state-client.ts), [`contracts/interface.ts`](../../packages/sdk/src/contracts/interface.ts), and [`internal/browser-host.ts`](../../packages/sdk/src/internal/browser-host.ts) expose and host the public guest capability.
- [`apps/backend/src/core/widget-state`](../../apps/backend/src/core/widget-state), [`apps/backend/src/shell/widget-state`](../../apps/backend/src/shell/widget-state), and the [`widget.runtime.state`](../../apps/backend/src/shell/api/widget/contract.ts) router own get/change/subscribe, CAS, replay, limits, and failures.
- [`WidgetInstanceStateStoreTurso.ts`](../../apps/backend/src/shell/database/WidgetInstanceStateStoreTurso.ts) persists the feature in `widget_instance_states`.

**API decision:** yes, remove the APIs too. `widget.runtime.state.get`,
`widget.runtime.state.change`, and `widget.runtime.state.events` exist only for
collaborative state. Keeping them would preserve a callable authority and a
public portability promise after the product feature is gone. Also remove the
public SDK `./state` entrypoint, collaborative client exports, host state port,
and Capsule capability contract.

This subtraction does **not** remove:

- guest-local ephemeral state from [`widget-channels.ts`](../../packages/sdk/src/widget-channels.ts) (`getWidgetLocalState`, `setWidgetLocalState`, and related helpers);
- widget props, lifecycle snapshots, functions, resources, or output channels;
- stable widget `instanceId`, which is still used to authorize mounts and direct function calls; or
- Canvas widget frames, Preview, publication, and filesystem catalog behavior.

The repository uses a clean baseline and provides no migration compatibility.
The removed state is not copied into `canvas_items`, manifests, resource stores,
or another database table.

## Plan

![Current widget inspector with the Collaborative State tab selected](./S148.png)

### 1. Remove the inspector surface

- Remove `collaborative-state` from the widget-detail tab type, tab list, and
  content in [`WidgetDetailPage.tsx`](../../apps/frontend/src/shell/framework/feature/sidebar/widgets/WidgetDetailPage.tsx).
- Update component and browser acceptance coverage to expect exactly
  **Overview**, **Config**, **Functions**, **Resources**, and **Files**.
- Make an old `?tab=collaborative-state` URL fall back through the existing
  invalid-tab behavior; do not retain a hidden route alias or redirect.
- Update the current screen atlas and replace inspector captures when their tab
  row still shows the deleted surface.

### 2. Remove browser transport and mount wiring

- Delete [`widget-collaborative-state.ts`](../../apps/frontend/src/shell/widgets/widget-collaborative-state.ts).
- Remove state-port construction and injection from the frontend Canvas
  extension and `FrontendWidgetRuntime`; mounts continue with function and
  output ports only.
- Remove widget-state request/stream DTOs, operation paths, cursor metadata, and
  generated private-operation manifest entries from the frontend.
- Delete widget-state reconnect/resubscription tests while preserving the
  remaining domain stream recovery matrix.

### 3. Remove the public SDK capability

- Delete the collaborative client, its tests and generated type assertions, the
  `./state` package export, and collaborative exports from the root, widget,
  guest, host, and contract surfaces.
- Remove `IWidgetStateHostPort`, state snapshots/events, mount request `state`,
  and bridge `state` from SDK-owned public contracts and external composition
  fixtures.
- Remove the collaborative Capsule selector, schemas, descriptor, canonical
  hash, grants, stream binding, and host validation. A newly built artifact may
  request function capabilities only; an old collaborative capability request
  receives no compatibility adapter.
- Reshape strict manifest `ui.state` to retain only the local-store choice
  (`"none" | "ephemeral"`); remove `collaborative`. Old manifests containing that key are
  invalid and must be edited and rebuilt—there is no legacy reader or rewrite.
- Update SDK conformance fixtures/transcripts to prove local store, lifecycle,
  functions, resources, and outputs without collaborative state.

### 4. Delete the backend authority and private APIs

- Delete the widget-state core programs/service/errors, live service and stream
  implementation, simulation Layer, shared live/sim conformance, and
  widget-state rate-limit benchmark.
- Remove `widget.runtime.state.get`, `widget.runtime.state.change`, and
  `widget.runtime.state.events` from the widget API contract, handlers,
  operation registry, cursor registry, runtime context, live Layers, semantic
  failure mapping, and generated transport inventories.
- Untangle runtime identity validation from the removed state identity schema;
  `widget.runtime.load` and function invocation must still validate
  `canvasId`, `elementId`, `widgetInstanceId`, and `widgetKey`.
- Remove `durableInstanceState` from authoring-inspection/CLI response metadata;
  canvas correlation remains truthful without reporting a capability that no
  longer exists.
- Remove widget state from architecture-required domain conformance and update
  the measured-performance record after deleting its benchmark.

### 5. Drop persistence from the clean database baseline

- Delete `widget_instance_states`, [`WidgetInstanceStateStoreTurso.ts`](../../apps/backend/src/shell/database/WidgetInstanceStateStoreTurso.ts), its
  SQL statement files, statement-registry entries, and focused store tests.
- Rewrite [`000-initial.sql`](../../apps/backend/src/shell/database/migrations/000-initial.sql) directly from 14 to 13 application tables. Do not add a
  migration, copy old rows, or add a compatibility table.
- Regenerate embedded migration bytes, expected schema/fingerprint, table and
  index counts, recovery fixtures, and constraint tests.
- Remove state-specific Canvas deletion assertions; the existing `canvas_items`
  cascade and widget-instance identity constraints remain for their surviving
  owners.

### 6. Remove authoring promises and release the SDK cut

- Update scaffolds, agent prompts, examples, current architecture guidance,
  [`AGENTS.md`](../../AGENTS.md), [`docs/PRD.md`](../../docs/PRD.md), the
  [widget-system authority](../../docs/internal/llm.widget-system.md), and the
  [screen atlas](../../docs/internal/screens/SCREENS.md) so durable/shared
  widget state is no longer promised.
- Keep completed task logs and explicitly superseded design/review documents as
  history; do not rewrite them into compatibility requirements.
- Select the next unused `@omnidraw/sdk` version, regenerate `bun.lock`, update
  `public-package-set.json`, and rebuild staged package declarations/manifests.
- Add a negative inventory for the removed RPC paths, SDK symbols/subpath,
  capability ID, table, and active product wording.

### 7. Qualify the subtraction

- Run SDK contract, host, local-store, function/resource, conformance,
  type-consumer, staged-package, and packed external-composition tests.
- Run backend database, API/transport, architecture, live/sim conformance,
  widget build/publication/runtime/function/resource, and typecheck gates.
- Run frontend widget-runtime, sidebar, RPC-generation, typecheck, and live
  browser inspector/Preview/published-widget acceptance.
- Prove local ephemeral state still dies with its mount, publication/runtime
  loading still works, and no durable shared state survives or can be reached.

## NOTES

- Scope is a hard subtraction, not a UI-only hide.
- No replacement durable widget state is introduced. Widgets may use
  mount-local ephemeral state or explicit declared resources/server functions
  when persistence is genuinely required.
- Stable `instanceId` and `widget_instance_id` on Canvas items are not part of
  this deletion; they still prevent identity confusion across mounts and
  function calls.
- The first implementation step should re-run repository search because
  generated manifests, test fixtures, and current prompts duplicate capability
  vocabulary in both SDK and backend build paths.
