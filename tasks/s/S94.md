# S94 - widget detail: context-mounted edit chat
[Overview](../BASED.md)

Make widget iteration direct from its detail page by adding a Chat tab that automatically works in the context of the selected widget.

## Context

The widget detail route in [`packages/ai-chat/src/sidebar/widgets/WidgetDetailPage.tsx`](../../packages/ai-chat/src/sidebar/widgets/WidgetDetailPage.tsx) currently exposes Overview, Config, Messages, States, and Files, but users must leave this page and manually establish context before asking the agent to change a widget. The existing chat UI lives under [`packages/ai-chat/src/chat/components/index.tsx`](../../packages/ai-chat/src/chat/components/index.tsx).

Add a Chat tab that automatically mounts the selected widget into the chat session. For a draft, the chat should receive the widget context and write tools needed to help the user make edits. For a published widget, the UI must clearly explain that no write tools are mounted: the agent can discuss or inspect it, but the user must create/open a draft before making changes.

## Plan

1. Add Chat as a routable widget-detail tab while preserving the selected widget source and identity.
2. Reuse the existing chat experience rather than creating a second chat implementation.
3. Automatically mount the selected draft as chat context, including its edit tools, and keep mount/unmount behavior safe across navigation and source changes.
4. Mount published widgets without write tools and show a clear read-only explanation with a path to edit as a draft.
5. Add focused tests for routing, automatic context mounting, draft write-tool availability, and published read-only messaging.
