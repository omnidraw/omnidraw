# S65 - widget tool icon metadata object and validation
[Overview](../../BASED.md)

Replace widget tool icon strings with structured icon metadata, validate lucid icon keys everywhere manifests/patches are set, and update the AI wizard Tool tab to save and preview the new shape.

## Context

Current manifest type stores widget tool icons as a single optional string in [`packages/service-actor/src/core/types.ts`](../../packages/service-actor/src/core/types.ts): `readonly icon?: string;`.

Requested target shape:

```ts
icon?: {
  lucidIcon?: <lucide-static export key>;
  svgIcon?: string; // raw SVG XML, emoji, or text
}
```

Rules from request:
- `svgIcon` has precedence over `lucidIcon` when both are present.
- Accepted `lucidIcon` keys are the same keys currently exposed by `import * as Lucid from "lucide-static"` in [`packages/canvas/src/components/AiWizzard/tabs/ToolTab.tsx`](../../packages/canvas/src/components/AiWizzard/tabs/ToolTab.tsx).
- All allowed keys must be validated when set.
- The allowed keys must also be listed in [`packages/service-agent/src/systemprompts.ts`](../../packages/service-agent/src/systemprompts.ts).
- The UI in [`ToolTab.tsx`](../../packages/canvas/src/components/AiWizzard/tabs/ToolTab.tsx) must reflect the new metadata shape.
- Saving via `Save tool metadata` must send the new `icon` object/null payload, not the old string value.

Current affected locations found during task creation:
- [`packages/service-actor/src/core/vibecanvasjson.zod.ts`](../../packages/service-actor/src/core/vibecanvasjson.zod.ts) validates `widget.tool.icon` as `z.string().optional()`.
- [`packages/api-agent/src/contract.ts`](../../packages/api-agent/src/contract.ts) accepts draft manifest patch `tool.icon` as `string | null`.
- [`packages/service-agent/src/AgentService.ts`](../../packages/service-agent/src/AgentService.ts) accepts draft manifest patch `tool.icon` as `string | null` and writes that string into the manifest.
- [`packages/service-agent/src/tools/CONSTANTS.ts`](../../packages/service-agent/src/tools/CONSTANTS.ts) exposes actor candidate tool icon as `Type.Optional(Type.String(...))`.
- [`packages/service-agent/src/systemprompts.ts`](../../packages/service-agent/src/systemprompts.ts) currently documents `widget.tool.label` and `behavior`, but does not document/list icon keys.
- [`packages/canvas/src/services/widget/fx.register-tool.ts`](../../packages/canvas/src/services/widget/fx.register-tool.ts) passes manifest tool icon through to `ToolService`.
- [`packages/canvas/src/services/widget/interface.ts`](../../packages/canvas/src/services/widget/interface.ts) derives widget tool typing from `TTool`.
- [`packages/canvas/src/services/tool/types.ts`](../../packages/canvas/src/services/tool/types.ts) defines runtime `TToolIcon = string`.
- [`packages/canvas/src/components/FloatingCanvasToolbar/RuntimeToolbar.tsx`](../../packages/canvas/src/components/FloatingCanvasToolbar/RuntimeToolbar.tsx) renders `tool.icon` as sanitized SVG string.
- [`packages/canvas/src/components/AiWizzard/tabs/ToolTab.tsx`](../../packages/canvas/src/components/AiWizzard/tabs/ToolTab.tsx) currently stores selected preset by comparing raw SVG strings and saves `icon?: string | null`.

## Plan

### 1. Choose one source of truth for lucid keys

Create or expose a shared allowed-key source that is used by validation, prompts, and UI.

Preferred implementation direction:
- Add a service-actor core module for tool icon metadata, for example `packages/service-actor/src/core/tool-icon.ts` or similar.
- Export:
  - `LUCIDE_STATIC_ICON_KEYS` as the canonical readonly list.
  - `TLucidStaticIconKey` if practical.
  - a small guard like `isLucideStaticIconKey(value)` or equivalent validator.
  - a normalizer/resolver helper only if it can stay dependency-safe for server and canvas usage.
- Decide whether `lucide-static` becomes a dependency of `@vibecanvas/service-actor` / `@vibecanvas/service-agent`, or whether the key list is generated/copied from `lucide-static` and checked by tests to prevent drift.
- Avoid having ToolTab, service-agent tools, zod, and prompts each maintain their own independent key list.

Notes:
- If a new `fn.*.ts` helper is introduced, follow fn-check rules: exported function names start with `fn`, runtime imports only from allowed leaves/constants/guards/UPPER_CASE imports, and no direct runtime globals.
- If a new `fx.*.ts`/`tx.*.ts` helper is touched, follow the corresponding fx-check/tx-check rules.

### 2. Update actor manifest contract types

In [`packages/service-actor/src/core/types.ts`](../../packages/service-actor/src/core/types.ts):
- Replace `readonly icon?: string;` with a structured type.
- Suggested local/shared types:

```ts
export type TVibecanvasToolIcon = {
  readonly lucidIcon?: TLucidStaticIconKey | string;
  readonly svgIcon?: string;
}
```

- Use the type in `TVibecanvasActorWidget.tool.icon?: TVibecanvasToolIcon`.
- Prefer narrowing `lucidIcon` to the actual key union only if the canonical keys can be represented without making the type file unwieldy.
- Preserve the semantic that an absent `icon` means no icon.

### 3. Update manifest validation

In [`packages/service-actor/src/core/vibecanvasjson.zod.ts`](../../packages/service-actor/src/core/vibecanvasjson.zod.ts):
- Replace `icon: z.string().optional()` with a strict object schema.
- Validate:
  - `icon` is optional.
  - `lucidIcon` is optional but, when present, must be one of `LUCIDE_STATIC_ICON_KEYS`.
  - `svgIcon` is optional string.
  - reject unknown icon object keys.
  - reject an icon object that has neither `lucidIcon` nor `svgIcon` if that fits current validation style; otherwise normalize it to absence at patch time.
- Keep `svgIcon` precedence as rendering/normalization behavior, not a validation error when both exist.

### 4. Update draft manifest patch API and service handling

In [`packages/api-agent/src/contract.ts`](../../packages/api-agent/src/contract.ts):
- Change draft manifest patch schema/type from `icon: z.string().nullable().optional()` to `icon: ZToolIcon.nullable().optional()`.
- Reuse service-actor zod schemas if export boundaries allow it; otherwise mirror schema with the same shared key guard.

In [`packages/service-agent/src/AgentService.ts`](../../packages/service-agent/src/AgentService.ts):
- Change `TAgentDraftManifestPatch.tool.icon` to the new object/null shape.
- In draft manifest patch application:
  - `null` clears the icon.
  - object validates `lucidIcon` against canonical keys.
  - object validates `svgIcon` as string.
  - empty strings should be either rejected or trimmed to absence consistently with UI.
  - write the new object shape into `manifest.widget.tool.icon`.
- Update issue messages from `expected a string` to precise messages such as `widget.tool.icon.lucidIcon: expected one of ...`.

### 5. Update actor candidate tool schema and prompts

In [`packages/service-agent/src/tools/CONSTANTS.ts`](../../packages/service-agent/src/tools/CONSTANTS.ts):
- Replace `icon: Type.Optional(Type.String(...))` with an object schema:
  - `lucidIcon`: optional enum/union of all allowed keys.
  - `svgIcon`: optional string, described as raw SVG XML, emoji, or text.
- Ensure the schema and AJV validation reject invalid `lucidIcon` values when `vc_set_actor_candidate` is called.

In [`packages/service-agent/src/systemprompts.ts`](../../packages/service-agent/src/systemprompts.ts):
- Document the new shape under `# Manifest contract` near `widget.tool.label` and `widget.tool.behavior`.
- State that `svgIcon` overrides `lucidIcon`.
- Add the allowed `lucidIcon` key list in the prompt source/runtime prompt.
- Make the prompt tell agents to prefer a valid `lucidIcon` key for common icons and use `svgIcon` only for custom raw SVG/emoji/text.

### 6. Update canvas runtime icon flow

Decide where structured manifest icon metadata converts into toolbar-renderable content.

Preferred direction:
- Keep manifest/API icon as the new object shape everywhere.
- Add a small resolver for canvas rendering that returns a render model:
  - if `icon.svgIcon` has non-empty content, use it.
  - else if `icon.lucidIcon` is valid, look up `Lucid[icon.lucidIcon]`.
  - else no icon.
- In [`packages/canvas/src/services/widget/fx.register-tool.ts`](../../packages/canvas/src/services/widget/fx.register-tool.ts), either pass the structured object through to `ToolService` or resolve to an internal toolbar render value at registration time.
- Update [`packages/canvas/src/services/tool/types.ts`](../../packages/canvas/src/services/tool/types.ts) and [`packages/canvas/src/services/widget/interface.ts`](../../packages/canvas/src/services/widget/interface.ts) to reflect whichever boundary is chosen.
- Keep built-in editor tools working. They currently import raw SVG strings from `lucide-static/icons/*.svg?raw`; either:
  - allow runtime `TToolIcon` to still be raw SVG/text while manifest widget icons are structured, or
  - migrate built-in tool registrations to the structured form too.
- In [`packages/canvas/src/components/FloatingCanvasToolbar/RuntimeToolbar.tsx`](../../packages/canvas/src/components/FloatingCanvasToolbar/RuntimeToolbar.tsx), render both raw SVG and emoji/text safely:
  - sanitize SVG before `innerHTML`.
  - render non-SVG text/emoji as text, not HTML.
  - keep fallback label behavior when no icon exists.

### 7. Update AI wizard Tool tab UI

In [`packages/canvas/src/components/AiWizzard/tabs/ToolTab.tsx`](../../packages/canvas/src/components/AiWizzard/tabs/ToolTab.tsx):
- Keep `Object.entries(Lucid)` as the UI source for preset dropdown options.
- Change internal selected icon logic from raw SVG comparison to key-based selection:
  - `ICON_NONE_ID` means `icon` is absent/null.
  - preset option means `{ lucidIcon: option.id }`.
  - custom option means `{ svgIcon: customText }`.
- When syncing from manifest:
  - if `icon.svgIcon` is present/non-empty, select custom and fill the text area.
  - else if `icon.lucidIcon` is present, select that key if valid.
  - else select no icon.
  - if both are present, custom wins in the UI because `svgIcon > lucidIcon`.
- Change label from `Custom SVG` to `Custom SVG / emoji / text` or similar.
- Preview the effective icon using the shared resolver/renderer rules.
- Update dirty check to compare icon objects by normalized value, not old raw SVG string.
- Update `Save tool metadata` payload type to send `icon?: { lucidIcon?: string; svgIcon?: string } | null`.

Run a repo search for:

Known likely test/fixture updates:

### 9. Migration / compatibility decision

Decide explicitly whether existing string-valued manifests are rejected or migrated.

Options:
- Strict replacement: old `icon: "..."` manifests fail validation and must be edited.
- Temporary migration: when reading older manifests, convert old strings to `{ svgIcon: oldValue }`, then save the new shape.

Recommendation:
- Use strict validation for new patch/candidate inputs.
- Consider a narrow migration only for existing local drafts/published manifests if current user data would otherwise break.
- Do not keep long-term public API support for string icon patches unless product intentionally wants backwards compatibility.
