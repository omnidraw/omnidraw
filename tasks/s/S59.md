# S59 - cleanup functional-core eslint-disable exceptions
[Overview](../BASED.md)

Audit ESLint disable comments added during A45 and either remove them by aligning code with the rule or document why the exception should stay.

## Context

A45 introduced ESLint functional-core rules and used scoped `eslint-disable` comments for legacy violations so the repo could pass while enforcement moved from Pi/Codex preflight to ESLint.

Relevant task:
- [A45](../a/A45.md) - eslint functional-core rules plus Pi/Codex post-turn hooks

Goal:
- Keep real exceptions explicit and rare.
- Remove disables when a small refactor can satisfy the rule.
- If an exception remains, keep it narrowly scoped with a clear reason.

## Plan

### Phase 1 - inventory

Review each disable and classify it:
- remove now
- keep as real boundary exception
- needs follow-up refactor

### Phase 2 - cleanup

For each removable disable:
- change code to satisfy the functional-core rule
- remove the disable comment
- run `bun run lint:functional-core`

### Phase 3 - document remaining exceptions

For each remaining disable:
- keep only the exact rule names needed
- ensure the reason explains why the rule exception is intentional
- add a short note here if the exception is architectural
