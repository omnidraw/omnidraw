# D8 - widgets: headless mount-catalog dry-run in od_widget_validate
[Overview](../BASED.md)

`od_widget_validate` / `buildCheck` only runs `builder.construct`. It never
exercises the client mount boundary (`createWidgetUiArtifactMountPort` →
`createMountCatalog`). E42 proved that a widget can validate clean and still be
unmountable in the SPA, because the failing integrity check lived at mount time
and had no headless counterpart. Add a headless mount-catalog dry-run so
mount-only integrity failures surface during agent validation instead of on the
canvas.

## Context

- E42 regression: the builder signs `contractHash = sha256(server canonical)`
  while the old mount compared it to the browser-projection digest, an equality
  that could never hold. `od_widget_validate` reported "Preview build passed";
  the widget died only when the SPA mounted it.
- The mount boundary check now lives in
  `packages/ui-ai-chat/src/widget-runtime/mount-widget-ui-artifact.ts`
  (`createMountCatalog`) and uses
  `fnWidgetBrowserFunctionCapabilityRequestMatches` from
  `@omnidraw/widget-contract`.

## Direction

Add a headless step to the validate/buildCheck pipeline that feeds the assembled
preview artifact (browser descriptors + browser digest + signed runtime
descriptor, exactly as `WidgetPreviewService.#assembleArtifact` produces) into
the same `createMountCatalog` logic without requiring a live DOM/Capsule guest.
The cleanest shape is to extract the catalog-consistency portion of
`createMountCatalog` into a pure function in ui-ai-chat (or a shared matcher in
widget-contract) that the validator can call directly, so the validator and the
real mount share one implementation and cannot drift.

Acceptance: a widget whose signed capability request is inconsistent with its
browser descriptors fails `od_widget_validate` headlessly with an actionable
diagnostic, before it ever reaches the canvas.
