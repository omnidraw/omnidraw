## Plan

### 1. Preserve behavior first
- Run existing widget connection tests before each optimization.
- Keep established connection visuals, handles, commit direction, DOM portal behavior, grouping, selection, and undo/redo intact.
- Keep perf test local-only and compare `workScore` before/after.

### 2. Try small isolated improvements
- Make one optimization at a time.
- Run `bun --filter @vibecanvas/canvas test:perf` after each change.
- Record before/after numbers in NOTES.

### 3. Graduate only safe wins
- Keep changes that reduce workScore meaningfully and pass normal tests.
- Avoid broad architecture changes unless small fixes plateau.

## NOTES

### Optimization ideas

| Idea | Where | Expected perf effect | Risk | Validation |
|---|---|---:|---|---|
| Sync only connections attached to moving widget instead of all widget inputs | `tx.sync-widget-connections.ts`, caller args | Very high: line writes/findOne become attached-connections * frames instead of total-connections * frames | Medium: must still refresh other lines after create/delete/hydrate/resize | Existing widget connection tests + perf `linePointWrites` drop |
| Build a connection index map by widget id | widget service state or local sync helper | High: avoid scanning all widgets every drag frame | Medium: stale index on create/delete/group/hydrate | Add tests for deleted/missing endpoints and recreated widgets |
| Pass known widgets/connection store into sync instead of `layer.find` | `WidgetManagerService` / sync portal | Medium-high: remove repeated layer-wide find | Medium: service must own lifecycle cleanly | perf `layerFindCalls` drop to near zero |
| Remove `moveToBottom()` from every existing line update; order once on creation or batch order | `syncConnectionLine` | High: current result has 27,540 calls | Low-medium: visual z-order may change | screenshot/handle tests + line remains behind widgets |
| Avoid `layer.findOne(#lineId)` per connection by storing line refs in map or node attr | `tx.sync-widget-connections.ts` / service | High: current result has 27,540 findOne calls | Medium: cleanup of stale refs | tests for remove and reconnect |
| Batch redraw once explicitly and prevent accidental repeated draws if possible | connection sync / Konva ops | Very high if current 110,340 batchDraw count is reducible | Medium: Konva internals may still schedule draws | perf `batchDrawCalls` drop |
| Put connection lines into dedicated connection layer | `SceneService`, widget sync | High: moving elements should not redraw heavy foreground | High: z-order/camera/group/hit behavior changes | camera transform tests + visual/manual check |
| Put active dragged widget and attached connection lines in `dynamicLayer` during drag | widget drag listener + scene helper | High: static foreground mostly stays untouched during drag | High: restore parent/index/absolute transforms; cross-layer endpoint math | drag, group, DOM portal, connection tests |
| Move transform drag proxy from `staticForegroundLayer` to `dynamicLayer` | `Transform.plugin.ts` | Medium-high for non-widget shape/line drag | Medium: pointer math/z-order must stay correct | transform plugin tests + perf for mixed scene later |
| Add reusable movement-layer helper to lift moving nodes to dynamic layer and restore | new service/helper | High long-term for all elements | High: grouping, ordering, selection, transformer, DOM portals | phased tests per element type |
| Throttle widget connection sync during drag to animation frame | `fx.attach-widget-listener.ts` | Medium: reduces duplicate syncs per frame if drag events are dense | Low-medium: line may lag slightly | manual feel + perf elapsed maybe lower |
| Cache boundary points by widget size and arc | sync helper | Low-medium: reduces math only, not redraw/find costs | Low | micro counter not enough; elapsed only |
| Hide/defer connection handles during drag and render only lines | sync helper | Medium: fewer child mutations | Medium: UX changes, handles may be desired | visual behavior decision needed |
| Split established connection render from hover/active connection UI | widget service/layers | Medium: active drag cheaper, clearer ownership | Medium | connection interaction tests |
| Add dirty-connection ids after widget data changes | append/remove connection flow | High: sync only changed ids | Medium-high: lifecycle complexity | tests for create/delete/update resize |

### Current hypothesis

The fastest safe sequence is probably:
1. stop `moveToBottom()` on every existing line update,
2. cache connection line lookup refs,
3. sync only connections attached to the moving widget during drag,
4. then consider dynamic layer movement for broader drag performance.
